# v1.1.2 Release Root-Cause Copy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Append the approved root-cause and verification text to the existing GitHub Release `v1.1.2` without changing its tag, title, assets, or existing notes.

**Architecture:** Treat the current GitHub Release body as the source of truth. Read and validate it immediately before mutation, insert the approved text at stable section boundaries, update only the body through `gh release edit`, and then read the remote Release back to verify every new entry occurs exactly once while metadata remains unchanged.

**Tech Stack:** GitHub CLI, PowerShell, GitHub Releases API

### Task 2: Append The Approved Copy

**Files:**
- Modify remotely: GitHub Release `v1.1.2` body only

- [ ] **Step 1: Update the body atomically and retain rollback data**

Run the following in one PowerShell process so `$originalBody` remains available for rollback:

```powershell
$release = gh release view v1.1.2 --json name,tagName,isDraft,isPrerelease,url,assets,body | ConvertFrom-Json
$originalBody = [string]$release.body
$rootCauseAdditions = @'
- 预备兵池：修复容量统计遗漏已动员人员、读档后兵池状态不完整、征召失败人员未正确回池，避免战备期长期不征兵或重复超额补充。
- 战后返乡：修复战争结束仅清除任务却没有建立返乡状态的问题；军团可跨海调用运输系统回国，新战争接管时会取消旧返乡任务。
- 战争展示：修复结算与编年史使用占位战争名、白和平与朝贡文本不准确的问题，统一读取真实战争名称和结果。
- 天命继承：修复数据库继承成功后，运行态、帝号、年号、历史记录可能因后续步骤失败而永久缺失的问题，引入可重试持久化流程。
- 法律核心：修复旧天命核心尚未写入时被新天命替换，导致两代核心同时丢失的问题；新天命会继承已落库和待处理快照，历史补写不会覆盖当前天命状态。
- 王朝国号：修复王朝建立成功但国号投影失败后无法重试，以及旧存档从实时领土错误重建历史核心的问题。

'@
$verificationAddition = '- 预备兵池、战争返乡与天命继承三个专项测试及完整规则测试通过；部署的 3239 个源码与资源文件均通过相对路径和 SHA-256 一致性校验。' + "`n`n"
$updatedBody = $originalBody.Replace("`n## 验证`n", "`n$rootCauseAdditions## 验证`n")
$updatedBody = $updatedBody.Replace("`n## 安装`n", "`n$verificationAddition## 安装`n")
if ($updatedBody -eq $originalBody) { throw 'Release body was not changed' }
gh release edit v1.1.2 --notes $updatedBody | Out-Null

try {
    $actual = gh release view v1.1.2 --json name,tagName,isDraft,isPrerelease,url,assets,body | ConvertFrom-Json
    $needles = @(
        '预备兵池：修复容量统计遗漏已动员人员',
        '战后返乡：修复战争结束仅清除任务却没有建立返乡状态',
        '战争展示：修复结算与编年史使用占位战争名',
        '天命继承：修复数据库继承成功后',
        '法律核心：修复旧天命核心尚未写入时被新天命替换',
        '王朝国号：修复王朝建立成功但国号投影失败后无法重试',
        '部署的 3239 个源码与资源文件均通过相对路径和 SHA-256 一致性校验'
    )
    foreach ($needle in $needles) {
        if (([regex]::Matches($actual.body, [regex]::Escape($needle))).Count -ne 1) {
            throw "Release verification failed for: $needle"
        }
    }
    if ($actual.name -ne $release.name -or
        $actual.tagName -ne $release.tagName -or
        $actual.isDraft -ne $release.isDraft -or
        $actual.isPrerelease -ne $release.isPrerelease -or
        $actual.assets.Count -ne $release.assets.Count) {
        throw 'Release metadata changed unexpectedly'
    }
}
catch {
    gh release edit v1.1.2 --notes $originalBody | Out-Null
    throw
}
```

Expected: exit code `0`; only the Release body changes.
