# AW3 War Decisions Casus Belli Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace uncontrolled vanilla war launching with AW3 decision-driven wars using claims, cores, casus belli, targeted war decisions, and no-CB penalties.

**Architecture:** Add a `WarClaim` persistence layer and a `WarDecisionService` that owns all civilized kingdom war starts. Vanilla/random war entry points are blocked unless the war is explicitly allowed by AW3, while rebellions, monsters, natural hostile behavior, and future Mandate of Heaven special wars use explicit allowlists. UI exposes fabrication/declare-war state through the existing kingdom policy/decision surface plus a target-selection panel.

**Tech Stack:** C# net48, NeoModLoader, Harmony, WorldBox `WarTypeAsset`, AW3 `KingdomPolicyService`, AW3 SQLite `[TableDef]`, existing `HistoryWriter`, existing policy/decision UI.

---

## Research Summary

AW2 added these war types:

- `reclaim`: recovery war for recently lost territory, alliance join allowed.
- `vassal_war`: force a neighbor into vassalage, alliance join disabled.
- `independence_war`: vassal rebellion against suzerain, alliance join disabled.
- `tianming`: war against Mandate kingdom, alliance join allowed.
- `tianmingrebel`: rebellion war against Mandate kingdom, alliance join disabled.

AW2 launched them through plot assets:

- `reclaim_war`
- `vassal_war`
- `Independence_War`
- `absorb_vassal`
- modified vanilla `new_war`
- modified rebellion plot for Tianming rebels

AW3 already has `reclaim`, `vassal_war`, and `independence_war` registered. AW3 should not copy AW2's direct plot approach because AW3 now has a stronger policy/decision UI and history system. The new design should make wars a visible stateful decision pipeline:

`fabricate/obtain reason -> choose target -> start war -> resolve goal -> write history`

## Design Choices

Recommended approach: **soft-block vanilla war plots and centralize civilized wars in AW3.**

- Prefix vanilla civilized war plot methods to stop normal random wars from bypassing AW3.
- Add a final safety gate around `Diplomacy.startWar`/`WarManager.newWar` only for civilized kingdom-vs-kingdom wars.
- Use a scoped guard token so AW3 services can intentionally start wars without being blocked.
- Keep non-civilized fights and explicit special wars outside the block.

Rejected approach: fully replacing `WarManager` like AW2 did. That is too invasive for WorldBox 0.51 and risks breaking unrelated war behavior.

## War Types

### Implement Now

- `aw_normal_war`: fallback normal war with a valid generic reason.
- `reclaim`: recover owned core or recent lost city.
- `vassal_war`: force target into vassalage.
- `independence_war`: vassal breaks away from suzerain.
- `restoration_war`: claimant restores a fallen kingdom.
- `general_rebellion_war`: powerful general rises against monarch.
- `fief_independence_war`: fief city or regional lord breaks away.

- `tianming`
- `tianmingrebel`

## Casus Belli Model

Use three layers:

- **Core**: strongest claim. Does not expire quickly. Used for reclaim wars and recently lost cities.
- **Claim**: fabricated or inherited reason. Expires after a configurable number of years.
- **Special CB**: generated by systems such as vassalage, restoration, rebellion, fief risk, or Mandate.

No-CB wars are allowed only through an explicit forced declaration path and add penalties:

- political points decrease.
- diplomatic opinion penalty against neighbors.
- legitimacy/order penalty stored on kingdom data.
- higher rebellion/general-risk modifiers.
- national history records "无故兴兵".

## Task 3: Block Vanilla Civilized Wars

**Files:**
- Create: `Code/patch/AW_WarDecisionPatch.cs`

- [ ] **Step 1: Block vanilla king war plot**

Patch `ClanManager.tryPlotWar` with Prefix:

```csharp
if (WarDecisionService.ShouldBlockVanillaWarPlot(pActor, pPlotAsset))
{
    return false;
}
return true;
```

Rules:

- block if actor kingdom and target are civilized kingdoms.
- do not block if kingdom is mad/rebel system special and AW3 explicitly allows it.
- do not block if `WarDecisionService.IsAw3AllowedWarStart` is true.

- [ ] **Step 2: Final safety gate**

Patch `WarManager.newWar` or `Diplomacy.startWar` only if the method signature is stable in AssetRipper. Prefix returns false for civilized kingdom-vs-kingdom wars when:

- no AW3 allow token is active.
- war type is not vanilla rebellion/whisper/special non-civ.
- attacker and defender are both normal kingdoms.

This prevents hidden vanilla paths from bypassing the plot block.

- [ ] **Step 3: Log blocked war attempts**

Use throttled log:

```csharp
ModClass.LogInfo("[war gate] blocked vanilla war " + attacker.name + " -> " + defender.name);
```

Throttle by kingdom/year to avoid log spam.

## Risk Controls

- Do not block non-civilized combat.
- Do not block explicit rebellion systems until each one has an AW3 replacement.
- Keep Tianming war types registered but disabled until MoH exists.
- Use a scoped AW3 war-start token so our own services do not fight our own Harmony gate.
- Keep no-CB possible for player control and emergency AI, but make it visibly costly.
