# 流官与科举、贡举制度设计

## 目标

完善官职、品阶和任职履历之间的晋升关系，修复流官制度实际上无法稳定轮调、反而容易制造官职空缺的问题，并为贵族、寒门和平民提供经教育、考试进入官场的长期渠道。

本设计保留九品中正制。九品中正负责乡品、初授品阶和六年复评；新考试制度负责取得入仕资格。两者并存，不互相覆盖。

## 已确认的制度边界

- 九品中正制完成后才启用流官制。仅完成“官场制度”时不得提前轮调地方官。
- 科举科技 `aw_tech_civil_service_examination` 依赖九品中正制 `aw_tech_nine_rank_system`。
- 三省六部仍只依赖九品中正制，不追加科举前置条件。
- 天命国或帝国级国家使用完整科举：乡试、会试、殿试。
- 其他国家使用次等贡举：州郡试、国试。
- 科举和贡举三年一科，各阶段在同一世界年内依次完成。
- 考试向贵族、寒门和平民开放，但考生必须先接受学派教育。
- 考试通过只提供资格、入仕起点和候选优势；不得让白身直接成为宰相或其他高官。
- 帝国和天命身份以届次开科时的状态为准。本届中途升降爵位不改变考试模式，下届重新判断。

## 当前问题与修正方向

### 官职与品阶

现有十八阶官阶和九品正从的对应方向保留：基层官职最低对应正七品，中层最低对应正五品，高层最低对应正三品。问题在于 `ApplyOfficeRankFloor` 会在任命时直接把低品或白身抬到官职门槛，允许没有履历的人越级。

修正后将“能否成为候选”和“任命后授予什么品阶”分离：

- 白身和新录取者只能从基层或地方职位起步。
- 中层官职要求达到对应品阶，并有基层任职和至少一次合格考课。
- 高层官职要求达到对应品阶，并有中层任职和至少一次合格考课。
- 任命不再自动把官阶抬到目标官职的最低门槛；不满足门槛的人不会进入该职位的正式候选池。
- 殿试前三名可获得更高入仕起点和候选加成，但仍不能直接进入高层职位。
- 现任官员不因制度研发而被立即清退，后续升迁时再应用新门槛。

### 流官

当前流官判断错误绑定 `CourtService.HasOfficialCourt`，应统一改为 `CourtService.HasNineRankSystem`。现有轮调还存在“先罢免、后找目的地”的非原子流程，找不到去处时会永久丢失职位。

新流程先生成完整轮调计划，再一次性提交：

1. 读取本国到期地方官、现任城市、可用目的城市和资格状态。
2. 生成不把官员留在原任城市的确定性轮调环。
3. 在内存中验证每位官员仍存活、仍属于本国、目的城市仍属于本国且未被占领、每城只有一位拟任者。
4. 全部验证通过后，统一更新官员履历、城市主官和任期。
5. 任何一项失效时取消整组提交，保留所有原职，并将下次尝试推迟一年。

同一年每国最多执行现有预算允许的轮调数量。人数不足以形成轮调环时不强行罢免。城市临时缺官时，优先任命满足条件的异地官员；没有合格人选时允许本地受教育者担任一年“署理”，待下一次安全轮调替换。署理不是正式流官履历，不能借此越级晋升。

## 科技与制度状态

新增科技定义：

```text
ID: aw_tech_civil_service_examination
前置: aw_tech_nine_rank_system
适用: 所有已启用 AW3 国策的国家
运行时名称:
  天命国或帝国级国家 -> 科举制度
  其他国家           -> 贡举制度
```

AI 在完成九品中正后才考虑该科技。官职空缺多、已受教育但没有入仕渠道的人多、国家行政规模大时提高研发权重；帝国和天命国获得额外权重。该权重不得越过科技前置条件，也不得阻塞其他所有科技。

## 持久化模型

新增两张 SQLite 表，由现有反射建表和增列机制管理。

### `CivilServiceExamSessionTableItem`

每行表示一国的一届考试：

- `ID`：届次主键。
- `KINGDOM_ID`、`KINGDOM_NAME`：开科国家和名称快照。
- `MODE`：`imperial_exam` 或 `tributary_exam`。
- `CYCLE_YEAR`：开科世界年。
- `STAGE`：当前阶段。
- `STATUS`：`scheduled`、`running`、`ranking_pending`、`completed`、`cancelled`。
- `OPEN_WORLD_DAY`、`NEXT_DUE_WORLD_DAY`：开科与下一阶段的绝对世界日。
- `HOST_RULER_ID`：开科君主。
- `FINAL_RULER_ID`：殿试或国试定榜君主；尚未定榜时为 `-1`。
- `PLAYER_RANKING_PENDING`：玩家是否仍可调整殿试前三名。
- `CANDIDATE_CURSOR`：分帧处理游标。
- `UPDATED_TIME`：最后更新时间。

### `CivilServiceExamCandidateTableItem`

每行表示一位考生在一届考试中的完整快照和结果：

- `ID`、`SESSION_ID`、`ACTOR_ID`。
- `ACTOR_NAME`、`HOME_CITY_ID`、`HOME_CITY_NAME`：避免人物死亡或迁移后榜单失真。
- `SOCIAL_ORIGIN`：`noble`、`declined_noble`、`commoner`。
- `SCHOOL_ID`、`LOCAL_GRADE`：开科时的教育和乡品快照。
- `LOCAL_SCORE`、`METROPOLITAN_SCORE`、`PALACE_SCORE`、`NATIONAL_SCORE`。
- `CURRENT_STAGE_RESULT`：待考、通过、落第、缺考或取消。
- `QUALIFICATION`：无、举人、贡士或进士。
- `FINAL_RANK`、`FINAL_TITLE`：最终名次及状元、榜眼、探花等称号。
- `ENTRY_BONUS`：进入官场候选池时使用的固定加成。
- `UPDATED_TIME`。

数据库是考试结果的真相源。Actor data 只保存最新资格的运行时投影，用于候选评分；读档、人物迁移或投影丢失时从最近一条有效考试记录重建。表上建立届次、国家加年份、Actor 加国家、活动状态加到期日索引，避免 UI 和调度器进行全表扫描。

## 考生来源与阶层判定

开科时只构建一次有界候选池，不在每帧扫描全国 Actor。候选来源依次为：

1. 本国已受教育且未取得同级资格的贵族和宗室。
2. 本国已受教育的寒门。
3. 本国学院和学派名册中学识较高的平民。
4. 尚无中央正式官职、但符合晋升条件的地方官或署理官。

共同条件：人物存活、成年、属于开科国家、不是奴隶、没有不可任官状态、具有有效学派教育记录。君主、已在任的中央高官和本届重复报名者不进入新考生池。

阶层快照只用于显示和统计：

- 贵族：报名时具有贵族或宗室身份。
- 寒门：报名时不是贵族，但档案中可追溯到贵族或氏族背景。
- 平民：没有现存贵族身份，也没有可追溯贵族血脉。

贵族身份不直接增加考试分数。九品乡品继续影响授官和后续官阶评定，但不决定考试是否通过。

单国单届最多保存 96 名考生。构建候选池时使用现有官员索引、贵族档案索引、学派成员索引和学院居民索引，禁止调用无界的世界 Actor 遍历。人数超过上限时按教育程度、知识能力、年龄适任性和确定性 Actor ID 排序截断，三个阶层都至少保留一个名额；某阶层没有合格者时名额可让给其他阶层。

## 届次与阶段

科技完成后的下一个完整世界年开第一科，之后以首科年份为锚点每三年一科。每国使用 `KINGDOM_ID` 计算不超过 30 世界日的固定偏移，错开同阶段的 AI 国家处理时间，但全部阶段仍在同一年完成。

阶段日期由现有世界日历换算统一计算，不另建第二套历法。科举在该年约 5% 处错峰开科，30% 处结算乡试、55% 处结算会试、80% 处结算殿试，并在 95% 处完成或自动定榜；贡举在约 5% 处开科、40% 处结算州郡试、80% 处结算国试，并在 95% 处完成。阶段到期只是进入可处理队列，不允许单帧清空全部考生；每阶段预留的时间必须足以按下述 8 人预算处理最大候选池。

### 天命国或帝国：科举

1. 乡试：形成考生池并评定基础学识，达到 60 分后按成绩录取；录取上限为 `min(64, max(12, 城市数 * 4))`，通过者取得举人资格。
2. 会试：只处理本届举人和已持有本国贡举贡士资格者，达到 60 分后按成绩录取；录取上限为 `min(32, max(6, 城市数 * 2))`，通过者取得贡士资格。
3. 殿试：只处理本届贡士。仍然存活并属于开科国家的贡士全部取得进士资格，殿试分数只决定最终榜单。
4. 定榜：前三名为状元、榜眼、探花，其余按最终分数排序。

### 非帝国：贡举

1. 州郡试：形成考生池，达到 60 分后按成绩录取；录取上限为 `min(48, max(8, 城市数 * 3))`。
2. 国试：从州郡试通过者中录取贡士，要求达到 60 分；录取上限为 `min(20, max(4, 城市数))`。

贡士可进入地方和中低级中央职位的候选池。国家以后成为帝国或取得天命时，其仍然有效的贡士可跳过乡试参加会试。贡士经任职、考课和升品后仍可继续晋升，不永久封死在中低层；限制的是首次授官，不是终身仕途上限。

各阶段分数为 0 到 100 分，并在第一次结算时持久化。确定性随机种子由届次 ID、Actor ID 和阶段组成，读档不得重掷。评分由人物通用学识能力、阶段侧重能力、学派教育成果和最多正负 5 分的确定性波动组成；阶层不加分，乡品不计入考试分。相同分数按 Actor ID 稳定排序。缺考或人物在阶段结算前死亡会持久化为对应结果，不删除其榜单行。

## 定榜与玩家操作

殿试完成后，玩家控制的天命国或帝国进入 `ranking_pending`：

- 玩家只能在殿试合格者中调整前三名，不能把落第者直接改为进士。
- 窗口显示原始总分、当前名次和调整后的前三名。
- 确认后立即持久化，不能通过关闭再打开重复定榜。
- 到期未操作、君主死亡或国家失去玩家控制时，由现任君主和主导派系自动定榜。

AI 定榜以考试总分为主。君主能力和主导派系对殿试合格者的调整限制在正负 3 分；原始分差超过 6 分时，低分者不能越过高分者。非帝国国试始终自动定榜，不提供殿试前三名调整。

## 入仕与晋升

考试科技完成后，新任文职正式官员必须满足教育和资格门槛：

- 贡士和普通进士从基层或地方职位起步。
- 殿试前三名可获得较高的初授品阶和中层职位候选加成，但不进入高层职位候选池。
- 从基层进入中层必须具备基层履历、对应品阶和至少一次合格考课。
- 从中层进入高层必须具备中层履历、对应品阶和至少一次合格考课。
- 乡品只影响初授品阶和同等条件下的任用排序，不覆盖考试资格。

为兼容旧存档，科技完成时已经在任的文官保留职位。君主、继承人、先师客卿和纯军事官职不被考试资格强制清退。正式候选暂时不足时，只允许受教育者署理空缺；署理任期一年、不自动获得正式官阶、不参与高层晋升，下一轮候选刷新时优先替换。

候选池刷新继续使用现有五年节奏和事件触发补缺，不增加逐帧 Actor 扫描。考试结果写入后仅将相关国家的官场候选缓存标脏。

## UI

官场窗口增加一个入口按钮：

- 天命国或帝国显示“科举”。
- 其他国家显示“贡举”。
- 未完成前置科技时按钮保持可见但禁用，Tooltip 明确显示缺少九品中正或考试制度。
- 点击后打开完整考试窗口，返回按钮回到原国家的官场窗口。

考试窗口复用现有宽窗口和高对比度控件，默认尺寸与官场窗口一致。顶部显示国旗、国名、制度名、本届年份、当前阶段和距下一阶段时间；中部使用阶段切换控件；主列表显示画像、姓名、籍贯、阶层、学派、乡品、各阶段成绩和当前状态；殿试页提供前三名调整；历届页读取已经完成的榜单。

所有列表只读取持久化届次和考生行。窗口刷新不得扫描当前国家全体 Actor。人物已经死亡时仍显示姓名和考试快照，画像使用人物档案的种族、皮肤和头部数据重建。

## 历史记录与本地化

以下事件写入国家史和相关人物传记：开科、取得举人、取得贡士、取得进士、殿试前三名、首次正式授官。普通落第不逐人写入编年史，只保留在历届榜单，防止历史表膨胀。

所有制度名、阶段、资格、名次、状态、署理原因、禁用原因、日期和 AI 定榜说明均使用本地化键。中文措辞区分“科举”和“贡举”，不得在非帝国国家界面显示“殿试”“状元”等帝国专属文本。

## 调度与性能预算

- 活跃考试使用全局按 `NEXT_DUE_WORLD_DAY` 排序的到期队列。
- 每个权威模拟周期最多推进一届考试。
- 每次最多评定 8 名考生，剩余考生通过 `CANDIDATE_CURSOR` 后续继续。
- 候选池只在开科时构建一次，最大 96 人。
- UI 不触发考试推进、候选发现或数据库写入。
- 所有写入通过现有历史异步写入协调器或同等的单写者路径串行提交。
- 暂停、载入中和联机客户端镜像状态不得推进考试或执行流官轮调。
- 流官每国每年沿用现有上限，先规划、后提交，失败不产生半完成状态。

## 存档、读档和状态变化

- 读档时重建活动届次到期队列和最新资格投影，不重新生成考生或分数。
- 同一存档重复加载不得重复开科、重复授予资格或重复写历史。
- 君主死亡不取消考试；继任君主成为最终定榜者，开科君主快照保留。
- 国家覆亡时取消尚未完成的届次，保留已完成历届榜单。
- 国家合并、分裂或 Actor 改换国籍后，活动考试只接受仍属于开科国家的考生；离境者记为缺考。
- 本届考试模式在开科时冻结。爵位或天命状态变化只影响下一届。
- 科技被旧存档修复逻辑补齐时，仍从下一个完整世界年开第一科，不在读档帧集中补考。

## 验证要求

### 规则测试

- 流官在只有官场制度时关闭，在九品中正完成后开启。
- 无完整轮调计划时所有原职保持不变；完整轮调时不存在原地留任、重复目的城市或半提交。
- 白身不能因任命高官而被直接抬到正三品。
- 中层和高层候选分别满足品阶、履历和考课门槛。
- 科举科技依赖九品中正；三省六部依赖关系保持不变。
- 天命或帝国选择三阶段科举，其他国家选择两阶段贡举。
- 三年一科、同年完成、各国固定错峰，并能在读档后恢复同一届次。
- 贵族、寒门和平民均可报名，阶层本身不改变考试分数。
- 贡士在国家升级后可参加会试；殿试前三名不能直接进入高层职位。
- 玩家定榜只能调整合格者前三名，超时自动定榜且只执行一次。

### 持久化与恢复测试

- 分数第一次生成后读档不变化。
- 活动届次、候选游标、资格和榜单可完整恢复。
- 君主死亡、考生死亡、国籍变化、国家覆亡和爵位变化均按上述规则收敛。
- Actor data 资格投影丢失时可以从数据库恢复，不生成重复记录。

### 性能与 UI 测试

- 断言候选池最大 96 人，单权威周期只推进一届且最多评定 8 名考生。
- 源码守卫确认没有考试或流官逻辑挂到每帧全员 Actor 更新。
- 打开和刷新考试窗口不扫描世界 Actor，不推进模拟状态。
- 官场入口、禁用 Tooltip、科举/贡举动态名称、阶段列表、历届榜单、殿试定榜和返回官场均有本地化和布局测试。
- Debug、Release 构建通过；实机跨至少六个世界年验证两届考试、官员晋升和地方轮调，没有年度尖峰和长期空缺。

## 非目标

- 不取消九品中正制，也不把科举变成唯一官阶来源。
- 不为非帝国国家提供殿试、状元、榜眼、探花。
- 不允许考试直接授予宰相等高官。
- 不在本功能中重做学派教育、官场派系、政治点数或三省六部制度。
- 不增加考试作弊、买官、舞弊案、主考官派系斗争等扩展事件；这些可在基础制度稳定后单独设计。
