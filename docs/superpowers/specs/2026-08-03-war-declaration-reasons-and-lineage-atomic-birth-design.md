# 宣战失败原因贯通与族谱出生记录原子化设计

## 目标

本设计修复两个已经通过代码调用链和存档数据库确认的根因：

1. 外交宣战的真实不可用原因在外交主窗口、宣战目标窗口和权威提交链中被覆盖或丢弃。
2. 新生子女的人物档案与亲子边分开提交，普通 Xia、猴族以及西方/兽人的轻量族谱路径可能只留下亲子边，造成族谱上下行不对称和后代链断裂。

本设计不修改战争规则本身，也不改变哪些人物应进入完整族谱。它只保证已有规则的失败原因可见，并保证所有用于族谱导航的出生关系具有完整、原子的最小数据。

## 宣战可用性

### 统一结果

新增统一的宣战可用性结果，至少包含：

- `Available`
- `FailureReason`
- 对应的战争目标

外交主按钮、战争目标行、确认按钮和权威命令提交必须使用同一套检查。状态在窗口打开后发生变化时，最终以主机权威提交返回的原因覆盖客户端预判。

### 原因保留

`WarDecisionService.CanQueueWarPair` 返回的 `non_aggression_pact`、`same_alliance`、`vassal_external_war_blocked`、`already_at_war` 等原因必须原样传入目标级规则。`WarDecisionQueueRules` 不再把这些原因覆盖为 `basic_blocked`。

待执行的宣战已经存在时，返回明确的 `war_preparation`；参与者无效、没有战争理由及各战争目标前置条件不足也各自保留稳定的 reason key。

### UI 行为

- 外交主窗口先聚合所有目标的真实可用性。存在任一可用目标时按钮可用；全部不可用时按钮置灰，并在 Tooltip 显示优先级最高的真实原因。
- 宣战窗口不再删除不可用目标。目标保留、置灰、不可点击，Tooltip 显示该目标不可用的具体原因。
- 自动选择只允许落在可用目标上。
- 确认按钮无有效选择时显示当前目标或聚合后的失败原因。
- 提交失败时显示主机返回的本地化原因，不再统一显示“当前无法执行此外交操作”。

### 本地化

所有已知 reason key 映射到 `aw_diplomacy_failure_<reason>`。已有等价文案可以复用；缺少的原因补齐中文、英文和俄文本地化。未知原因才回退到通用不可用文案，界面不得直接显示 `basic_blocked` 或原始枚举字符串。

## 族谱出生事务

### 数据不变量

任何 `FamilyEdge` 提交必须满足：

1. child 的 `ActorArchive` 已存在，或将在同一数据库事务中 upsert。
2. child 最小档案和本次出生的父母边同时成功或同时失败。
3. 事务成功后只推进一次家庭结构 projection revision。
4. 事务失败时不留下可被查询到的半套边，也不提前推进 revision。

### 最小人物快照

普通 Xia、猴族、西方和兽人的轻量出生路径统一生成最小人物快照。最小快照保存族谱正确导航和画像回退所需的真实出生数据，包括：

- actor id、物种与性别
- 出生时间、父母 id 和代数
- 当时可取得的姓名、城市、国家及氏族字段
- 当时可取得的 head、skin、skin set、phenotype 等画像身份
- 存活状态

未取得的字段保持空值或明确的无值标记，不伪造氏族、爵位或称号。人物以后获得氏族、爵位或死亡时，继续由现有完整归档路径更新同一档案。

### 写入边界

出生处理先在主线程捕获不可变快照，再将 child upsert 和最多两条父母边装入一个异步写入 envelope。数据库工作线程在一个 SQLite 事务内提交全部内容。成功回调清理 pending 状态并推进一次 `FamilyStructure` revision；失败回调清理 pending/prerequisite 并记录可诊断原因。

`ArchiveActor` 的调用结果改为可区分 `NotEligible`、`Queued`、`Committed` 和 `Failed` 的结果，出生链不得再忽略归档被拒绝的情况。对不符合完整族谱资格的人，最小快照属于关系完整性记录，不等同于授予贵族或氏族身份。

### 查询与显示

族谱查询不再把“存在边但 child 档案缺失”静默过滤为不存在。新数据下该状态属于完整性错误；旧档迁移期间则显示明确占位节点，以保持上下代导航连续。

## 旧存档修复

加载存档数据库后执行有版本标记、可重复运行的完整性迁移：

1. 扫描 `FamilyEdge LEFT JOIN ActorArchive` 找出孤立 child id。
2. 若 WorldBox 中仍存在对应活人，从 actor 捕获最小或完整快照并补档。
3. 若人物已死亡且无可验证快照，建立 `unresolved` 占位档案，仅保存 child id、已知父母关系和明确的资料缺失状态。
4. 不猜测死者姓名、物种皮肤、爵位或氏族。
5. 在一个迁移事务中完成补档，成功后记录 schema/data migration version，并推进一次族谱 projection revision。

占位节点允许父代向下继续展开，也允许通过已知边返回父代。后续若从其他可靠历史记录恢复到真实档案，正常 upsert 可以替换占位内容。

## 错误处理与诊断

- 宣战检查记录最终 reason key 的来源层，未知 key 记录一次限频警告。
- 出生事务记录 child id、父母 id、队列接纳状态和事务结果，但不在正常成功路径打印逐人物 debug 日志。
- 保存边界继续 flush 已接纳的历史写入；未接纳的出生事务必须明确失败，不能被当作已完成。
- 加载后输出一次聚合完整性指标：孤立边数量、活人回填数量、占位数量和失败数量。

## 测试

### 宣战

- 非侵略条约、同盟、已交战、附庸外交受限分别保留原始 pair reason。
- pending、无目标、全部失败、部分可用、全部可用的按钮聚合结果正确。
- 不可用目标保留并置灰，可用目标可选择，自动选择不会选中失败目标。
- 客户端预判与主机状态不一致时，最终提示采用主机 reason。
- 所有已知 reason key 均有三语言映射，不落入原始 key 或 `basic_blocked`。

### 族谱

- 普通 Xia、猴族、西方、兽人出生并 flush 后，child 档案和双亲边同时存在。
- 队列满、SQLite busy 和注入事务失败时，child 与边同时不提交，projection revision 不推进。
- 出生后立即保存、重载，数据库反连接的孤立 child 数为零。
- 父看子、子看双亲、死者后代导航和重载后的双向关系一致。
- 旧存档夹具迁移后孤立边数为零；活人补真实档案，无法恢复的死者显示占位节点。
- 最小档案不会使普通人物错误获得贵族、氏族或官场资格。

## 验收标准

1. 外交界面从按钮到权威提交均显示真实、已本地化的宣战不可用原因。
2. 新出生数据不再产生 `FamilyEdge` 指向不存在 child archive 的记录。
3. 已知问题存档迁移后，族谱上下代导航不再因 2979 名缺档子女而断裂。
4. 无法恢复的死者以明确占位显示，不伪造身份或画像。
5. 保存、加载和异步写失败均不会产生新的半套族谱数据。
