# 朝贡付费保护与宗室女眷入贡设计

## 目标

把松散朝贡关系从永久身份改为按年续期的付费保护关系：

- 有效朝贡期内，宗主与朝贡国不能互相宣战；
- 朝贡国每年根据自己与宗主体系的实力差距决定实缴比例；
- 朝贡国越强、宗主越弱，实缴越少；达到拒贡门槛后关系终止；
- 愿意缴纳但没有任何资源可转移时，同样因欠贡终止关系；
- 每次成功岁贡最多附带一名合格女眷，依次供宗主君主、继承人或王子纳为妾室；
- 正式附庸的贡赋、战争和独立逻辑保持不变。

## 已确认规则

采用历史风格的岁贡制。新建立的朝贡关系立即生效并获得双向和平保护，第一次应缴时间为下一年。成功缴纳后续期一年。

朝贡国与宗主体系的国力比使用完整战争潜力计算。双方都计入现役军人、后备兵、城市、领土以及正式附庸的加权支援能力，但不把松散朝贡国算入宗主的战争力量。

实缴档位为：

| 朝贡国国力 / 宗主体系国力 | 实缴比例 |
|---|---:|
| `< 50%` | 100% |
| `50% - 75%` | 75% |
| `75% - 100%` | 50% |
| `100% - 125%` | 25% |
| `>= 125%` | 0%，主动拒贡 |

边界采用左闭规则：恰好达到 50%、75%、100% 或 125% 时进入下一档。125% 与现有 AI 优势战争门槛一致。

黄金或政治点任一实际转移大于 0 即视为成功履约。两项实际转移都为 0 时，若实缴档位为 0，结束原因为实力拒贡；若档位大于 0，结束原因为无力纳贡。

## 方案选择

采用逐关系持久化方案。每条松散朝贡关系分别保存处理年份、成功缴纳年份、下次应缴年份和最近实缴档位。现有宗主国级别的 `VASSAL_TRIBUTE_LAST_YEAR` 无法区分多个朝贡国，不再承担松散朝贡关系的结算幂等职责。

未采用以下方案：

- 继续使用宗主国统一年度标记：无法判断具体哪个朝贡国已缴或欠缴；
- 只从关系建立时间推算：无法记录续贡结果，读档后容易产生永久保护；
- 只在宣战 UI 拦截：AI、战争队列和原版入口仍可绕过。

## 组件边界

### `TributaryPaymentRules`

纯规则组件，输入双方国力和基础应缴额，输出：

- 标准化国力比；
- 实缴百分比；
- 缩放后的黄金与政治点请求额；
- 主动拒贡或继续缴纳的决定。

政治点保持浮点计算。黄金按整数计算；当基础黄金应缴额、实缴档位和可用库存都大于 0 时，缩放结果至少为 1，避免 25% 档因整数舍入被误判为完全欠贡。

### `TributarySettlementService`

逐条处理到期的松散朝贡关系，负责幂等门禁、资源转移、续期、关系终止、女眷入贡和历史记录。它不处理正式附庸。

`VassalService.SettleAnnualTribute` 保留为年度入口，但将正式附庸结算与松散朝贡结算分开。正式附庸继续走当前规则；松散朝贡交给新服务。

### `TributaryProtectionRules`

提供一个权威判断：两个国家之间是否存在直接、活跃的松散朝贡关系。判断与方向无关，因此同一个谓词同时保护宗主和朝贡国。

战争可用性展示、AI 目标筛选、战争计划入队、外交宣战提交、战争决策校验和最终 `startWar` 补丁都调用同一判断。

### `RoyalHouseholdRecipientRules`

纯规则组件，负责宗室接收人顺序、资格和容量：

1. 当前男性君主；
2. 当前男性继承人；
3. 按现有继承规则排序的成年男性王子。

只有存活、成年、处于宗主国、具有生育能力且不属于共和政体的接收人才可入选。继承人的容量为 2，每位王子的容量为 1；君主继续使用现有按国家等级计算的 2、4、8 容量。

王子限定为当前君主存活、成年且仍属于宗主国的男性直系儿子，复用现有直系子嗣索引以及嫡出、出生先后排序，不把旁系宗亲、官员或选举继承候选当作王子，也不进行全世界 actor 扫描。当前继承人从 `HeirService` 的已登记只读投影取得并从王子列表去重。

### 扩展后的 `RulerHouseholdService`

复用现有妾室资格、迁移、家室记录、怀孕和出生合法性逻辑，但允许显式指定家室男性，而不再强制其必须是当前君主。

现有字段 `RULER_ACTOR_ID` 在兼容旧存档的前提下解释为家室拥有者。新增来源与角色元数据，以区分普通外交献婚和朝贡女眷，并支持按朝贡关系与年度去重。

## 持久化模型

`VassalRelation` 增加以下字段，均由反射建表系统为旧库幂等补列：

- `LAST_TRIBUTE_ATTEMPT_YEAR`，默认 `-1`；
- `LAST_TRIBUTE_PAID_YEAR`，默认 `-1`；
- `NEXT_TRIBUTE_DUE_YEAR`，默认 `-1`；
- `LAST_TRIBUTE_FACTOR_PERCENT`，默认 `-1`。

新建立的松散朝贡关系设置 `NEXT_TRIBUTE_DUE_YEAR = 当前年 + 1`，其余字段保持未处理状态。关系在建立后立即活跃，战争保护不依赖一次虚假的首年缴纳记录。

旧存档中活跃且 `NEXT_TRIBUTE_DUE_YEAR < 0` 的松散朝贡关系，在首次年度维护时迁移为本年到期并立即接受一次实力与支付评估。正式附庸忽略这些字段。

`RulerHousehold` 增加：

- `OWNER_ROLE_AT_ENTRY`：`king`、`heir` 或 `prince`；
- `SOURCE_KIND`：普通外交来源或 `tributary_offering`；
- `SOURCE_RELATION_ID`：来源朝贡关系，普通外交记录为 `-1`；
- `SOURCE_TRIBUTE_YEAR`：来源岁贡年份，普通外交记录为 `-1`。

`SOURCE_RELATION_ID + SOURCE_TRIBUTE_YEAR` 用于防止一次岁贡重复上贡女眷。现有 `SOURCE_PROPOSAL_ID` 继续服务普通外交提案，朝贡来源允许为 `-1`。

## 年度结算流程

对于每条到期的松散朝贡关系：

1. 验证朝贡国、宗主国、关系投影和数据库行仍然一致；
2. 若 `LAST_TRIBUTE_ATTEMPT_YEAR` 已是本年，跳过，保证同年最多处理一次；
3. 在转移资源前将本年记为尝试年，采用 at-most-once 语义；
4. 读取双方完整战争潜力并计算实缴档位；
5. 档位为 0 时，以 `tribute_refused_power` 结束关系；
6. 档位大于 0 时，按档位缩放当前基础贡赋并执行黄金、政治点转移；
7. 两项实际转移都为 0 时，以 `tribute_unpaid` 结束关系；
8. 任一资源实际转移成功时，更新成功缴纳年、最近档位和下一应缴年；
9. 财物履约完成后，尝试一次女眷入贡；
10. 分别为双方写入朝贡历史，记录实际资源、档位和下次应缴年。

单条关系异常不得中断同一宗主的其他关系。异常发生时保留关系及原到期年，但本年不重复扣款；下一年度可重新处理，并输出包含关系 ID、双方国家 ID 和处理阶段的诊断日志。

## 女眷入贡流程

只有财物成功履约后才尝试女眷入贡，每条关系每年最多一人。25%、50%、75% 和 100% 档都使用同一“一人上限”，女眷不会再按档位拆分概率。

候选人沿用现有家室门禁：

- 女性、成年、18 至 33 岁；
- 存活且属于朝贡国；
- 贵族身份及有效姓氏、氏族谱系；
- 未婚、没有既存家室、非奴隶；
- 与接收人不是近亲。

候选顺序为：

1. 朝贡国当前君主的亲生女儿；
2. 朝贡国统治宗族的女眷；
3. 其他合格贵族女眷；
4. 同一优先级内按现有年龄与 actor ID 稳定排序。

服务先按宗室接收顺序寻找第一个有空余妾位的人，再为该接收人选择第一个通过近亲等最终校验的女眷。没有候选人、所有接收人满额或人物迁移失败时，只跳过本次女眷，不撤销财物履约和朝贡续期。

成功后女眷迁入宗主首都，记录为接收人的妾室，并写入人物与双方国家历史。她不成为原版互为 `lover` 的正妻，子女继续使用现有妾生子非嫡出规则。

## 宗室家室生命周期

当前维护逻辑会在家室男性不再是君主时关闭记录，必须按来源角色扩展：

- 旧记录和普通君主家室仍保持现有兼容行为；
- 朝贡妾室只在家室男性死亡、女眷死亡、双方不再属于同一接收国或记录被显式关闭时终止；
- 接收人由继承人或王子即位后，已有妾室继续保留并计入当前君主容量；
- 即位造成存量超过君主容量时不删除已有妾室，只禁止继续新增；
- 接收人角色下降不主动解除既有关系；若其不再是君主、继承人或王子，新增容量为 0；
- 月度怀孕队列从只处理当前君主扩展为按国家有界轮转处理活跃家室男性，保持每国每月最多启动一次妾室怀孕，避免按人物全量扫描。

`ResolveManagedFather` 不再要求父亲必须是当前君主，而是要求活跃家室记录、父母存活、同属记录中的接收国。妾生子合法性保持现有结果。

## 战争门禁

只要直接松散朝贡关系的数据库行和运行时投影仍为活跃状态，双方之间所有战争类型都被阻止：

- 宗主对朝贡国的普通战争、征服、宣称、吞并或其他战争目标；
- 朝贡国对宗主的普通战争以及当前被错误允许的独立战争；
- 玩家入口、AI 入口、排队入口和原版最终开战入口。

断贡调用现有关系终止流程，原子地关闭数据库行、清理运行时投影、更新计数和地图模式。关系终止后，朝贡门禁立即消失，但其他停战协定、同盟、宣战理由和冷却仍正常生效。

朝贡保护只表示宗主不征讨朝贡国。本设计不让朝贡国自动加入宗主战争，也不强制宗主参加朝贡国对第三方的战争。

`VassalAIService` 必须区分正式附庸与松散朝贡国。正式附庸继续使用独立战争评估；松散朝贡国不得再走独立战争分支，只能通过年度实力评估拒贡退出。退出后可在后续普通 AI 周期中按常规规则宣战，不在结算同一时刻强制开战。

## 历史、展示与诊断

朝贡关系详情增加：

- 最近一次成功缴纳年份；
- 最近实缴档位；
- 下一次应缴年份。

历史记录区分：

- 成功朝贡：双方国家、实际黄金、实际政治点、档位、下次应缴年；
- 女眷入贡：女眷、接收宗室、双方国家和来源朝贡关系；
- 实力拒贡：双方国力与国力比；
- 无力纳贡：基础请求额、实缴档位和实际转移为零的结果。

诊断日志至少包含关系 ID、朝贡国 ID、宗主 ID、当前年、应缴年、国力比、档位、实际转移和女眷结果。正常未到期关系不输出逐年噪声日志。

## 测试策略

纯规则测试覆盖：

- 49.99%、50%、75%、100%、124.99% 和 125% 的档位边界；
- 黄金缩放与最小正数规则；
- 任一资源大于 0 即履约，两项为 0 即终止；
- 主动拒贡与无力纳贡结束原因；
- 宗室接收顺序和 2/4/8、2、1 容量；
- 女眷候选优先级和稳定排序。

服务与持久化测试覆盖：

- 新关系次年首次结算；
- 旧存档关系首次年度迁移；
- 多个朝贡国逐关系独立结算；
- 同年重复 tick 不重复扣款或重复上贡女眷；
- 成功、拒贡、无力纳贡各自更新正确字段和关系投影；
- 没有女眷或迁移失败不影响财物续期；
- 继承人即位后妾室保留，且不重复计数；
- 家室男性不是君主时怀孕父亲解析仍正确且有界。

战争回归测试覆盖：

- 有效朝贡期内两个方向、所有战争类型都被阻止；
- 战争展示、AI、队列、提交和最终入口使用同一规则；
- 断贡后只移除朝贡门禁；
- 正式附庸仍可按现有规则发动独立战争；
- 第三方与朝贡国之间的战争权限不受影响。

最后运行规则测试、源代码门禁、项目编译，并在游戏内验证连续两个岁贡年、主动拒贡、无力纳贡、女眷入贡、继承人即位和双方宣战拦截。运行时日志用于确认每条关系每年只结算一次。

## 非目标

本设计不包含：

- 可配置的三年一贡或五年一贡；
- 玩家手动指定贡女或宗室接收人；
- 宗主为朝贡国提供自动参战义务；
- 朝贡国加入宗主的附庸军事网络；
- 因一次拒贡立即自动发动惩罚战争；
- 改变正式附庸的贡赋、吸收、独立或军事义务规则。
