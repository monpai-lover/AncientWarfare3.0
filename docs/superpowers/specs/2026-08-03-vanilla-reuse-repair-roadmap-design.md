# AW3 原版能力复用修复路线图

## 目标

在不削弱 AW3 战争导演、战争目标、军团任务、动员和联机权威规则的前提下，消除 AW3 与 WorldBox 原版之间重复的状态所有权，并修复审查期间确认的正确性问题。

本轮明确不处理新的多级附庸地图模式、国号标签、城市标签或 nameplate 池化。

## 子项目

### A. 正确性与低风险原版 API 复用

设计规格：`docs/superpowers/specs/2026-08-03-vanilla-reuse-correctness-design.md`

范围：

- 修复逐鹿结算中活动战争暂时引用已销毁国家的问题。
- 强制已登记世子保持本国国籍并居住于本国有效城市。
- 修复已死亡人物在当前打开的族谱中仍显示“在世”的问题。
- 空城重新归属统一使用原版 `City.joinAnotherKingdom`。
- 使用原版战争、城市统计和对象 ID 索引替换语义等价的手工实现。
- 限制重复异常日志，单一 AW3 阶段故障不得永久暂停整个世界。

### B. RTS 原版执行权收归

设计规格：`docs/superpowers/specs/2026-08-03-rts-native-execution-ownership-design.md`

范围：

- AW3 保留战略规划；Actor 实际移动交给原版路径系统。
- Army 创建、成员、统帅、销毁和存档由原版生命周期 API 负责。
- AW3 决定跨海需求和运输优先级；原版 Taxi 负责请求、登船、航行和登陆。
- AW3 决定占领政策；原版完成 `finishCapture/joinAnotherKingdom`。
- 删除同一 Actor、Army、TaxiRequest 或 City 状态同时被两套执行器修改的路径。

## 实施顺序

1. 完成子项目 A 的自动化测试、代码修改、回归和游戏内验证。
2. 在 A 稳定后执行子项目 B，不并行修改共享的 `War`、`City`、`Army` 和 Actor 生命周期代码。
3. B 按移动、Army、Taxi、占领四个检查点渐进迁移；每个检查点必须能独立回退。

## 总体验收

- 逐鹿灭国后持续运行至少一个游戏年，不出现活动战争引用失效国家或 `Kingdom.getSpecies` 空引用。
- 世子在指定、存档读取和后续国籍变化后，都能在一个游戏月内回到登记国家。
- 当前已打开的族谱能在人物死亡后的有限帧内显示“已故”和正确卒年。
- RTS 军团能完成集结、连续攻城、跨海、回援和战后清理，无双路径执行、重复军团或重复运输请求。
- 任一 AW3 阶段异常只降级该阶段，不造成逐帧日志风暴或全局永久暂停。
