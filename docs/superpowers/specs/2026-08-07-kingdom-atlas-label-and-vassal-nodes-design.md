# 舆图国号同步与附庸关系节点设计

## 目标

舆图国号在视觉和布局上与附庸层级 map mode 保持同步，并让获得附庸、失去附庸进入舆图时间轴。实现只读取已有城市历史、城市几何归档和 `VassalRelation`，不建立新的历史累计池。

## 国号渲染

舆图不再将层级地图的世界单位直接换算成 `UnityEngine.UI.Text.fontSize`。抽取共享的国家标签视觉渲染边界，由层级地图和舆图共同使用以下规则：

- `HierarchicalVassalMapModeGeometry.CalculateLabelPlacement` 计算最大连通疆域、锚点、角度和可容纳字号；
- `HierarchicalVassalMapModeRules.ResolveRenderedLabelSize` 计算最终世界单位尺寸；
- 使用相同字体和 `TextMesh` 字形边界测量，长国号按照实际字形宽高缩放；
- 两字国号使用相同的 `CalculateCountryLabelGapLevel` 和 `CalculateCountryGlyphCenterOffset`；
- 正文使用国家主色暗化后的颜色，透明度与层级地图一致；
- 描边使用白色八方向 `TextMesh`，厚度为最终字号的同一比例；
- 国号不使用背景板。

舆图离屏相机仍只渲染专用层。底图和标签在同一离屏目标上合成，不读取实时地图相机，也不复用层级地图运行时对象的位置状态。世界坐标通过节点的完整地图宽高映射到输出像素，标签字号按同一比例映射，因此疆域越大，可容纳的国号越大；狭长、小型或长名称疆域会按包络结果缩小。

## 附庸关系节点

每条有效 `VassalRelation` 最多产生两个节点：

- `START_TIME >= 0`：获得附庸节点；
- `END_TIME >= 0`：失去附庸节点。

只保留宗主国或附庸国等于当前舆图王国的关系节点。节点双方分别为宗主和附庸，使用关系行保存的历史名称和历史颜色。关系开始节点按开始时刻计算有效关系快照；关系结束节点按结束发生后的状态计算，使图片能够体现附庸已经脱离。

节点时间轴统一按以下键稳定排序：

1. `world_time`；
2. 节点类型：城市事件、获得附庸、失去附庸；
3. 原始记录 ID。

同一时刻的关系节点重放城市归属时包含该时刻全部城市事件。节点稳定键使用 `event_kind + source_id + phase`，不把关系 ID 强塞进城市 `event_id`，避免缓存、manifest 和增量续生成冲突。

## 节点显示

获得/失去附庸节点沿用现有左右双方信息和编年史列：

- 标题显示年份以及本地化的“获得附庸”或“失去附庸”；
- 双方为宗主国和附庸国；
- 地图显示双方及该时刻按设计应可见的历史附庸疆域；
- 物理边界仍按实际国家所有者区分；
- 附庸继承历史宗主颜色，但保留自己的边界和国号。

## 缓存与兼容

PNG、GIF、预览缓存和 manifest 使用新的节点稳定键。旧的仅城市节点缓存不再命中新版本，但不会被删除。旧存档没有附庸关系记录时仍可生成城市节点；缺少关系结束时间时只生成获得附庸节点。

## 测试

- 国号布局测试覆盖大、小、狭长疆域以及长名称，确认字号随可容纳疆域变化；
- 源码守卫要求舆图使用共享 `TextMesh` 视觉渲染边界，禁止固定像素字号和单层 UI Outline；
- 关系节点测试覆盖开始、结束、未结束、无关王国、同一时刻多关系和稳定排序；
- 缓存键测试确认城市节点、获得附庸节点和失去附庸节点不会碰撞；
- 舆图专用规则测试、完整规则测试和 net48 主项目编译必须通过；
- 游戏内验收对比同一疆域在层级地图与舆图中的字体、字号层级、角度、颜色、字距和描边。
