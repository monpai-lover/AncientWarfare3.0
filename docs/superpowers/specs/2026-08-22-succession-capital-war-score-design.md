# 宗统分裂战争首都目标与全境分数设计

## 目标

修复宗统分裂战争在迁都和全境占领场景下的结算不一致：开战时冻结双方首都作为战争目标；原宗或竞争宗攻下对方冻结首都时，由对应一方获胜并完成整合；一方完全占领另一方全部有效城市时，权威战争分数立即结算为胜方 `+100`、败方 `-100`。

## 现状与根因

`SuccessionDisputeSnapshot` 当前只保存原宗、竞争宗和战争 ID，不保存开战时首都。`SuccessionDisputeService.OnWarEnded` 因而主要信任原版 `WarWinner`，首都迁移后无法判断实际宗统目标是否完成。

`WarScoreService.RecordCityControlChanged` 会为最后一座城市设置 `Decisive`，但没有统一的全境占领极值结算入口；城市控制贡献、战斗分数和损耗分数可能让最终签名分数停留在普通范围。

## 设计

### 1. 开战首都快照

在宗统快照中增加：

- `OriginalCapitalCityIdAtWarStart`
- `RivalCapitalCityIdAtWarStart`

`StartWar` 成功绑定宗统战争时读取双方当前有效首都并持久化。旧存档没有字段时使用 `-1`，读取运行时可从战争创建前的可用首都或当前有效首都补齐一次；无法补齐时保留原版 `WarWinner` 回退逻辑。

### 2. 宗统战争胜负

战争结束时只对宗统战争启用首都目标判定：

1. 原宗控制竞争宗开战首都，原宗获胜，竞争宗整合回原宗。
2. 竞争宗控制原宗开战首都，竞争宗获胜，原宗整合回竞争宗的宗统归属。
3. 两个冻结首都都没有被对方控制时，回退 `WarWinner`，兼容早期存档和非首都结算。
4. 首都迁移只改变国家当前 `capital`，不改变快照中的目标城市。

控制判定使用权威冻结占领记录和当前城市归属，避免只看视觉占领进度。若冻结首都已毁灭，则该方向不判定为完成，继续使用另一方首都或原版赢家回退。

### 3. 全境占领战争分数

新增纯规则函数 `WarScoreTotalOccupationRules`，输入双方初始有效城市数、当前双方有效城市数、城市控制归属和双方战争身份，输出是否满足全境占领及胜方。

满足以下条件时触发：

- 失败方开战时至少有一座有效城市；
- 失败方当前有效城市数为零，或其全部开战城市均由胜方控制；
- 胜方仍是战争参与方，且控制记录的控制者与胜方 kingdom ID 一致。

触发后由 `WarScoreService` 在同一持久化事务中：

- 将 canonical score 写为 `+100`（攻击方视角或防守方视角依战争身份确定）；
- `ForPerspective` 对另一方返回 `-100`；
- 保留城市控制、战役和历史记录；
- 标记 `DecisiveScore` 和全境结算事件，保证重复 tick 幂等；
- 让现有强制投降/和谈 AI读取到极值分数。

普通战争不改变现有城市分数预算和战斗分数规则，只有满足全境条件时才进入极值结算。

## 持久化与兼容

- 宗统表新增两个可空/默认 `-1` 的城市 ID 字段，数据库迁移使用已有幂等迁移模式。
- 旧快照读取成功但字段不存在时按 `-1` 处理，不阻止战争结算。
- 新增的全境结算事件使用独立事件键 `total_occupation:<war>:<winner>`，避免重复发放。
- 战争结束先完成分数持久化，再执行宗统整合，避免整合过程中丢失分数状态。

## 测试

- 原宗占领竞争宗开战首都，判定原宗获胜。
- 竞争宗占领原宗开战首都，判定竞争宗获胜。
- 开战后迁移任一首都，仍以旧城市作为目标。
- 首都被毁灭时不误判为占领成功。
- 失败方所有城市被同一胜方控制后，canonical score 为 `+100`，失败方视角为 `-100`。
- 已触发全境结算后重复控制事件不重复写入或改变结果。
- 旧快照缺少首都字段时仍可按原版赢家完成结算。

## 非目标

- 不改变普通战争的宣战理由、城市割让规则和非宗统战争目标。
- 不改变宗统战争之外的迁都规则。
- 不把普通城市占领全部改成固定 `+100`，只有全境条件满足时才极值结算。
