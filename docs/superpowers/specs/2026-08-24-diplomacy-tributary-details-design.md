# 外交窗口朝贡详情展示设计

## 目标

在外交窗口的国家关系列表和选中关系标题中，直接显示现行朝贡关系的核心内容；悬停提示补充完整结算信息。非朝贡关系的现有展示和外交操作保持不变。

## 现有上下文

- `DiplomacyConversationWindow.BuildRelationDetail` 负责外交关系卡片和选中关系标题的摘要文本。
- `VassalService` 已从 `VassalRelation` 表读取朝贡关系，并保存 `TRIBUTE_RATE`、`LAST_TRIBUTE_PAID_YEAR`、`NEXT_TRIBUTE_DUE_YEAR`、`LAST_TRIBUTE_FACTOR_PERCENT`。
- `VassalFiscalRules` 与 `VassalService.ReadCentralPowerSummary` 已有预计政治点和黄金的计算路径。
- 女眷进贡由 `TributaryHouseholdOfferingService` 按关系和年份防重复提交，不能在 UI 中重新触发结算。

## 方案

### 数据边界

增加只读的朝贡外交详情读取方法，输入外交双方，先确认当前活动关系的朝贡方向，再返回：

- 朝贡方和宗主方方向；
- 合同贡率；
- 下一次结算年份及距离当前年份；
- 最近一次结算年份；
- 最近一次实际缴纳比例；
- 按现有财政公式计算的下一次预计政治点和黄金；
- 当前结算状态（待缴纳、已按期缴纳、尚无记录、关系已失效）；
- 当前年份是否已有女眷进贡记录。

读取失败、关系失效或数据库字段缺失时返回“暂无结算记录”，不影响外交窗口打开。

### 展示位置

1. 左侧外交国家列表的关系摘要：朝贡关系额外增加一行紧凑文本，显示“朝贡比例、下次结算年份、预计政治点/黄金”。
2. 选中关系标题：复用同一摘要，避免两处状态不一致。
3. 国家卡片悬停提示：在现有关系、君主、首都和军力信息后增加完整朝贡明细，包括最近结算结果和女眷状态。

只对朝贡关系增加高度；普通、战争、盟友和条约关系保持现有高度与布局。

### 本地化

新增独立的 `aw_diplomacy_tributary_*` CSV 文案键，覆盖标题、比例、下次结算、预计政治点、预计黄金、最近结算、女眷状态和未知状态。代码 fallback 保持中文可读，避免 CSV 缺失导致英文泄漏。

## 数据流

`DiplomacyConversationWindow` -> `VassalService` 只读查询 -> 朝贡详情 DTO -> `BuildRelationDetail` / `DiplomacyKingdomListItem` 文本与 tooltip。

UI 刷新只读取当前选中或列表中的关系，不修改关系投影、结算年份、政治点、黄金或后宫数据。

## 错误处理

- 任何数据库异常捕获并返回空详情；外交窗口继续显示关系名称、好感和距离。
- 王国被销毁、关系结束或双方不是直接朝贡关系时，不显示朝贡行。
- 预计金额使用非负值和现有公式，不在 UI 层重复转账或写历史。

## 测试

- 源码规则测试：宗主方向、朝贡方向、非朝贡关系和失效关系的详情判定。
- 源码守卫：外交摘要调用朝贡详情读取，且使用 `aw_diplomacy_tributary_*` 本地化键。
- 主项目构建通过；不要求在规则测试项目既有重复文件/缺失脚本问题解决前扩大测试范围。
