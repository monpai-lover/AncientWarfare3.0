# 历史人物大臣箱扩充设计

## 目标

扩充历史人物抽卡系统的大臣箱，覆盖当前六个历史时期，并将武将作为大臣箱中的子类型。文臣部署后进入官场候选池；武将部署后立即成为已有国家的大将并带领军队。大臣部署不改变当前国家名称，官场来源显示统一使用“姓名（历史朝代）”。

## 范围与不变项

- 保留 `HistoricalFigureCardRole.Monarch` 和 `HistoricalFigureCardRole.Minister` 两个顶层角色。
- 君主箱的割据建国、国家命名和现有部署行为保持不变。
- 大臣只能部署到已有国家的城市，不能在无主地建国。
- 大臣部署使用目标城市所属种族，不默认生成 Xia 种族。
- 现有五级稀有度、概率、金色“神秘人物”展示和汰换规则保持不变。
- 不修改与本功能无关的女性继承、heir 禁任官和普通官场定期换人逻辑。

## 数据模型

新增大臣子类型：

```csharp
public enum HistoricalFigureCardMinisterType
{
    CivilOfficial,
    MilitaryGeneral
}
```

`HistoricalFigureCardDefinition` 增加或提供以下稳定字段：

- `MinisterType`
- `CollectionId`
- `HistoricalKingdomName`
- `HistoricalEra`
- `FameScore`
- 父母卡片 ID 与展示名
- 背景简介和详细传记
- `IsMilitaryGeneral` 便捷判断

君主卡的 `MinisterType` 使用默认值，不参与武将部署分支。大臣卡必须显式配置文臣或武将类型。

### 历史数据标准

每张新增卡必须具备唯一稳定 ID、人物姓名、历史时期、历史政权、名气值、卡片稀有度、收藏品来源、背景介绍和详细介绍。父母资料有可靠依据时使用父母卡片 ID；资料不确定时保留说明或空值，不伪造谱系。

历史政权字段只用于人物来源、官场标签和历史记录，不用于改名当前国家。显示格式为：

```text
人物姓名（历史朝代）
```

例如 `韩信（汉）`、`诸葛亮（蜀汉）`、`房玄龄（唐）`。

## 六时期大臣池

继续复用当前六个箱子：

1. 先秦/秦
2. 汉
3. 三国、两晋、南北朝
4. 隋唐
5. 五代十国、宋辽金
6. 元明清

每个时期的大臣池不少于 40 张，且同时包含文臣和武将。新增数据按人物历史年份归入对应时期箱，并设置对应 `CollectionId`。

名臣范围包括政治家、谋臣、制度建设者、学者型官员、统帅和名将。代表性人物包括管仲、商鞅、李斯、韩信、萧何、张良、诸葛亮、周瑜、房玄龄、魏征、王安石、岳飞、张居正、戚继光等。具体卡片 ID 必须保持稳定，不能使用姓名字符串作为运行时唯一键。

## 抽取、仓库与汰换

- 文臣和武将都属于大臣箱，不新增第三个顶层箱子。
- 大臣箱列表可以按名气值排序，排序不能改变卡片对象与点击索引的对应关系。
- 金色人物继续以“神秘人物”显示，不在普通箱子列表中直接暴露具体姓名。
- 新卡必须写入所属朝代箱的收藏品来源，才能参与仓库筛选和汰换。
- 现有五级颜色和概率继续使用：蓝、紫、粉、红、金，由高概率到低概率排列。

## 部署流程

### 公共流程

1. 校验卡片存在、玩家拥有卡片、目标城市有效且属于存活的文明国家。
2. 按目标城市种族生成成年历史人物。
3. 写入卡片身份、父母、历史政权、背景和部署标识。
4. 将人物加入目标城市和当前国家。
5. 根据 `MinisterType` 执行文臣或武将分支。
6. 写入传记、任职历史和卡片来源。
7. 所有状态提交成功后才消耗仓库卡片。

### 文臣分支

- 不修改国家名称、首都或国家历史国号。
- 加入当前国家的官场候选池。
- 候选池记录历史来源标签“姓名（历史朝代）”。
- 不创建军队，不设置大将身份。
- 记录当前国家、城市和文官候选状态。

### 武将分支

- 不修改国家名称、首都或国家历史国号。
- 使用现有普通军队维护体系。
- 先通过 `GeneralService.PromoteToGeneral` 标记为正式大将。
- 优先复用目标城市可接纳的普通军队。
- 没有可用军队时调用现有 `ArmyManager.newArmy(actor, city)` 创建军队。
- 确保历史人物成为军队成员和队长，并更新军队锚点、国家归属和名称。
- 立即补充初始士兵，使部署完成后地图上能看到军队。
- 不进入文官候选池，但保留在军事官场和正式将领列表中。

军队操作优先复用 `AWArmyService`、`StandingArmyService`、`GeneralService` 和现有军队生命周期接口，避免直接绕过队长租约、军队归属和清理逻辑。

## 事务与回滚

部署失败时必须回滚：

- 人物创建和城市加入状态。
- 大将标记、官职记录和候选池记录。
- 新建军队、军队成员关系和队长关系。
- 传记和任职历史的半成品记录。

只有人物、官职/军队、历史记录全部成功后才调用卡片消耗。新建军队无法完成有效队长绑定时，安排现有清理队列处理空壳军队，并返回明确错误，不消耗卡片。

## 历史记录与 API

### 文臣

记录出生、历史身份、部署、当前国家、当前城市、官场候选和任职信息。官场标签使用历史朝代，不使用当前国家名称。

### 武将

除上述记录外，记录入仕、任命大将、创建或加入军队、担任队长和初始兵力。国家灭亡、人物死亡和军队解散继续由既有生命周期服务维护。

对外 API 暴露稳定查询字段：

```csharp
HistoricalFigureCardRole Role { get; }
HistoricalFigureCardMinisterType MinisterType { get; }
string HistoricalKingdomName { get; }
string CollectionId { get; }
bool IsMilitaryGeneral { get; }
```

其他历史模组通过卡片 ID 查询定义，不依赖卡片在列表中的位置，也不自行解析姓名来判断人物类型。

## 存档兼容

- 现有六张汉代大臣卡继续可读。
- 旧卡缺失 `MinisterType` 时通过稳定 ID 映射到文臣或武将。
- 旧存档缺少 `CollectionId` 时按卡片所属时期补齐。
- 未知或损坏的子类型回退为文臣，保证存档可加载。
- 重载后武将保留正式大将标记和军队队长状态；文臣保留官场候选状态。

## 测试与验收

### 卡池

- 六个时期箱子都能返回大臣卡。
- 每个时期大臣卡不少于 40 张。
- 每个时期同时存在文臣和武将。
- 所有卡片 ID 唯一，收藏品来源有效。
- 父母卡片 ID 可解析时必须指向存在卡片。
- 金色人物继续显示为神秘人物。

### 文臣部署

- 只能部署到已有国家的城市。
- 生成种族等于目标城市种族。
- 国家名称不变。
- 官场显示包含“姓名（历史朝代）”。
- 加入文官候选池且不创建军队。
- 成功后消耗卡片，失败后保留卡片。

### 武将部署

- 只能部署到已有国家的城市。
- 生成种族等于目标城市种族。
- 国家名称不变。
- 标记为正式大将并成为军队队长。
- 复用或创建普通军队，并立即拥有初始士兵。
- 不进入文官候选池。
- 地图上能看到人物和军队。
- 任一步骤失败都能回滚。

### 存档与回归

- 旧存档能读取既有大臣卡。
- 新增子类型和收藏品来源可以保存、加载。
- 重载后武将身份、队长关系和文臣候选状态保持一致。
- 君主卡仍能在空地建国并设置历史国号。
- 大臣部署不会触发国家改名。
- 既有女性继承、heir 禁任官、官场换人和军队维护测试不回归。
