# 爵位男系续承与禁卫世子登基设计

## 目标

1. 所有男性持爵者及其已经确定的男性继承人，在没有存活儿子时继续尝试生育，避免爵位因原版个人子女上限而绝嗣。
2. 继承人的儿子同样进入下一代续承链，使爵位不是只保证一代。
3. 已登记世子若带有旧禁卫身份，继承权优先；登基前完整清理禁卫身份、职位和编制。
4. 不取消普通人的原版子女上限，不开放无限生育，不绕过世界生育法、死亡、无配偶、饥饿和城市危险条件。

## 已确认根因

原版 `Actor.hasReachedOffspringLimit()` 使用 `stats["offspring"]` 限制个人累计子女。人类和 Xia 的基础值均为 5。达到上限后：

- `DecisionsLibrary.sexual_reproduction_try` 的权重从 `2.0` 降为 `0.1`；
- `BabyHelper.canMakeBabies()` 直接拒绝母亲继续怀孕；
- AW3 `NobleHeirPregnancyService` 的重试条件也要求未达到上限。

AW3 当前只提高 `birth_rate`，该值控制一次分娩的额外婴儿尝试，不提高个人累计子女上限。因此连续生女、续弦对象已有子女或儿子早亡后，十月怀孕与 70% 生男规则仍可能被原版上限永久截断。

禁卫方面，`AccessionIdentityService.Prepare()` 已调用 `DismissGuard(actor, "became_king")`，但当前规则同时：

- 禁止禁卫进入 `Kingdom.setKing`；
- 禁止禁卫身份被即位流程替换；
- 不允许以 `became_king` 为理由结束终身禁卫身份。

所以既有清理调用无法生效。

## 续承资格

新增统一的续承资格解析，只有以下男性角色可触发个人子女上限豁免：

- 当前国王；
- 王国已登记继承人；
- 在任藩王；
- 藩国已登记世子；
- 持有有效男性个人爵位者；
- 持有男性个人爵位者当前的嫡长存活儿子，即该爵位的预期袭爵人。

普通贵族身份本身不构成豁免。女性持有的公主、郡主等非男性世袭样式不建立父系续承豁免。

预期袭爵人沿用 `NobleRankService` 死亡袭爵时的父系、男性、存活、嫡长排序，避免生育系统和实际袭爵选出两套不同的人。

## 生育规则

定义 `NeedsMaleLineContinuation`：角色具有续承资格、本人存活成年、具备生育能力，并且没有存活儿子。

当夫妻任一方满足该条件时：

1. `BabyHelper.canMakeBabies()` 仅忽略“母亲已达到个人 offspring 上限”这一项；成年、生育能力、营养仍必须通过。
2. `NobleHeirPregnancyService` 的后续十月怀孕重试同样忽略个人 offspring 上限。
3. 现有 70% 男、30% 女规则保持不变。
4. 第一胎或后续胎仍无存活儿子时，分娩完成后继续排队重试。
5. 一旦出现存活儿子，立即清除重试请求并恢复原版个人子女上限。
6. 唯一存活儿子死亡后，索引更新，符合年龄、配偶、营养和安全条件的父母重新进入续承流程。

该豁免不修改 `stats["offspring"]`，因此 UI、遗传统计和普通繁殖仍使用原版数值，也不会让已有儿子的持爵者继续超额生育。

## 配偶与代际延续

现有 `NobleRemarriageService` 保留，并把续承资格角色作为最高优先级对象。每年仍使用有界候选扫描，避免恢复全图配偶搜索。

个人爵位预期袭爵人在确定后即获得续承资格，不必等父亲死亡、自己拿到爵位后才开始求嗣。这样可以在两代之间形成：

`持爵者 -> 存活儿子/预期袭爵人 -> 该继承人的存活儿子`

若预期袭爵人死亡，资格随实际嫡长存活儿子的重新解析转移，不持久保留在失效对象上。

## 禁卫世子登基

普通禁卫仍不得进入继承候选池。继承人身份优先于禁卫身份：角色一旦成为王国明确登记的继承人，就立即以 `became_heir` 原因退出禁卫军；禁卫招募也继续排除现任继承人。登基流程再处理“旧存档中的登记继承人仍遗留禁卫身份”这一兼容路径。

登基顺序为：

1. `HeirService` 提交新继承人登记时先确认目标角色，若有禁卫身份则以 `became_heir` 调用统一 `DismissGuard`；
2. 清除禁卫布尔、队长标记、禁卫特质、禁卫 citizen job、禁卫军 Army 归属和王国 roster，空禁卫军按现有 `TryRemoveEmptyArmy` 清理；
3. 只有禁卫身份清除成功后才写入继承人 id 和 `IS_HEIR`；
4. `Kingdom.setKing` 前确认候选人是该国已登记继承人，并允许 `became_king` 再做一次幂等兼容清理；
5. 确认禁卫身份已清除后再进入 `AccessionIdentityService.Prepare` 和原版 `setKing`；
6. 新君主即位后由 `OnKingChanged` 为新朝廷维护禁卫，但现任继承人和新君主本人永不重新进入候选名单。

非登记继承人的禁卫、普通官职替换、奴役和城市领袖任命仍受终身禁卫规则阻止。读档只恢复已保存状态，不把普通禁卫提升为国王；若存档中的当前国王残留禁卫标记，只做幂等清理。

## 性能与持久化

- 生育决策热路径不得查询 SQLite。
- 王、王国继承人、藩王和藩国世子使用现有运行态索引。
- 个人爵位持有者和预期袭爵人使用随授爵、出生、死亡、袭爵和读档更新的有界内存索引。
- 男嗣判断继续使用 `DynasticLivingSonIndexService`，不在每次 AI 决策时遍历全体 Actor。
- 新索引属于可重建运行态，不新增存档权威字段；权威爵位仍来自 `Enfeoffment` 和现有继承记录。

## 测试

规则测试覆盖：

- 普通人达到五名子女后仍被原版限制；
- 持爵者无存活儿子时可越过个人上限；
- 登记继承人和个人爵位预期袭爵人获得相同豁免；
- 已有存活儿子后豁免立即关闭；
- 儿子死亡后豁免恢复；
- 世界法、营养、生育能力和城市安全仍能阻止怀孕；
- 非登记禁卫仍不能登基；
- 登记世子登基前禁卫特质、职位、Army 和 roster 全部清除；
- `became_king` 清理幂等，重复执行不损坏新禁卫编制。

集成验证运行生育、续弦、继承、禁卫专项测试和完整项目构建；实机使用新世界观察至少三代持爵家系，并检查登基前后的 Actor 职业、特质和军队归属。
