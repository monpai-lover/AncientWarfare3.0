# 聯合科舉武舉與動態將領編制設計

## 目標

在現有科舉系統上加入武舉。科舉和武舉共用同一個開科週期、開科年份、階段時間與王國年度入口，但候選人、評分、資格、名額和任命結果分開保存。

武舉必須支援 75 歲退休規則，直接使用原版 `Actor.getAge()`。殿試通過者授予大將職級；地方武試通過但殿試未通過者授予地方小將領職級。每個王國的將領編制與空缺依照實際軍事需求動態計算。

## 現有代碼基礎

- `KingdomAnnualWorkService.RunStateGovernmentExam()` 是年度考試的唯一入口。
- `CivilServiceExamService.OnKingdomYear()` 負責以 `LineageKeys.CIVIL_SERVICE_EXAM_ANCHOR_YEAR` 和 `CivilServiceExamRules.IsCycleYear()` 判定三年一科。
- `CivilServiceExamService` 建立場次、安排階段到期日、處理候選人和排名。
- `CivilServiceExamCandidateQuery`、`CivilServiceExamRules`、`CivilServiceExamPersistence` 和 `CivilServiceExamWindow` 分別提供候選人、規則、存檔和 UI 模式。
- `Army`、`ArmyData`、`ArmyManager` 和 `GeneralService` 提供軍隊、隊長及將領資料來源。
- 原版年齡公式為 `Date.getYearsSince(base.created_time) + age_overgrowth`，武舉與退休邏輯不得建立第二套年齡系統。
- `last_office_exam_timestamp` 是官職考核時間，不用來控制科舉或武舉共同週期。

## 聯合開科週期

新增 `ExamCycleService` 作為共同調度器。`KingdomAnnualWorkService.RunStateGovernmentExam()` 只呼叫它，不再讓科舉和武舉各自判定年份。

共同調度器的責任：

1. 讀取或建立 `CIVIL_SERVICE_EXAM_ANCHOR_YEAR`。
2. 使用目前的三年週期判定本年是否開科。
3. 解析科舉和武舉共用的 `Tribute` 或 `Imperial` 模式。
4. 為同一王國、同一週期年建立一個科舉場次和一個武舉場次。
5. 為兩個場次產生相同的開科日和階段到期日。
6. 以王國 ID 加週期年作為冪等鍵，避免重複建場。

科舉與武舉使用獨立資料表和 session ID，但共享以下欄位：

```text
KingdomId
CycleYear
OpenWorldDay
StageDueWorldDay
ExamMode
```

如果一方候選人不足，該方可以標記為 `Cancelled` 或提前完成，但不得改變另一方的開科年份和階段時刻。

## 武舉階段與資格

武舉沿用科舉的 `Scheduled`、`Local`、`Prefectural`、`Metropolitan`、`Palace`、`Ranking` 和 `Completed` 狀態。UI 顯示名稱改為：

```text
Local        地方武試
Prefectural  州府武試
Metropolitan 武會試
Palace       武殿試
Ranking      武榜排名
```

資格分為：

```text
武秀才：地方武試通過
武舉人：州府武試或武會試通過
武進士：武殿試通過
```

結果規則：

- 地方武試未通過者，不進入將領候補。
- 通過地方武試並完成地方階段者，可以進入後續州府武試與武會試。
- 進入殿試但未通過者，保留其地方或會試資格，授予地方小將領任命資格。
- 殿試通過者授予武進士，進入大將任命池。
- 非帝國模式沒有武殿試時，通過最高可用階段者視為地方小將領候補，不直接授予大將資格。
- 武舉資格只在角色存活、未退休、未年滿 75 歲且任命時再次通過資格檢查時有效。

## 候選人資格

武舉使用獨立的 `MilitaryExamCandidateQuery`，但沿用科舉的本地居民、外籍居民、奴隸、君主和現任職務排除邏輯。

候選人必須符合：

```csharp
actor != null
actor.isAlive()
actor.getAge() >= actor.subspecies.age_adult
actor.getAge() < 75
!actor.isKing()
!actor.isHeir()
!actor.isPrince()
!actor.isSlave()
!RetirementService.IsRetired(actor)
```

已任命的中央官員、軍府長官、軍隊隊長和其他王國現任將領不重新進入同一王國武舉候選池。普通士兵、地方軍人和未擔任指揮職位的軍籍角色可以參加。

## 武舉評分

評分直接讀取現有角色能力，不新增角色能力欄位：

```text
warfare   35%
damage    20%
strength  15%
speed     10%
diplomacy 10%
軍功      10%
```

分數範圍維持 0 至 100，保留科舉的小幅隨機修正。`warfare` 是統率和戰術核心；`damage` 和 `strength` 反映武藝；`speed` 反映機動；`diplomacy` 反映軍隊協調與服從；軍功從現有戰爭、參戰、勝利和服役資料中讀取，沒有資料時按 0 處理。

各階段的權重可以不同，但最後總分和排名使用同一個 0 至 100 的標準，方便 UI、AI 和任命流程比較。

## 動態將領編制

王國不設定固定將領數量。每年在聯合開科前，先計算該王國的軍事職位需求。

### 大將需求

大將職位代表戰略級指揮，需求來源為：

- 每一支需要獨立指揮的戰略軍隊一個主將槽位。
- 每一個軍府或軍事總管區一個主將槽位。
- 首都或最高軍事中心一個防務主將槽位。
- 王國正在進行大型戰爭且存在獨立戰線時，為每條需要獨立指揮的戰線增加主將槽位。

不為空軍隊、已解散軍隊或不需要獨立指揮的臨時隊伍建立大將槽位。大型軍隊可以增加副將需求，但副將是否使用大將或小將領由軍隊規模和軍府規則決定。

### 地方小將領需求

地方小將領職位代表城市、駐軍和地方部隊指揮，需求來源為：

- 每一個有駐軍或軍事建制的城市一個地方指揮槽位。
- 每一支沒有合格指揮官的地方軍隊一個小將領槽位。
- 大型軍隊超過主將單獨管理能力時，增加副將槽位。
- 邊境城市、戰區城市和軍府下轄城市可依現有軍事狀態增加地方槽位。

### 空缺計算

空缺不是簡單按角色總數估算，而是按職位槽位計算：

```text
大將空缺 = 大將需求槽位 - 現任合格大將 - 已鎖定任命的大將候補
小將領空缺 = 地方需求槽位 - 現任合格小將領 - 已鎖定任命的小將領候補
```

結果下限為 0。退休、死亡、離境、被俘、王國易主和軍府撤銷都會使槽位重新變成空缺。

### 候補名額

武舉候補數量依空缺和軍隊規模計算，不固定為全國常數：

```text
候補目標 = max(最低保留數, ceil((大將空缺 + 小將領空缺) / 2))
```

最低保留數只在王國擁有有效軍事建制時啟用；沒有軍隊、軍府和駐軍的王國不強行產生武將候補。候補上限使用科舉的容量限制模式，避免人口很小的王國建立過大的考試列表。

## 殿試任命規則

武舉錄取結果直接對應動態職位槽位：

```text
武殿試通過者        → 大將候補 → 大將職位
地方武試通過、殿試落選者 → 小將領候補 → 地方小將領職位
```

任命排序：

1. 先處理大將空缺，只從武進士中選擇。
2. 大將空缺填滿後，武進士可以按需要填補高階地方指揮槽位。
3. 再處理地方小將領空缺，優先使用殿試落選但地方或會試資格完整者。
4. 候補不足時，才使用科舉現有的普通軍職替補或臨時任命規則。
5. 任命前重新檢查角色年齡、存活、王國歸屬和現有職位，避免考試期間狀態變化造成錯任。

一名角色不能同時佔用大將和小將領槽位，也不能同時佔用文官正式職位和軍事正式職位。

## 75 歲退休

年度順序固定為：

```text
退休檢查
    ↓
釋放官員與將領槽位
    ↓
重新計算文官和軍事空缺
    ↓
聯合開科判定
    ↓
同時建立科舉和武舉場次
```

退休判定只使用：

```csharp
actor.getAge() >= 75
```

退休角色保留履歷、軍功、武舉排名和資格記錄，但不再執行官職 AI、不再指揮軍隊、不再進入候選池，也不得被新職位任命。

## 存檔與多人同步

新增資料：

```text
MilitaryExamSession
MilitaryExamCandidate
MilitaryOfficerRecord
```

每個場次和候選人都使用唯一鍵，並保存週期年、階段、評分、資格、名次、任命狀態和角色年齡快照。載入舊存檔時：

- 舊存檔沒有武舉資料時，從現有科舉錨定年份重建共同週期。
- 不修改原角色 `created_time` 或 `age_overgrowth`。
- 重建武舉 runtime queue 時，重新驗證 75 歲退休和王國歸屬。
- 多人模式下以王國 ID、週期年和場次 ID 防止重複開科與重複任命。

## UI 設計

將 `CivilServiceExamWindow` 擴展為聯合考試窗口：

```text
第 N 年聯合開科

[科舉] [武舉] [歷屆考試]
```

武舉頁面顯示：

- 當前武舉階段和共同開科年份。
- 大將需求、現任大將、大將空缺。
- 小將領需求、現任小將領、小將領空缺。
- 候選人年齡和距離 75 歲的年數。
- warfare、damage、strength、speed、diplomacy、軍功和總分。
- 是否地方武試通過。
- 是否殿試通過。
- 對應的大將或小將領任命資格。

窗口必須在 100%、125% 和較小解析度下測試，候選人列表和歷屆場次保持可滾動，長文字不得覆蓋按鈕或排名。

## 錯誤處理

- 共同調度器以唯一鍵保證重入安全。
- 建立一方場次失敗時記錄錯誤並保留另一方可恢復的場次資料。
- 職位需求計算遇到無效軍隊、已毀城市或空軍隊時跳過該項，不中斷整個年度工作。
- 所有軍職任命使用冪等操作，重試不會產生第二份軍職記錄。
- 候選人查詢、評分和任命失敗時，不刪除已保存的考試結果。

## 驗證範圍

需要驗證：

1. 科舉和武舉在同一王國、同一週期年同時開科。
2. 兩種考試的階段時間一致，但候選人和分數獨立。
3. 殿試通過者進入大將候補，殿試落選但地方通過者進入小將領候補。
4. 軍隊、城市、軍府和戰爭狀態改變時，需求槽位和空缺數量正確變化。
5. 75 歲角色會先退休，再被計入空缺，且不會被新任命。
6. 舊存檔載入後共同週期、武舉候補和現任將領狀態一致。
7. UI 的科舉／武舉切換、列表滾動、排名、任命按鈕和本地化文字正常。
8. 重新建置後查看 `Player.log`，確認沒有空引用、重複場次或 UI 堆疊錯誤。

## 設計決策總結

聯合開科只共用時間和調度；科舉與武舉的候選人、評分、名額、資格、結果和任命完全分開。武舉殿試通過者是大將，地方通過但殿試未通過者是地方小將領。將領數量由實際軍事職位槽位決定，退休與軍事狀態變更會即時釋放或建立空缺。
