# 天命末城海岛避难与复兴设计

## 目标

当天命王朝只剩一座有港口的城市时，王、继承人、城市领袖和居民组成避难队伍，经现有临时运输船链前往海岛。无主海岛在登陆后建立新城；已有国家的海岛不瞬间转移，登陆完成后仅记录避难标记并通过现有普通战争流程处理。

## 架构

采用直接扩展 `MandateService` 的方案。`MandateService` 负责触发条件、避难状态、天命保护和最终交接；`IslandEscapeService` 只负责登船、航行、登陆和失败回滚；岛屿候选扫描独立缓存，不在 actor tick 中执行。

## 触发与候选

每个天命年度周期只评估一次。要求当前天命王朝有效、恰有一座存活城市、该城存在可用港口、没有正在进行的避难。候选岛必须是可登陆陆地并有海岸路线。无城市岛优先；已有城市岛允许作为目标，但不改变其所有权。没有候选或路线失败时保留原城并延迟重试。

## 迁移状态

`None -> Evaluating -> Boarding -> Voyaging -> Landing -> Founding/WarPending -> Completed/Failed`。状态和成员 ID 写入王国数据，读档时只恢复有效阶段，禁止重复注册运输组。进入 Evaluating 后暂停新的天命末城判定；只有在 Founding 或 WarPending 成功后才提交交接。

## 身份与交接

旧天命王朝保留国家 ID、国号、王朝历史和复国目标。无主岛登陆成功后，在目标 tile 创建新城，恢复成员的城市归属并保留旧朝身份。旧大陆末城在迁移提交后交给新的天命朝；新天命朝通过现有战争结束/天命接替逻辑产生，不在登船开始时提前清理旧朝。已有国家岛屿只启动普通战争，不做 `joinAnotherKingdom` 或瞬间吞并。

## 失败与历史

运输、登陆、建城任一步失败都释放成员任务、清理临时船请求、保留旧城和天命状态。成功、失败、海岛建城、避难战争和大陆天命交接分别写入国家史与城市史；新增日志使用 `LogError`。

## 验证

覆盖唯一末城、港口要求、候选排序、状态转移、读档恢复、无主岛建城、有主岛宣战、失败回滚和不重复建城；编译后部署到 Mods，使用存档验证登船、登陆和战争链不影响 RTS 运输。
