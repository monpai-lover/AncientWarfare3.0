# AW3 继承、政体与维护性能修复设计

## 目标

修复王位交接期间被误判为绝嗣所引发的一连串问题，并统一君主制与共和国的继承状态：有合法父系继承人时必须继续搜索兄弟和旁支；真正绝嗣时由共和国选出最强首领及次强继任者；临时空位不得触发共和国、原版全国分裂、叛乱危机或禁卫军解散。同时修复天命过早出现、共和国状态错误继承、禁卫军与奴隶军维护尖峰，以及氏族大树定位失效。

## 已确认根因

1. 原版 `KingdomBehCheckKing.execute()` 在旧王死亡后清空 `kingdom.king`，并通过 `timer_new_king` 等待 5 到 20 秒再选新王。
2. `HeirService.GetHeir()` 只以当前 `kingdom.king` 为基准。临时空位时 `FindHeir()` 返回空，随后 `StoreHeirSelection()` 把已经准备好的继承人覆盖为 `-1`。
3. `RepublicGovernmentService.RefreshAfterKingCheck()` 是原版检查的后置补丁，即使原版因 `timer_new_king > 0` 提前返回，它仍会把临时空位当成绝嗣并切换共和国。
4. 共和国状态会清空继承人，而 `GetHeir()` 又对共和国直接返回空，错误状态因此无法自行恢复。
5. 原版 `checkKingdomChaos()` 会让所有非首都城主同时独立。模组为了填满城主职位而主动调动王子，这会把一次继承查询失败放大为王子集体分裂。
6. 禁卫军维护也把临时空位视为无王，集中执行军队移除、数据库更新、历史记录、图形重建和归档。
7. 奴隶军填充先把候选人转成战士，再检查军队容量和奴隶比例，并在一次维护中重复扫描、转职和装备多个单位。
8. 氏族大树只显示男性，但定位路径同时遍历父母。定位可能选中母系路径，目标随后被男性过滤隐藏；失败处理又直接重开小家族树。

## 继承状态机

### 继承基准

继承查询按以下顺序解析基准人物 ID：

1. 当前仍然有效的国王 ID；
2. `KINGDOM_PRE_SUCCESSION_KING_ID` 保存的旧王 ID；
3. 若旧王实体已经从世界单位表移除，仍使用该 ID 查询持久化父子关系。

继承排序不依赖旧王对象存活。候选人与旧王通过父系 ID 链计算最近共同祖先及双方深度，排序依次为：

1. 旧王的父系直系后裔，代数越近越优先，同代取最年长者；
2. 兄弟及同代堂兄弟；
3. 较年轻旁支，代数越近越优先；
4. 年长旁支作为最终兜底。

资格仅排除已经担任国王的人，并继续排除死亡、非男性、奴隶和疯狂者。城主、将军、军队队长和封地持有人都可成为继承人。未成年仅保留现有父系直系兜底，不因官职失格。

### 只读查询与刷新

`HeirService` 分离两类操作：

- 只读查询只读取已登记继承人并验证资格，不清标记、不改 ID、不移动人物；高频城主、禁卫军、奴隶军和危机检查必须使用只读查询。
- 主动刷新才重新扫描父系候选、写入 `KINGDOM_HEIR_ID`/`KINGDOM_SUCCESSION_MODE`，并维护 `IS_HEIR` 标记。

在 `timer_new_king > 0` 的交接窗口中，查询只能返回死亡前准备好的登记人，绝不把缓存覆盖为空。

### 交接窗口保护

对启用 AW 谱系制度的国家，交接窗口内必须：

- 禁止转换共和国；
- 禁止执行原版 `checkKingdomChaos()`；
- 不把“暂时没有当前国王”计入将军叛乱危机；
- 保留禁卫军并等待新王接管；
- 保留已经准备好的继承人和继承模式。

显式的 `shattered_crown` 文化事件继续保留；模组现有将军叛乱、封地叛乱也不受影响。

## 王子城主与原版分裂

保留 `AW_CityLeaderPatch` 在全国范围寻找王室男性、调动王子填充空缺城主的行为。唯一受保护而不被调走的是当前登记的君主制或共和国继任者。城主补选只读取继任者 ID，不触发继承刷新。

`checkKingdomChaos()` 对夏人王国以及已启用 AW 谱系制度的夏化王国始终拦截。真正绝嗣应进入共和国选举，而不是让每个非首都城主创建独立国家。`checkShatteredCrownEvent()` 不拦截。

## 共和国选举

共和国不再随机抽取平民，而是对国内全部合格人物稳定排序：

```text
主分 = diplomacy + warfare + stewardship
并列 = level -> combat strength -> age -> actor ID
```

前四项降序，actor ID 升序，保证同一存档结果确定。候选人为本国、成年、存活、非奴隶、符合当前男性继承制度且未担任其他国家国王的人。贵族、平民、城主、将军、队长和封地持有人全部允许参选。

共和国建立流程：

1. 先完成候选排序；没有任何候选时不写入共和国状态。
2. 第一名登记为共和国首领并由原版 `setKing()` 即位。
3. 第二名写入 `KINGDOM_HEIR_ID`，继承模式写为 `REPUBLIC_ELECTIVE`。
4. 首领在位期间保持不变，其余候选中最高分者作为继任者。
5. 首领死亡后，登记继任者即位，共和国状态保持不变，再从剩余人物中重排下一位继任者。
6. 继任者死亡、离境或失格时重新计算，不把共和国误清为君主制。

共和国只有在父系君主候选彻底耗尽后建立；旧的“任意城主回退为世袭国王”路径不再阻止共和国。新建或分裂国家继承政策快照时，`ClassRepublic` 必须清洗为默认政体，除非该国家随后自行完成共和国选举。

## 天命门槛

普通天命宣称，包括 AI 自动宣称和“受命称帝”决议，都必须先完成 `aw_policy_mandate_rites`。成功的天命战争、叛军宣称和异族伪朝军事宣称继续走现有特殊来源，不受该普通政策门槛限制。

`aw_policy_mandate_rites` 提前为：

- `Column = 4`, `Row = 2`；
- `Cost = 90`；
- 仅要求 `aw_policy_ancestral_rites`；
- 仅要求 `aw_tech_rites_music`。

从政策依赖中移除 `aw_policy_early_law` 和 `aw_tech_granary_accounting`，并在 AI 社会政策顺序中把天命礼制移到祖先祭祀之后。历史人物不再绕过“受命称帝”决议的天命礼制要求。仍保留现有国力、爵位、法统核心和最强独立国要求，不增加固定世界年龄门槛。

## 禁卫军维护性能

禁卫军在王位交接期间原地保留。新王即位后复用现有禁卫军、刷新归属和名称，不执行解散再招募。只有共和国、天命叛军或国家真正灭亡时才解散。

所有解散路径统一为有完成状态的增量操作：

- 优先使用禁卫军军队和登记 roster 定位成员；
- 每次维护最多处理固定数量的禁卫；
- 未完成时保留军队、roster 和状态提示，下一次维护继续；
- 全部处理完成后才清空状态提示和游标；
- 单个禁卫的数据库、历史、图形及归档工作随批次摊开，避免同一帧集中执行。

纯规则测试覆盖交接保护、解散条件、批次上限和“只有完成后清提示”。

## 奴隶军填充性能

填充流程先复用一次军队构成统计，再按以下顺序工作：

1. 检查总容量、非奴隶干部上限和奴隶比例；
2. 有容量时优先挂接已经是战士的候选；
3. 只有通过容量/比例检查后才允许转职；
4. 每次最多转职 2 人；
5. 城市候选扫描使用持久游标和固定扫描上限；
6. 军队仍未填满且还有候选时，设置短间隔的错峰续跑，而不是一帧填完或等待完整维护周期。

为扫描、转职/装备和挂接分别增加 benchmark 标签。规则测试覆盖容量检查先于转职、现役战士优先、批次限制、游标推进与续跑判定。

## 氏族大树定位

大树的边和定位路径统一为严格父系：父节点只有在 `GetFatherId(child) == parent` 时才连接该男性子节点。

定位流程：

1. 使用登记始祖时，沿父亲链构造 `始祖 -> ... -> 目标` 路径。
2. 登记始祖缺失时，以目标能够追溯到的最早父系祖先作为根。
3. 目标为女性或因大树男性过滤不可显示时，定位到其最近可显示的父系祖先。
4. 目标无法连接到登记始祖时，仍停留在大树并定位根节点，不再静默重开小家族树。
5. 大树模式重新显示“展开在世分支”和“全部折叠”工具。

测试覆盖父系优先而不走母系、缺失始祖兜底、女性目标定位父亲、不可达目标留在大树，以及大树边必须是父子关系。

## 测试与验证

新增 `Tests/SuccessionGovernmentRuleTests`，集中验证继承状态、共和国排序、原版分裂拦截、政策状态继承和大树定位纯规则。现有测试项目分别扩充：

- `MandateRulerTitleRuleTests`：普通宣称政策门槛、特殊来源例外、政策节点位置和依赖；
- `GeneralRebellionRuleTests`：交接窗口不产生缺嗣危机；
- `RoyalGuardActionRuleTests`：交接保护和增量解散；
- `CityMaintenanceRuleTests`：奴隶军批次、容量先验、游标和续跑；
- `FamilyTreeRelationRules` 相关用例放入新测试项目。

关键回归场景必须明确建模：老王有多个儿子，世子及世子之子均死亡，仍存活的世子兄弟必须成为继承人，国家不得转为共和国。每项生产改动均先加入能稳定失败的规则测试，确认失败原因后再写最小实现。

最终验证包括全部规则测试项目、`dotnet build AncientWarfare3.csproj`、差异检查，以及逐条对照本设计的需求清单。

## 非目标

- 不改变模组的将军叛乱和封地叛乱系统。
- 不关闭 `shattered_crown` 显式文化事件。
- 不取消王子跨城市填充城主职位。
- 不引入固定 20 年世界年龄门槛。
- 不改变天命战争、叛军和异族伪朝的军事宣称例外。
