# 土匪落草、山寨扩张与义军首领设计

## 目标

增强土匪/义军的形成链路：城市饥荒或腐败会提高居民落草数量；山寨区域会随压力从 2x2 扩大到 3x3、4x4（4x4 封顶）；没有首领的归义军/义军可以从历史人物候选池召唤一名首领。

## 设计边界

- 复用现有城市年度工作流、忠诚度、饥荒判断、腐败服务和历史人物状态库。
- 不新增第二套腐败或饥荒数据源。
- 不改变已有土匪建国、剿匪、归义和战争结算流程，只补充候选、配额、尺寸和首领兜底。
- 旧存档没有山寨尺寸字段时按 2x2 读取并可继续升级。

## 落草配额

每个文明城市每年最多结算一次。候选人必须满足现有忠诚阈值，并且是成年普通居民；排除国王、继承人、city leader、官员、禁卫军、奴隶、船只、现有军队特殊身份和已属于土匪/义军的人。

基础转化人数按城市成年人口比例计算，并设置固定年度上限。饥荒和高腐败同时存在时倍率叠加；只有其中一项存在时只应用对应倍率。实际人数经过人口下限和随机扰动裁剪，至少为 1，不能使城市跌破最低居民数。转化后的人口进入现有土匪/山寨创建或补充流程，不直接复制城市人口。

## 山寨尺寸

新增 `BanditStrongholdSize`：`Small2x2`、`Medium3x3`、`Large4x4`。状态写入 `PeasantRebelBanditStrongholdState`，schema 递增并在反序列化时归一化。

- 新建山寨根据落草人数、腐败、饥荒和压力选择初始尺寸。
- 已有山寨只允许向上扩张，不允许缩小；年度压力结算达到下一档阈值时尝试扩张。
- 2x2、3x3、4x4 均必须由连续、可建墙的 TileZone 候选组成；找不到完整候选时保留当前尺寸。
- `FixedZoneKeys` 始终表示当前实际占用区域，旧存档的四个区域保持原样。
- 4x4 为硬上限，所有规则函数都拒绝更大尺寸。

## 义军历史首领

义军创建后和年度治理校验时，如果当前 king 不存在或已死亡，按以下顺序补首领：

1. 现有合法成年居民/城市首领，沿用现有 founder 评分。
2. 历史人物候选池中可用的人物：未生成，或已死亡且历史人物状态允许重新生成；遵守现有唯一性、顺序和持久化约束。
3. 没有候选时保留现有失败流程，不创建无首领义军或不改变国家归属。

历史人物生成必须通过 `HistoricalFigureService`/`FigureStateStore` 的预留、提交和死亡状态接口完成。成功后设置义军 king、`MANDATE_REBEL_LEADER`/相关义军身份、历史人物特质和历史记录；失败时回滚预留，避免占用候选。

## 数据流与容错

- 所有年度入口先检查副本/回放和世界状态，避免在不可变更阶段写入。
- 任何城市、TileZone、历史人物或国家对象失效时跳过本轮并保留现有状态。
- 尺寸扩张采用事务式计划：规划失败不修改现有墙、城市或 `FixedZoneKeys`。
- 历史人物候选生成失败只记录诊断，不影响原有义军和战争流程。

## 测试范围

- 饥荒、高腐败、两者叠加的落草人数与年度上限。
- 人口下限、候选排除和至少一人的规则。
- 2x2 -> 3x3 -> 4x4 升级、4x4 封顶、旧存档默认 2x2。
- 完整/不完整 TileZone 候选的尺寸规划。
- 普通居民优先、无居民时历史人物候选、无候选时失败回滚。
- 历史人物状态提交和失败回滚的规则覆盖。
