# AW3 正确性与原版 API 复用设计

## 目标与边界

本子项目修复已经由代码和日志确认的状态错误，并替换语义完全等价的手工查询。它不修改战争导演策略、兵员池口径、附庸递归军力、历史统计口径或新地图模式。

## 1. 逐鹿结算原子边界

### 已确认根因

`ZhuluWarSettlementService.Process` 当前先逐城调用 `City.joinAnotherKingdom`，再调用 `WarManager.endWar`。转走败方最后一城会使败方 `Kingdom` 失效，而该对象仍短暂存在于活动 `War` 的参与者列表中。原版成就检查随后遍历活动战争并调用失效国家的 `Kingdom.getSpecies()`，产生逐帧 `NullReferenceException`。AW3 的全局调度异常处理又重复暂停世界并写日志，形成日志风暴和严重掉帧。

### 设计

逐鹿结算必须成为有明确阶段的单一操作：

1. 快照战争、胜方、败方和待转移城市，并验证所有对象仍有效。
2. 阻止该战争接受新的逐鹿结算、占领或和谈操作。
3. 在败方最后一城转移前，使战争退出原版活动战争索引；结束战争使用已经快照的 `WarWinner`。
4. 通过原版 `City.joinAnotherKingdom` 转移允许割让的连续领土。
5. 写入 AW3 战果、编年史、战争目标和缓存清理。

如果在战争退出活动索引前失败，可以有界重试。如果已经结束战争但领土转移失败，必须继续完成同一个结算事务的恢复，不得重新创建战争，也不得把已销毁国家放回活动战争。

### 不变量

- 活动 `War` 的所有参与国家必须具有有效 `data`。
- 任何会销毁国家的最后城市转移，都不能发生在该国家仍属于活动战争时。
- 同一个逐鹿战争只能完成一次。

## 2. 世子本国归属不变量

### 已确认根因

`HeirService.StoreHeirSelection` 只在首次指定世子时调用一次召回。世子之后可能因婚姻、流亡、城市转移或国家兼并再次改变国籍，现有代码没有持续校验登记世子的归属。

### 设计

新增统一的登记世子归属协调服务，负责验证：

- `KINGDOM_HEIR_ID` 指向存活、有效的 Actor。
- 世子的 `kingdom` 必须等于登记国家。
- 世子的 `city` 必须是该国家的有效城市。

协调入口包括：

- 指定或重新选择世子之后。
- 国家月度权威更新。
- 存档恢复管线完成后。
- 婚姻迁移、流亡返回、城市转移和国家归属变化之后。

召回顺序为首都、人口最多的有效本国城市、任意有效本国城市。召回前解除外国军团成员关系、外国官职和不再成立的流亡状态，再使用原版 `Actor.joinCity` 同步城市与国家。召回失败时保留登记但加入有界重试；如果登记国家已经灭亡或无有效城市，则清理世子登记并重新选择，而不是把 Actor 传送到无效对象。

## 3. 族谱死亡状态一致性

### 已确认现象

族谱画像渲染会实时检查 `Actor.isAlive()`，tooltip 的“在世/卒年”则在节点 `Bind` 时从异步快照生成。因此 Actor 死亡后可能出现死人画像已经生效、旧 tooltip 仍显示在世的状态。

### 数据优先级

生死状态按以下优先级解析：

1. 实时 Actor 明确死亡或 `isRekt`。
2. 待提交 `ActorArchivePendingStore` 中的死亡快照。
3. 已提交 `ActorArchive` 的 `is_alive/death_time`。
4. 旧批量族谱快照。

任何明确死亡证据都必须覆盖旧快照中的“在世”。死亡归档成功提交后必须推进 `FamilyTreeProjectionRevision.LifeStatus`。当前打开的窗口检测版本变化后重取对应节点；tooltip 在悬停时读取当前节点投影，不永久捕获绑定时的生死字符串。

实施前先增加诊断测试，区分“归档提交没有推进版本”和“节点已经更新但 tooltip 闭包仍持有旧文本”。修复必须落在实际断点，不能仅把 tooltip 强制改为已故。

## 4. 原版 API 复用

允许直接替换：

- 空城重新归属：`City.setKingdom` 改为 `City.joinAnotherKingdom`。
- 活动战争判断：使用 `Kingdom.hasEnemies` 或 `WarManager.hasWars`。
- 活城市数量：使用 `Kingdom.countCities`。
- 语义为当前居民总量的查询：使用 `City.getPopulationPeople` 或 `Kingdom.getPopulationPeople`。
- Actor、City、Kingdom、Army 按 ID 恢复：只使用对应 `SystemManager.get(id)`。

必须保留：

- 兵员池、潜在动员量和城市独立军团口径。
- 附庸递归军力、战争参与方基线和历史记录口径。
- 需要访问具体 Actor 的候选、补员和学校索引扫描。

## 5. 故障隔离

`MapBox.Update` 或 AW3 权威阶段捕获异常时，记录限量诊断并禁用发生故障的 AW3 阶段。只有用户或联机权威明确发起暂停时才改变全局暂停状态。相同异常必须按签名限流，不能逐帧写入日志。

## 测试与验收

- 规则测试：逐鹿结算顺序、最后城市转移、重复结算和恢复状态。
- 集成模拟：败方一城与多城两种逐鹿战争，结算后活动战争参与者全部有效。
- 规则测试：外国世子、无首都、有备用城市、国家灭亡和存档恢复。
- 族谱测试：实时死亡、待写死亡、已提交死亡和旧快照四种组合；tooltip 与画像必须一致。
- 源码守卫：禁止在目标服务中重新加入全世界 ID 回退扫描和空城 `setKingdom`。
- 游戏内验证：逐鹿结算后运行一年；保持族谱窗口打开并杀死节点人物；迁移世子到外国后等待一个月并读档复验。
