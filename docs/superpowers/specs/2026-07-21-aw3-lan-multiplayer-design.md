# AW3 游戏内局域网联机子 Mod 设计

- 日期：2026-07-21
- 状态：设计已确认，待书面规格审阅
- 目标版本：首个可发布版本
- 玩家规模：2-4 人
- 适用范围：指定且完全一致的 WorldBox、Ancient Warfare 3 和联机子 Mod 版本

## 1. 文档关系

本文取代 `2026-07-19-lan-multiplayer-design.md` 的总体方案。旧方案以 Flutter 外部客户端为前提，与本轮“每名玩家都在自己的 WorldBox 内游玩”的要求冲突，不再作为实现依据。

`2026-07-19-lan-multiplayer-interfaces.md` 保留为 AW3 服务入口的调研目录，但不是稳定接口契约。实现前必须按当前代码重新核对其中的类、方法、参数和业务校验，联机子 Mod 也不直接依赖该文档提出的 publicized AW3 DLL 方案。

本文不使用 `aw3mp-client`，也不设计任何独立外部客户端。

## 2. 可行性结论

### 2.1 结论

该玩法在技术上可行，但属于高工作量、强版本绑定的功能。可行路线是“主机权威模拟 + 游戏内战略镜像客户端”，而不是让多台 WorldBox 各自模拟同一个世界。

首个必须通过的技术门是证明客户端镜像模式能够同时做到：

1. 加载主机世界快照并正常使用地图、相机和 AW3 界面。
2. 阻止客户端本地 AI、经济、战争和数据库写入成为游戏结果。
3. 从网络增量安全地更新国家、城市、军队等镜像对象。
4. 保留普通单位的可接受画面表现，而不要求其身份和站位与主机一致。

如果该技术门无法稳定通过，就不能继续承诺“所有玩家都在自己的 WorldBox 世界内看到同一局势”。此时只能退回游戏内战略地图投影或外部客户端，而这两种退路都不属于当前获批方案。

### 2.2 代码调研依据

- WorldBox 没有可复用的完整联机层，需要从会话、传输、同步和权限开始建设。
- `MapBox.Update()` 每帧调用 `Randy.nextSeed()`，随机调用分布在大量游戏脚本中；AI 更新、集合遍历和并发任务也无法保证各机器顺序相同。因此确定性锁步会迅速分歧。
- 新版 WorldBox 仍保留 `City.target_attack_city` 和 `City.target_attack_zone`，AW3 也已有 `AWArmyMarchService`、全局寻路桥和军队安全补丁，说明战略行军与城市攻击命令存在可复用落点。
- AW3 的国家政策、宣战、官场、行军和部署服务大多是 `internal`，例如 `KingdomPolicyService`、`DiplomaticWarDeclarationService`、`CourtService`、`AWArmyMarchService` 和 `ArmyDeploymentService`。独立子 Mod 需要稳定的公开桥接层。
- AW3 的历史、族谱、官场等状态不只存在于 `map.wbox`。`LineageArchiveManager` 使用 `aw3_lineage_archive.db`，并随游戏存档复制，因此加入快照和保存协调必须包含该数据库；不能只传地图文件。
- 四年前的弹幕 Mod 证明了“外部输入绑定国家并在游戏内执行命令”的概念，但它基于旧 NCMS API，并使用普通 `Queue<Action>` 接收动作。新实现只复用概念，网络线程必须使用 `ConcurrentQueue<NetworkCommand>`，Unity 对象只能由主线程访问。

## 3. 产品目标与非目标

### 3.1 目标

- 主机在已经打开的 WorldBox 世界中选择“开放局域网”。
- 其他玩家从自己的 WorldBox 内发现房间、加入主机世界并扮演一个国家。
- 每个国家最多由一名玩家独占控制；每名玩家同时只控制一个国家。
- 所有玩家可查看完整世界战略信息，但只能操作自己被分配的国家。
- 首个可发布版本覆盖基线版本 AW3 国家级窗口中所有面向普通玩家、非调试性质的写操作，而非只做宣战和移动军队的演示版。
- 无人国家继续由完整 AI 控制；玩家国家采用人机协同。
- 支持游戏中途加入、断线重连、持久席位以及主机管理。
- 保持局域网式使用方式，不建设中央账号、公共大厅、NAT 穿透或中继服务。

### 3.2 非目标

- 不做公网服务、官方匹配或中心服务器。
- 不做主机迁移。
- 不做确定性锁步、客户端规则预测或规则回滚。
- 不同步每个普通平民和普通士兵的身份、路径与精确位置。
- 不提供战争迷雾；首版是全地图公开信息。
- 不支持高于 `2x` 的世界速度。
- 不保证不同 WorldBox、AW3 或联机子 Mod 版本互通。
- 不把 God Power 或绕过业务门槛的调试能力开放给普通玩家。

## 4. 方案比较与选择

### 4.1 选定：主机权威战略镜像

主机是唯一真实模拟器和唯一存档写入者。客户端加载一致快照，进入镜像模式，通过权威事件和增量快照更新可见世界，并把玩家操作作为命令请求发给主机。

该方案支持热加入、断线恢复、权限校验和局部纠偏，也不要求 WorldBox 具备确定性。代价是需要建设镜像世界适配层、稳定网络 ID 和 AW3 公共桥接层。

### 4.2 否决：多端同步模拟

所有实例运行完整世界，只同步玩家指令，再通过哈希和快照纠偏。它在画面上最自然，但 WorldBox 的随机数、AI 时序和并发更新会快速产生差异。频繁纠偏最后会退化为不断重载世界，不能作为稳定方案。

### 4.3 否决：画面或外部状态流式共享

世界只在主机运行，其他玩家通过外部程序或远程画面操作。同步简单，但不满足玩家在自己的 WorldBox 内游玩的要求，也重复了已经被否决的外部客户端路线。

## 5. 总体架构

功能由 AW3 本体中的小型公共桥接层和独立 NeoModLoader 子 Mod `AW3.Multiplayer` 组成：

```text
Multiplayer UI
    -> AW3.Multiplayer session/replication layer
        -> public AW3 Multiplayer Bridge
            -> WorldBox objects + AW3 services + AW3 database
```

### 5.1 AW3 公共桥接层

桥接层是联机代码访问 AW3 的唯一入口，负责：

- 输出稳定、可序列化的国家、城市、战争、资源、宫廷、贵族和族谱读模型。
- 提供类型化命令及对应的 `Can*`/验证结果。
- 在主线程调用现有 AW3 服务执行操作。
- 发出联机所需的领域变化事件或脏分区标记。
- 暴露玩家国家所需的 AI 门控，不让子 Mod 用大量 Harmony 补丁猜测 AW3 内部行为。

桥接 DTO 不在线路上传输 C# 枚举对象或 Unity 引用，只使用协议定义的字符串类型 ID、数值 ID 和基础字段。首选真正的公共 facade；`InternalsVisibleTo` 只能作为迁移期间的受控手段，反射和 publicized AW3 DLL 不作为正式架构。

### 5.2 联机子 Mod 模块

- `LanDiscovery`：UDP 广播与房间发现。
- `SessionTransport`：TCP 连接、消息分帧、握手、校验、限流和重传请求。
- `AuthoritativeHost`：权威网络 Tick、命令排序、执行、事件日志和状态广播。
- `ReplicaClient`：快照加载、增量应用、插值和镜像一致性检查。
- `ReplicaWorldAdapter`：隔离客户端本地规则模拟，只保留渲染、地图交互和允许的表现行为。
- `EntityRegistry`：宿主对象与稳定网络 ID 的映射。
- `SeatManager`：玩家身份、国家席位、重连凭据和主机管理。
- `PauseController`：合并玩家、断线、同步和存档暂停原因。
- `SnapshotCoordinator`：一致快照、事件追赶和局部重同步。
- `SessionPersistence`：联机元数据的保存、校验和恢复。
- `MultiplayerUI`：房间、国家席位、主机管理和锚定国家操作窗口。

### 5.3 线程边界

UDP/TCP 收发、压缩和文件传输可在后台线程执行，但后台线程不得读取或修改 Unity/WorldBox/AW3 对象。收到的消息先转为纯数据命令并进入 `ConcurrentQueue<NetworkCommand>`；主机和客户端都在 Unity 主线程的固定阶段处理命令、构造权威读模型或应用镜像变更。

## 6. LAN 会话与 RTS 时序

### 6.1 传输

- UDP 广播只用于同一局域网内发现房间。
- TCP 长连接承载握手、快照文件、命令、权威事件和状态增量。
- 2-4 人且无战争迷雾时，不需要兴趣区域裁剪，也无需引入公网网络中间件。
- 协议消息至少携带协议版本、会话 ID、发送序号、权威 Tick、消息类型、关联命令 ID 和载荷长度。

### 6.2 权威 Tick

网络 Tick 独立于 Unity 渲染帧。客户端只发送“移动军队到城市”“任命某人为官”“启动某项政策”等命令意图，不发送自己修改后的对象状态。

主机按接收顺序和权威 Tick 排序，在主线程统一验证、执行并广播结果：

```text
client command
    -> session/seat/protocol validation
    -> ownership and expected-revision validation
    -> AW3 business validation
    -> main-thread execution
    -> command result + authoritative state event
```

离散变化立即可靠发送；活动军队位置和战斗状态约 5-10 Hz；人口、资源和经济汇总约 1-2 Hz 或按领域事件发送。具体频率由性能测试调整，协议不把频率写死。

客户端不做规则预测和回滚。按钮可立即显示等待主机确认，但不提前改变规则状态。军队画面可在最近两个权威位置之间插值。

游戏暂停时模拟 Tick 停止，网络 Tick、会话控制、重连、席位管理和快照传输继续工作。

## 7. 初始快照与增量同步

### 7.1 加入流程

1. 主机在当前世界点击“开放局域网”。
2. 客户端发现并选择房间，提交协议、WorldBox、AW3 和子 Mod 版本。
3. 主机校验版本与 Mod 清单；不一致则拒绝加入。
4. 主机在短暂系统暂停中建立一致快照屏障，记录快照序号 `N`。
5. 加入包包含 `map.wbox`、WorldBox 保存所需的配套状态、`aw3_lineage_archive.db` 和从主机元数据生成的只读 `client-session-manifest.json`。主机私有凭据摘要不发送给客户端。
6. 客户端加载为镜像世界，主机继续记录 `N+1` 之后的权威事件。
7. 客户端补放事件并通过分区摘要校验，追上当前 Tick 后才进入可操作状态。
8. 新玩家申请空闲国家；已有身份凭据的玩家优先恢复原席位。

热加入允许发生在游戏过程中。创建一致快照可造成短暂系统暂停，但不要求其他玩家退出世界。

### 7.2 同步层级

| 层级 | 内容 | 一致性要求 |
|---|---|---|
| 精确权威对象 | 国家、城市、战争、外交关系、军队、统帅、贵族、族谱人物、继承、政策、宫廷和资源 | 初始全量 + 可靠事件/增量 |
| 聚合对象 | 普通平民、普通士兵 | 按城市或军队同步数量与必要构成 |
| 本地表现 | 粒子、音效、普通单位具体站位和闲逛 | 各客户端可不同，不参与规则 |

普通平民按城市同步总数及必要的种族、职业、年龄段等统计。普通士兵按军队同步编制、兵力和必要构成。贵族、统帅及需要出现在族谱或履历中的具体人物仍独立同步。

客户端可以保留或生成数量接近的表现单位，但这些单位不能写入资源、人口、外交、战争或 AW3 数据库。军队的权威位置、目标、兵力和战斗结果来自主机，单兵站位不要求一致。

### 7.3 网络 ID 与纠偏

精确对象使用宿主分配的网络 ID，并附对象类型、宿主原生 ID 和世代号。客户端永远不在线路上传递本地对象引用。

状态按国家、城市、战争、军队、宫廷和族谱等领域分区计算版本与摘要。发现分歧时先重发单对象或单分区快照；关键索引无法恢复、事件日志断档或世界指纹不符时，执行完整重同步。重同步完成前客户端只读且不能提交国家命令。

## 8. 玩家、国家与 AI

### 8.1 席位规则

- 每名玩家一个国家，每个国家一个玩家，归属互斥。
- 首次选择空闲国家需要主机确认。
- 主机也是普通国家玩家，但额外拥有管理权。
- 主机可转让或释放席位、踢出玩家、切换玩家国家、临时接管断线国家。
- 无席位玩家只能留在大厅或观战，不能发送国家命令。
- 玩家国家灭亡后转为观战状态，世界继续运行；主机可将其分配到仍空闲的国家。

### 8.2 人机协同

玩家接管国家后，AI 继续处理人口、生产、建造、寻路、城市日常运转、自动继承维护及必要的空缺兜底。以下战略决策由玩家控制：

- 宣战、议和、外交提案和外交方向。
- 政策、科技、决议、天命和中央集权选择。
- 军队战略移动、攻击目标、征召和解散。
- 贵族、官职和可由玩家干预的继承操作。
- 藩国、附庸及其他已有玩家入口的国家管理动作。

AI 不得替玩家国家发起上述战略动作。系统性事件、自动历史记录、经济结算和规则强制结果仍正常运行。无人国家使用完整 AI；主机释放席位后恢复完整 AI。

## 9. 游戏内界面与操作

### 9.1 房间与大厅

- 局域网房间窗口：开放当前世界、发现房间、连接、显示版本错误和同步进度。
- 国家席位大厅：显示所有国家、控制玩家、连接状态、AI 状态和准备状态。
- 主机管理窗口：确认席位、转让、释放、踢出、临时接管及处理断线暂停。

### 9.2 锚定国家操作窗口

新增专用国家操作窗口，始终锚定玩家所属国家，不随地图当前选中对象变化。窗口复用 AW3 已有读模型与视觉模式，包含：

- 国家概览与资源。
- 城市、经济与政策。
- 军队、部署与战争。
- 外交关系。
- 宫廷、贵族与官职。
- 王室、继承与族谱。

玩家可以在地图或旧 AW3 窗口中查看其他国家的公开信息，但所有写入口都必须经过同一权限服务，不能通过旧窗口、快捷键或 God Power 绕过席位限制。

客户端镜像模式禁用原生 God Power、地形编辑、生成/删除单位、本地保存和其他会改变世界的入口，只保留相机、选中、查询与获准的国家命令。主机仍可使用明确标记为主机专属的世界管理能力；这些变化发生在权威世界中，并与其他主机状态一样进入同步和存档。

首个可发布版本覆盖基线版本 AW3 国家级窗口中所有面向普通玩家、非调试性质的写操作。旧接口目录列出的外交、政策、天命、藩国、官场、族谱和军队入口是覆盖清单的起点；实现计划必须基于当前代码生成新的命令清单和读模型清单。只有本文“非目标”明确排除的能力、纯只读功能、自动规则结算和 God Power/调试入口可以不成为玩家命令。

### 9.3 命令交互

每条命令包含唯一 ID、玩家会话、目标网络 ID、客户端已知对象版本和参数。高影响操作，如宣战、议和、废黜和继承干预，在客户端确认后才发送。

主机返回成功结果或稳定的原因代码，例如对象已死亡、资源不足、战争已结束、席位不符或对象版本过期。客户端收到成功结果后仍以权威状态事件更新界面，而不是根据本地猜测修改世界。

## 10. 时间控制、断线与身份

### 10.1 速度与暂停

- 联机模式只允许暂停、`0.25x`、`0.5x`、`1x` 和 `2x`。
- 禁止任何高于 `2x` 的速度。
- 任意玩家可以请求普通暂停。
- 只有主机可以恢复运行或切换速度。
- 原有速度按钮、快捷键和其他修改入口都必须通过联机权限检查。
- 暂停原因是集合而不是单一布尔值。断线、同步和存档暂停优先于普通玩家暂停，存在高优先级原因时主机也不能直接恢复模拟。

### 10.2 断线

任一已经取得席位的玩家断线后，主机立即添加全局断线暂停并保留该席位。原玩家凭持久身份和重连凭据恢复连接，通过增量追赶或完整重同步进入就绪状态后，解除对应断线暂停。

主机可以选择继续等待、踢出玩家、释放席位、转让席位或临时接管；这些操作解决席位后才允许解除断线暂停。多个玩家同时断线时，每个断线原因都必须分别解决。

主机断线或退出时首版直接结束会话。客户端不得选举新主机，也不得继续保存或运行一个伪权威世界。

### 10.3 身份

玩家在联机大厅手动输入玩家 ID，并由客户端在本地保存；ID 去除首尾空格后限制为 1-24 个可见字母、数字或 `_`、`-`、`.`，主机按大小写不敏感规则阻止两个等价 ID 同时连接。手动 ID 是公开身份名称而不是重连密钥。首次获得席位时，主机仍签发随机重连凭据；不能仅凭输入同一 ID 夺回国家。主机只保存凭据摘要，并以挑战响应方式验证重连，避免在线路上重复发送原始凭据。

## 11. 存档与会话元数据

每个世界的联机元数据保存在存档目录中的 `aw3-lan.json`，至少包含：

- 元数据格式版本、世界指纹和保存代次。
- 手动玩家 ID、凭据摘要和国家席位。
- 房间规则、速度上限和最后有效权威 Tick。
- 相关存档文件名、长度和内容摘要。

`aw3-lan.json` 是主机私有文件，不随加入快照原样下发。客户端只接收剔除凭据摘要和主机私有字段后的 `client-session-manifest.json`，其中保留世界指纹、协议版本、公开席位和快照校验信息。

玩家与国家的绑定随世界存档保留。主机重新开放该世界后，合法玩家可重新认领原国家，主机仍可解除或转让席位。

保存由主机协调：进入系统暂停，完成 WorldBox 保存，提交/备份 `aw3_lineage_archive.db`，再写入临时联机元数据和摘要。新一代文件全部通过校验后才更新当前代次；失败时恢复上一套完整代次。启动或开房时只接受文件摘要全部匹配的最新代次，必要时回退上一代，避免地图、AW3 数据和席位信息来自不同保存时刻。

客户端不能写权威存档。客户端镜像可使用临时缓存加快重连，但缓存不具有恢复世界的权力。

## 12. 错误处理与安全边界

- 版本或 Mod 清单不一致：握手阶段拒绝。
- 非席位、越权、字段非法或对象过期的命令：拒绝并返回原因代码。
- 重复命令：按命令 ID 幂等返回原结果，不重复执行。
- 消息乱序或缺口：按序号等待/请求补发；超过日志窗口则重同步。
- 快照损坏：按块校验并重传，未完成前不应用。
- 连续非法、超频或超大消息：限流并由主机断开连接。
- 局部状态分歧：重发对象或领域分区；无法修复时完整重同步。
- 保存失败：保留上一完整代次并保持系统暂停，向主机显示失败原因。
- 客户端应用镜像对象失败：停止该客户端命令权限，记录对象 ID、Tick 和异常后重同步，不能带着半更新世界继续操作。

该方案只面向受信任局域网，不声称抵御能够修改主机进程或读取本机凭据的攻击者。主机权威能阻止普通客户端直接篡改规则状态，但不是完整反作弊系统。

## 13. 性能原则

- 不逐帧扫描全世界对象；使用 AW3 事件、脏标记、索引和有界定时扫描。
- 活动军队使用快层，静止军队和国家数据使用慢层或事件。
- 普通平民和普通士兵只同步聚合，不产生逐人网络 ID。
- 快照构建在主线程只复制纯数据 DTO；序列化、压缩和发送转到后台线程。
- 对快照大小、事件日志长度、每 Tick 命令数和每连接发送队列设置硬上限。
- 网络、快照、镜像应用和 AW3 Bridge 都加入 profiler 计时与诊断计数。
- `2x` 是强制上限，不因主机性能更高而解除。

## 14. 实施里程碑与技术门

首个公开版本需要完整国家管理，但内部按以下顺序交付和验证：

1. **镜像模式技术验证**：两个 WorldBox 实例加载同一世界，客户端规则模拟和数据库写入被隔离，主机可远程改变一个国家、城市和军队并由客户端正确显示。这是继续投资的 go/no-go 门。
2. **AW3 公共桥接层**：建立当前代码版本的命令清单、读模型、业务校验和 AI 门控；单机内通过桥接执行完整操作。
3. **LAN 会话**：UDP 发现、TCP 握手、版本检查、身份、席位和主线程队列。
4. **快照与 RTS 同步核心**：一致快照、网络 ID、权威 Tick、事件日志、增量、摘要和重同步。
5. **战略世界覆盖**：国家、城市、资源、战争、军队和聚合人口。
6. **AW3 玩家操作全覆盖**：登记政策、外交、宫廷、贵族、继承、族谱、藩国以及基线国家级窗口中的其他非调试写入口。
7. **完整 UI 与恢复**：锚定国家窗口、主机管理、热加入、断线暂停、持久席位和保存恢复。
8. **长时间与故障加固**：性能、网络异常、损坏快照、非法命令和多实例测试。

任何里程碑都不能用未保护的反射、客户端直接改状态或跳过业务校验来伪造完成度。

## 15. 测试与验收

### 15.1 自动测试

- 协议消息序列化往返、长度限制和版本拒绝。
- 命令 ID 幂等、Tick 排序、乱序补发和事件日志截断。
- 席位所有权、主机权限、速度限制和暂停原因优先级。
- 网络 ID 世代、对象删除重建和过期版本拒绝。
- 分区增量应用、摘要差异、局部快照和完整重同步。
- 玩家身份挑战、凭据摘要和持久席位恢复。
- 保存代次、文件摘要、失败回滚和损坏代次恢复。
- AW3 Bridge 每个主要命令的业务校验、成功路径和稳定错误代码。
- 玩家国家 AI 门控以及无人国家完整 AI 回归。

### 15.2 多实例实机测试

- 2-4 个真实 WorldBox 实例在同一局域网加入同一房间。
- 重复抢占国家、越权操作、旧窗口绕过和客户端改速均被拒绝。
- 所有国家管理页签的命令由主机执行，并在各端得到一致权威结果。
- 运行中加入能够完成快照、事件追赶和席位分配。
- 已入席玩家断线会立即暂停；原身份能恢复；主机释放或接管也能正确解除暂停。
- 保存、关闭并重新开放世界后，合法玩家能重新认领原国家。
- 主机退出后客户端明确结束会话，不能继续模拟或保存。
- 人为注入延迟、重复、断包、损坏快照、非法命令和应用失败，不导致主机崩溃或存档损坏。

### 15.3 发布验收线

- 在 `2x`、2-4 名玩家和代表性大世界下连续运行至少两小时。
- 国家、城市、战争、军队、贵族、族谱和资源分区不存在无法自动修复的分歧。
- 普通人口和军队兵力聚合与主机保持一致，允许普通单位具体站位不同。
- 主机的模拟、快照和网络开销保持在可玩范围，且不会因连接玩家数增加而逐帧全图扫描。
- 诊断日志能用会话 ID、权威 Tick、命令 ID 和网络对象 ID 定位一次失败操作或同步分歧。

## 16. 最终决策摘要

- 架构：主机权威、RTS 命令流与增量快照、客户端游戏内战略镜像。
- 客户端：每名玩家都运行 WorldBox + AW3 + 联机子 Mod。
- 人数：2-4 人。
- 信息：全地图公开，无战争迷雾。
- 归属：一人一国、一国一人，主机拥有席位管理权。
- 操作：首发覆盖基线 AW3 国家级窗口中全部面向普通玩家的非调试写操作；专用窗口固定锚定玩家国家。
- AI：人口、生产和城市日常继续；国家战略决策由玩家掌握。
- 同步：国家、城市、战争、军队、贵族、族谱和资源精确；普通平民和士兵聚合。
- 时间：任意玩家可暂停，只有主机可恢复和改速；最高 `2x`。
- 加入：支持热加入和凭持久身份重连。
- 断线：任何已入席玩家断线都会全局暂停，直到重连或主机处置席位。
- 存档：席位随世界保存；主机是唯一权威存档写入者。
- 明确不做：外部客户端、确定性锁步、公网服务和主机迁移。
