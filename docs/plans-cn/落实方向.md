## §0 全局校正与底座事实（先读）

### 0.1 对设计优化.md 的六条硬校正

| # | 设计优化.md 的假设 | 实测真相 | 影响 |
|---|---|---|---|
| **1** | "`CourtService` 只有国家级快照，缺个体官员闭环" | **已存在** `OfficialCareerService`（任职账本）+ `GeneralService`（武轨 merit/loyalty/ambition 生产级） | §A 净新增只是**品级+考课+叙阶**，merit 骨架已在 |
| **2** | "扩 `CourtOfficerTableItem` 加字段" | `CourtOfficer` 是**追加式账本**（一 actor 多行 + 乐观并发精确比对），塞 mutable 字段会冲突 | §A 必须**新建 `OfficialCareerStateTableItem`**（模板 = `GeneralStateTableItem` 一 actor 一行） |
| **3** | "义军占领速度 ×8"（现有事实） | **不存在 ×8**。占领加速是 `CityOccupationAccelerationService`，bonus ≈ 1.55/0.45，对所有"有夺城目标+无守军"生效，非义军专属 | §C.1 相位机改为"复用现成加速器、按相位调系数" |
| **4** | 祭祀"花皇权"；集权/官制"挂 `KingdomTrait` buff" | **皇权是派生标量不可花**；**AW3.0 从不使用 KingdomTrait**（引擎支持但零先例，stat-key 兼容性未知） | §C 改为**花金/政治点**；集权/官制用 **`kingdom.data` 标量 + 命令式效果**，KingdomTrait 仅作可选验证路线 |
| **5** | 朝贡"复用城市税收/缴税路径转移金币" | **AW3.0 全程无金币/国库账户**。`Kingdom` 无 gold 字段；"税"是抽象 `CityEconomyStateTableItem.TAX_VALUE`，从不汇总更不转移。唯一真 get/set 的"货币"是 `LineageKeys.POLICY_POINTS` | §D 朝贡贡赋落在**抽象政点**（或原版城市 `"gold"` 资源堆 / 国王 `loot`），不是金币账户 |
| **6** | 虚封爵"挂 `LineageService`（家族威望）" | **家族威望 `dynasty_prestige` 是 `MandateService` 的国家级字段**，不在 LineageService，无个体载体 | §E 个体虚封需新建 `noble_rank`（actor.data）+ `EnfeoffmentTableItem`，威望个体化需产品决策 |

> 另有若干"设计假设其实已埋好挂点"的正面发现：`MandateRulerTitleRules.SelectTempleName` **已有未使用的 `refounder` 形参**（世祖只差一行 + 数据线）；共和政体已是"非血统继承"现成范式（§F）；`GeneralRebellionService.TryPalaceCoup` = `setKing` 已是现成篡位原语（§C.4）。

### 0.2 可复用底座（四路一致确认）

- **年度心跳分发器**：原版 `Kingdom.updateAge()`（几乎空）被 `patch\AW_KingdomPolicyPatch.cs` 的 Harmony **Postfix** 接管，按固定顺序调用各子系统的 `OnKingdomYear(Kingdom)`。
  - 恒跑块（每年）：`KingdomPolicyService.OnKingdomYear`（`:65`）→ 内含 `CourtService.OnKingdomYear`（`:72`，内部 5 年门控）、`MandateService.OnKingdomYear`（`:99`）、`CityEconomyService.OnKingdomYear`。
  - 错峰块：`GeneralService`/`VassalService` 走 `KingdomYearSchedulerRules.ShouldRunHeavySystem(year,id,modulo,slot)`（约 2~4 年一跑）。
  - **新系统照此约定加 `OnKingdomYear` 即可，无需新 Harmony patch。**
- **持久化两条路**：(a) `kingdom.data`/`actor.data` 的 `BaseSystemData.get/set`（int/long/float/bool/string，`aw_` 前缀键集中在 `LineageKeys.cs`）——随存档走、零 DB 开销、热读用；(b) `[TableDef]` SQLite 表——`LineageArchiveManager` 反射建表，`SQLiteHelper.AddMissingColumns`（`:270`）**自动为老档补列**，权威源 + 可聚合/UI。`GeneralService` 范式 = **两者都写，读时取 `Math.Max`**。
- **决议框架**：`KingdomPolicyDefs._all[]`（`PolicyNodeKind {Social,Tech,Decision}`）+ `KingdomPolicyService.ApplyEffect` switch（`:1143`）+ 门控 `IsSpecialRequirementMet`（`:1304`）。新决议 = 加一个 `KingdomPolicyDef` + 一个 case（+可选门控）。已有先例：`aw_decision_claim_mandate`→`MandateService.TryDeclareMandate`。
- **战争类型**：`content\DiplomacyContent.cs` `AddWarType(...)` → `AssetManager.war_types_library`；CB 门在 `WarDecisionService.HasIntrinsicCasusBelli`（`:285` switch）；胜负结算 `VassalService.OnWarEnded`（`:424`）。
- **外交好感**：原版 `AssetManager.opinion_library`（`OpinionAsset{translation_key, calc}`，**实时无状态**求和），AW3.0 现只读不写，注册新 `OpinionAsset` 是干净的非夺舍挂点（§G）。
- **死亡/继承钩子**：`AW_ActorDeathPatch`（原版 `Actor.die`，`isKing()`→`ChronicleEvents.OnKingDied`）；`AW_HeirPatch`（原版 `Kingdom.setKing` Postfix →`YearNameService.OnNewKing` 换年号 + `LineageService.OnKingFoundBranch` + `HeirService`）。

### 0.3 性能红线（贯穿全文）

所有新逻辑挂**年度低频 tick + 缓存快照**；**绝不**在热路径（尤其 `OpinionAsset.calc`、占领判定、每 actor 循环）里跑递归或 SQL。热读只读 `kingdom.data`/`actor.data` 缓存字段。新逻辑接 `UpdateAgeBenchmark.Begin/End` 计时（`CourtService` 已全程如此）。

## §A 官僚制个体生涯

**设计对应**：§1（品级/考课/叙阶/merit/三品软上限）+ §13.5（铨选/差遣/宦官）。**可行性总判：高**（骨架就绪，纯增量 Service + 一张新表）。

### A.1 现状实测

- `CourtService.OnKingdomYear(Kingdom)`（`core\court\CourtService.cs:164`）**每 5 年**（`CourtRules.DefaultRefreshIntervalYears=5`）刷新朝廷：`BuildYearRoster`（`getUnits()` 快照）→ `ValidateOfficers` → `EnsureMinimumCourt`（`FillCentralOffice`→`FindBestCandidate`→`ScoreCandidate`→`SetOfficer`）→ `RecalculateFactionCache` → `RefreshCityBureaus` → `UpsertCourtSnapshot`。
- **官员双写**：运行时投影挂 `actor.data`（`COURT_KINGDOM_ID/LAYER/OFFICE_ID/SCHOOL/CITY_ID`）；持久账本 `CourtOfficer` 表（`OfficialCareerService.Appoint/End`）。**唯一汇流点 = `ApplyCommittedOfficerProjection`**（本地官经 `SetOfficer:431`，客卿经 `SchoolGuestOfficeService` 异步 pending，都汇于此）。
- **武轨 merit 已生产级**：`GeneralService` + `GeneralStateTableItem`（`merit_score/loyalty_score/ambition_score/troop_power_snapshot`，一 actor 一行主键 `ACTOR_ID`），由 `OnWarEnded`（战功 10~16）/`OnCityTransferred` 驱动，`GetMerit` 取 actor.data 与 DB 的 `Math.Max`。
- **学派 7 维加权 policy AI 已闭环**：`CourtDirectionService.BuildContributions`（`:52`）给 king `8f`/heir `5f`/**中央官 `4f`**/大将 `3f`/城主 `5f` 权重 → 经 `CourtAIRules`/`WarDecisionAI:230` 影响科技投点与开战倾向。
- ⚠️ **无存储的人口增长率**：全代码只有瞬时 `city.getPopulationPeople()`；`CityEconomyStateTableItem` 有逐年 `TAX_VALUE/manpower/unrest_risk/food_stability`（这是文治考绩的真实数据源）。

### A.2 落实方向

**数据落点（校正 2）**：新建 `Code\core\db\OfficialCareerStateTableItem.cs`（模板 = `GeneralStateTableItem`，主键 `actor_id`）：
```csharp
[TableDef("OfficialCareerState")]
public class OfficialCareerStateTableItem : AbstractTableItem<OfficialCareerStateTableItem> {
    [TableItemDef(pIsPrimary:true)] public long actor_id;
    public long kingdom_id = -1;
    [TableItemDef(pDefaultValue:"1")] public int rank = 1;   // 1..18 (九品×上下)
    public int track = 0;              // 0文散官 / 1武勋官
    public string office_id = "";      // 现任实职快照
    public float merit = 0;  public int merit_cap = 1;
    public int term_end_year = -1;     // 任期心跳
    public int last_kaoke = 2;         // 0上..4下
    public int kaoke_mod_until = -1;   // 考绩4年修正到期
    public int seniority = 0;          public int last_pop_snapshot = -1; // 自存人口做增减考
    public double updated_time = -1;
}
```
热读镜像挂 `actor.data`（`LineageKeys` 加 `OFFICER_RANK` 等），仿 `GENERAL_MERIT` 的 `Math.Max` 双读。

**考课/叙阶加入位置**：`CourtService.OnKingdomYear` 内 `RecalculateFactionCache` 之前新增 `EvaluateOfficerCareers(pKingdom, yearRoster, tier)`（roster 已在手，接 benchmark）——只处理 `term_end_year<=year` 的官员（**任期心跳天然限流**，性能友好）。

**考绩数据源（校正后）**：
- 武功：`GeneralService.GetMerit(actor)` 直接可用。
- 文治：查官员驻城（`COURT_CITY_ID`）的 `CityEconomyStateTableItem`（`TAX_VALUE`↑/`unrest_risk`↓/`food_stability`），比原始人口更实且已入库。
- 户口增减考：因无存储增长率，用 `last_pop_snapshot` 自存上年人口做年际差，或改用 `CityEconomyState.manpower` 差。
- 主属性喂 §1.5 校核阈值（10/13/17/20/28）：`actor.stats["intelligence"|"stewardship"|"warfare"|"diplomacy"]`（`CourtService.SafeStat` 已在用）。

**品级接影响力（落实 §1.1）**：把 `CourtDirectionService.BuildContributions` 中央官那行的常数 `4f`（`:82`）与 `CourtInfluenceRules.InfluenceWeight` 改为按 `rank` 缩放（`4f * rankMult(rank)`）——**一处改动即实现"高阶官左右国策"**。

**入仕起阶（§1.3）**：挂在唯一汇流点 `ApplyCommittedOfficerProjection`（本地官+客卿都过此）——名士出仕（`SchoolGuestOfficeService`）天然接上官阶轨。

**§13.5 铨选（官资↔州格）**：加进现成实职评分器 `CourtService.ScoreCandidate`（`:324`）——读候选 `rank`（官资）vs 目标官职品级（州格，用现成 `CourtDirectionService.OfficeRank` 的 10/20/30 分档），差值给奖惩。⚠️ `ScoreCandidate` 在 `CandidateLimit*8` 循环内，rank 走 actor.data 热读，勿在此查 DB。

**§13.5 差遣/宦官轨**：差遣加 `assignment` 字段对辖区施加政策组合（接 `CityEconomyService`）；宦官轨用预留常量 `CourtOfficeLayer`（已有 `City/Censor` 位，加 `Eunuch`），互斥判定挂 `CourtAffiliationResolver.CanServe`。**这两条非纯数据（要新增对城市/封臣的作用逻辑），排在 rank/考课骨架之后。**

### A.3 风险与开放问题
- (R1) 双写一致性：新表 + actor.data 须在 `ApplyCommittedOfficerProjection`/`ClearOfficer` 同步（仿 GeneralService"下轮自愈"）。
- (R2) 人口增长率无存储 → 必须自建快照或用 `CityEconomyState` 年际差（先定）。
- (R3) 文武 merit 口径：`CourtInfluenceRules.InfluenceWeight`/`CourtDirectionService` 目前只吃 `GeneralService.GetMerit`，文官 merit 要接进同一读取，否则不影响国策。
- (OQ) 客卿跨国任职的 rank 归属（母国 vs host）；三品软上限名额存哪（kingdom.data 计数）+ "制授"决议是否纳入 `KingdomPolicyDefs`。

## §B 名号系统

## §C 天命升级

**设计对应**：§3 祭祀、§4 官制法律链、§13.1 治乱循环、§13.2 分级皇权、§13.4 权臣。**这是全项目机制升级的核心。**

### C.0 现状实测（关键）
- 天命**全局单例**：SQLite `MandateState` 只一行；双写 `kingdom.data`(`MANDATE_VALUE/AUTHORITY/PRESTIGE`)。
- `MandateService.OnKingdomYear`(`:99`) 每年：`CalculateYearlyDelta`(`:963`，一堆 ±项：有敌−2/无敌+1/核心控制/附庸忠诚/国王特质/世界纪元 age_ash−12…)→ clamp → `CrisisLevel`(`:1534`：collapse/lost/shaken/stable/golden，**纯派生字符串、无记忆**)→ `UpdateState` → `≤−30` 触发 `CollapseMandate`。
- ⚠️ 皇权 `CalculateAuthority`(`:997`) 是派生标量（不可花）；王朝威望单调不减。
- 称帝 `CanDeclareMandate`(`:223`)：礼制国策+非附庸+入夏级别+领土(城≥4或爵≥王)+核心≥0.65+最强独立。
- 义军 `MandateRebelService.OnMandateCollapse`(`:101`)：崩解挑≤3 核心城建义军，`MobilizeRebelForces`+`TryClaimMandate`（核心≥0.65 称帝复朝）。⚠️ **无 ×8**——占领加速是通用 `CityOccupationAccelerationService`(bonus 1.55/0.45)。
- 决议两套：轻量 `MandateDecisionService`（边防/祭天/改元单槽）；强大 `KingdomPolicyDefs`+`ApplyEffect`(`:1143`)（§3/§13.2/§4 应挂这里）。
- ⚠️ **KingdomTrait 引擎可用但 AW3.0 零使用** → 集权/官制 buff 走 `kingdom.data` 标量 + 命令式，勿依赖 KingdomTrait。

### C.1 ★ 治乱循环阶段机（§13.1，最高价值）
把纯派生的 `crisis_level` 升级为**有记忆的相位机**（增量改造，非重写）。
- **枚举+存储**：新 `MandatePhaseRules.cs` + `enum MandatePhase{Golden,Decline,Chaos,Renewal}`；扩 `MandateStateTableItem` 加列 `mandate_phase/phase_since_year/catalyst_score`（单例、DB 权威）+ `MandateReport` 加字段。
- **评估点**：`OnKingdomYear` 算完 `nextValue` 后、`UpdateState` 前插一行 `phase = MandatePhaseRules.Evaluate(...)`（唯一评估点、每年一次、全局单例）。

## §D 朝贡与附庸契约

**设计对应**：§7（朝贡结算 P0）+ §13.3（朝贡国/叩关）。**可行性：高**。

### D.1 现状实测
- ⚠️ **AW3.0 无金币账户**（校正 5）。原版缴税走 actor `loot`（`BehActorGiveTax`：市民→城主→国王 `addLoot`）；AW3.0 的"税"是抽象 `CityEconomyStateTableItem.TAX_VALUE`（`CityEconomyService.OnKingdomYear` UPSERT，从不汇总/转移）。唯一真 get/set 货币 = `LineageKeys.POLICY_POINTS`。

### D.2 落实

**朝贡结算（激活三字段）** —— 新 `VassalService.SettleTribute(suzerain)`：
