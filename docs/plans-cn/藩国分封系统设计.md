## 1. 定位：藩国是什么，不是什么

**藩国** = 皇帝把一片非首都城市（通常在边疆）划给宗室皇子，让他以**藩王**身份世代镇守。它在"主权强度"轴上介于郡县和附庸之间：

| 国家层 | 法理归属 | 独立外交/宣战 | 独立天命 | 地图色 | 治理者 | 世袭 | 可否作乱 |
|---|---|---|---|---|---|---|---|
| **郡县**（中央直辖） | 中央 | 无 | 共中央 | 中央色 | 流官太守 | 否 | 否 |
| **藩国**（本系统） | **中央**（法理核心） | **无**（共中央外交） | **共中央** | **中央色**（藩国地图模式显深浅） | **宗室藩王** | **是**（宗室支世袭） | **是**（靖难/削藩逼反） |
| **附庸**（VassalService） | 藩属自身 | 半独立 | **独立** | 独立色（专属地图模式显宗主色） | 附庸国王 | 是 | 是（独立战） |
| **独立国** | 自身 | 完全 | 独立 | 独立色 | 国王 | 是 | — |

**藩国的四条铁律**（区别于附庸的关键）：
1. **法理归中央**：藩国的城在法理/天命上**始终属于帝国**（哪怕藩王实控、甚至独立出去，法理仍在中央→这就是削藩的正当性来源）。
2. **共天命、共外交、共色**：藩国不单独算天命值、不能自己对外宣战、不显独立颜色——它是帝国的一部分。
3. **半自治**：藩王有**实在的地方权力**（镇军、留税、属官、募兵），但都是**行政级**，不是主权级。
4. **可作乱**：藩王有兵有地有宗室合法性，削藩逼反或中央暗弱时可"靖难"，作乱**成功=同朝更替（入主中央）**，失败=除藩。这是藩国的戏剧内核，也是"屏藩王室"的双刃。

**历史母题**：西汉郡国并行→七国之乱→推恩令；西晋分封诸王→八王之乱；明初分封塞王→靖难之役。藩国系统就是要把"分封屏藩 vs 尾大不掉"这对两千年张力做成可玩循环。

## 2. 核心架构决策

### 2.1 引擎约束（实测）
原版 WorldBox **没有任何"子王国/省/藩"中间层**：一座城 `City.kingdom` 解析到**唯一一个** `Kingdom`（扁平），`Kingdom.cities` 就是一张平表。AW3.0 已用两种数据层叠加补足：
- **封地 FiefService**：城**留在母国**（`city.kingdom` 不变），只在 `FiefGrantTableItem` 打标签 + actor 键 `GENERAL_FIEF_CITY_ID` + 把大将钉成城太守(`setLeader`)与城军队长。**城行为完全同母国**（AI 走 `city.kingdom`）——零自治，纯标签。
- **附庸 VassalService**：城拆成**独立影子 Kingdom**，仅在专属地图模式渲染成宗主色，需主动"重新粘合"（战争拖拽/独立吸收）。真自治，但代价大。

> ⚠️ **引擎无钩子**能给"留母国的城"独立的战/外交立场。所以：留母国=法理统一但零行为自治；影子国=有自治但要主动粘回一体。

### 2.2 三方案权衡

| 方案 | 平时表达 | 自治来源 | 问题 |
|---|---|---|---|
| **甲 影子王国** | 藩国=被压制的独立 Kingdom（藩王当王、城转入） | 引擎原生 | 本质**还是主权国**，要两级同步天命/色/外交，比附庸更"像国家"——**违背"不能用附庸套"**；且要 patch 基础政治图上色才能显母国色（比附庸更重） |
| **乙 纯数据层** | 城留母国，藩国只是分组标签 | 全靠 AW3.0 服务模拟 | 语义准（行政非主权）、零天命/色同步，但**平时零行为自治**（城行为=母国） |
| **丙 数据层 + 法理核心 + 作乱裂变**（推荐） | 平时=乙；作乱时城 `makeOwnKingdom` 裂变成叛军 | 平时靠服务模拟半自治，战时靠裂变获真主权 | 需两态切换，但每一步都有现成件 |

### 2.3 推荐：方案丙（数据层 + 法理核心 + 作乱裂变）

**这是唯一同时满足"行政非主权"语义与"藩王作乱"玩法、且完全贴合 AW3.0 架构的方案。** 三根支柱全部已有现成件：

1. **平时 = 封地式数据层**（复用 FiefService 骨架）：藩国城**留在帝国 Kingdom**（`city.kingdom` = 帝国）→ 天命/法理/颜色/外交/城市 AI **天然全归中央、零同步**（这正是"行政区划不是实权国"的精确表达）。藩王的半自治**全部由 AW3.0 服务层模拟**（镇军/留税/属官/募兵，见 §5）——与官场/学派/天命这些"数据层叠在引擎对象上"的 AW3.0 既有范式完全一致。

2. **城标记为帝国法理核心**（复用 MandateCoreCity 层）：**这是本设计最关键的现成件**。AW3.0 的 `MandateService.IsLegalCoreCity(city)` / `MandateCoreCityTableItem` **已经把"法理归属"与实际 `city.kingdom` 解耦**——一座城即便被藩王实控甚至裂土独立，`IsLegalCoreCity` 仍判其属帝国，`CountControlledCoreCities` 已用"owner==帝国 || 根宗主==帝国"算实控率，`NonCoreLoyaltyRules` 已对"占了法理不属你的城"扣忠诚。**藩国城 = 帝国法理核心**，于是"平时法理统一、作乱后法理仍在帝国→削藩/平叛有正当性、藩王入主=继承本朝法理"全部现成表达。

3. **作乱 = makeOwnKingdom 裂变**（复用 GeneralRebellionService 封地独立链）：削藩逼反/中央暗弱时，藩国城 `makeOwnKingdom(藩王, pRebellion:true)` 裂变成真·叛军 Kingdom（藩王当王），多城并入用 `joinAnotherKingdom(..., pRebellion:true)`——**与现有封地独立战 `WAR_FIEF_INDEPENDENCE`、天命义军 `WAR_TIANMING_REBEL` 完全同型**。但因城仍是帝国**法理核心**，这是"宗室内战争法理"，胜负结算区别于义军/独立（见 §8）。

**一句话架构**：藩国平时是"封地 Plus"（宗室 + 城群 + 世袭 + 半自治服务层），战时复用现成裂变链变叛军，法理层保证它始终"名义上是帝国的"。

## 3. 数据结构

### 3.1 新表 `FeudatoryTableItem`（藩国主记录）
模板参照 `FiefGrantTableItem`，但记城群、藩王、宗室支、自治与状态：
```csharp
[TableDef("Feudatory")]
public class FeudatoryTableItem : AbstractTableItem<FeudatoryTableItem> {
    [TableItemDef(pIsPrimary:true)] public long feudatory_id;
    public long empire_kingdom_id;      // 所属帝国（母国）
    public long prince_actor_id;        // 藩王（宗室）
    public string prince_name = "";
    public long shi_branch_id = -1;     // 藩王所属宗室支（世袭锚，LineageService 氏支）
    public long seat_city_id = -1;      // 藩都（藩王坐镇的城，= 藩王的 leader 城）
    public int rank = 0;                // 0=郡王 1=亲王（影响辖城上限/兵额/自治上限）
    public int autonomy = 40;           // 自治度 0..100（见 §6）
    public int loyalty = 60;            // 藩王对中央忠诚 0..100（削藩/作乱判据）
    public long garrison_army_id = -1;  // 藩国镇军（特殊军队，见 §11）
    public int established_year = -1;
    public int status = 0;              // 0在藩 1削藩中 2作乱 3独立 4除国
    public double start_time = -1; public double end_time = -1;
    public string end_reason = "";
}
```

### 3.2 辖城副表 `FeudatoryCityTableItem`（一藩多城，一城一行）
```csharp
[TableDef("FeudatoryCity")]
public class FeudatoryCityTableItem : AbstractTableItem<FeudatoryCityTableItem> {
    [TableItemDef(pIsPrimary:true)] public long entry_id;
    public long feudatory_id; public long city_id; public int active = 1;
}
```
> 辖城本身仍 `city.kingdom == empire`。此表只是**分组标签**（相当于 FiefService 的"城→大将"关系，扩成"城→藩国"）。

### 3.3 运行时热读键（`LineageKeys` 新增）
- actor 键：`FEUDATORY_ID`（藩王身份，仿 `GENERAL_FIEF_CITY_ID`）、`TRAIT_FANWANG="fanwang"`（藩王 trait，类比 `TRAIT_ZHUHOU`）。
- city 键：`FEUDATORY_ID`（该城属哪个藩，热读免查表）。
- kingdom 键：无（藩国不是 Kingdom，帝国侧不需专属键；藩国集合按 `empire_kingdom_id` 查表 + 缓存）。

### 3.4 新服务 `FeudatoryService`（挂 `OnKingdomYear`）
职责：分封/就藩、年度维护（镇军刷新/留税结算/忠诚演化/削藩逼反判定）、削藩、作乱裂变、袭藩/推恩/除国、法理核心登记、查询缓存。**低频年度 tick + 缓存快照**（与 FiefService/VassalService 同节律，走 `KingdomYearSchedulerRules.ShouldRunHeavySystem` 错峰）。

## 4. 分封流程（就藩）

### 4.1 谁能封 / 封谁 / 封什么
- **谁能封**：帝国级、天命国（或已研"分封研究"国策）的皇帝。门槛可复用 `设计优化.md §5` 的分封国策线（`aw_policy_base_enfeoffment`/`border_enfeoffment`）。
- **封谁**：宗室**皇子/王子**——遍历 `emperor.getChildren(false)`，取 `NOBLE_DISTANCE<=1`（直系）且带 `TRAIT_GUIZU` 的成年男丁；排除嗣君（`HeirService.IsCurrentHeir`，太子留京继统）。宗室枚举/五服距离/嗣君去重全现成。
- **封什么**：一片**非首都**城（藩都 + 若干辖城），优先**边疆城**（`CityBehBorderSteal` 式边界判定 或 距首都远）——呼应"镇守一方/御边"。藩都不能是帝国首都；辖城须 `city.kingdom == empire` 且非他藩。评分可仿 `FiefService.ScoreCity`（但**反过来避开法理核心首都圈**，选外围）。

### 4.2 大封诸王（一次性仪式）
接 `设计优化.md §5.3` 大封宗室决议：皇帝即位/统一后发"大封诸王"决议（花皇权/威望），遍历成年皇子按序封藩：嫡长留京（嗣君）、余子各授一藩（边疆优先）。写天命史高光（§12 骈体文案："封皇子 X 为 Y 王，就藩 Z，屏藩王室"）。

### 4.3 就藩动作（`FeudatoryService.Establish`）
1. 建 `FeudatoryTableItem` + `FeudatoryCityTableItem` 行；藩王打 `TRAIT_FANWANG` + `FEUDATORY_ID` 键。
2. **藩王坐镇藩都**：`藩都.setLeader(藩王, pNew:true)`（引擎原生：太守≠王即可，藩王不是帝国王故可当 leader）。藩王 `joinCity(藩都)`。
3. **登记法理核心**：辖城全部 `MandateService.OnKingdomCoreCreated(empire, city, "feudatory")`（或直接标 `IsLegalCoreCity`）——藩国城成帝国法理核心。
4. **组藩国镇军**：`AWArmyService.EnsureArmy(empire, 藩都, 藩王, "feudatory_garrison", 名, pDetached:false)`——军钉在藩都、队长=藩王。
5. 授个体虚封爵（接 `设计优化.md §5.1` `noble_rank`：亲王/郡王）。
6. 写史（就藩），刷新缓存。

## 5. 藩王的权与限

> 半自治的精髓：**藩王有实在的地方权力，但全是行政级、无一是主权级**。因为城在引擎里仍属帝国（零原生自治），所有"权"都由 AW3.0 服务模拟；所有"限"则是引擎天然（城行为=帝国）。

### 5.1 藩王有的（行政权，服务模拟）

| 权力 | 实现 | 复用 |
|---|---|---|
| **镇守一方（镇军）** | 藩国镇军（特殊军队，队长=藩王，钉藩都），御边/平叛/听征调 | `AWArmyService.EnsureArmy` 新角色 `feudatory_garrison`（钉城 attached；若藩王随军出征则 detached + 仿禁卫军跟随 AI） |
| **留税（财政自治）** | 藩国城的抽象税**留存一部分**给藩王（养镇军/建藩都），少上缴中央 | 仿 `FiefMilitaryRules.ActiveFiefTaxMultiplier=0.88`；接 `落实方向.md §D` 抽象税/政点——藩国**少remit**给中央 |
| **藩国属官** | 藩国衙署（藩相/长史/中尉），藩王自任地方官 | `CourtService` 地方官署层（`CityBureauStateTableItem`）扩一个"藩国官署"子类，官阶低于中央（§11） |
| **有限募兵** | 藩国城可为镇军补兵（比郡县略强的兵额/民力） | 仿 `FiefMilitaryRules.ActiveFiefManpowerMultiplier=1.35` |
| **藩都建设自主** | 藩都发展/建筑倾向由藩王影响（非中央国策） | 接城市 AI 政策驱动层 |

### 5.2 藩王没有的（主权权，引擎天然禁止）

| 禁止 | 为什么天然成立 |
|---|---|
| **独立外交/宣战** | 藩国城 `city.kingdom == empire`，战争/外交全走帝国粒度（`Kingdom.isEnemy`/WarManager），藩国**根本没有独立开战的对象**——引擎层面就发不出自己的战争 |
| **独立天命** | 天命是全局单例按 Kingdom 算，藩国不是 Kingdom，**共帝国天命** |
| **独立颜色** | 城属帝国 Kingdom，默认渲染帝国色；藩国区分只在**藩国专属地图模式**用帝国色的深浅变体（§12） |
| **吞并他藩/互攻** | 同属帝国 Kingdom，`isEnemy` 对同国恒 false，藩国间**永不交战**（和平时） |
| **叛离即脱法理** | 即便作乱裂变，城仍是帝国**法理核心**（§9），故"藩王独立"在法理上是"叛"不是"分" |

> **这正是"偏自治行政区划不能用附庸套"的精确落地**：附庸有独立天命/色/外交（主权级），藩国全无——藩国的"自治"只在财政/军事/人事三个**行政**维度，且强度由自治度轴调节。

## 6. 自治度轴 autonomy

`FeudatoryTableItem.autonomy`（0..100）是藩国的核心调节旋钮，一轴联动多项：

| autonomy | 留税 | 镇军兵额 | 中央干预 | 忠诚漂移 | 作乱风险 |
|---|---|---|---|---|---|
| **低（0–30）· 虚藩** | 少留、多上缴 | 小 | 中央可随意换藩王/查藩/移封 | 稳（削藩温和） | 低 |
| **中（30–70）· 实藩** | 中 | 中 | 换藩王需理由、削藩有代价 | 随事件波动 | 中 |
| **高（70–100）· 强藩** | 多留、几乎不上缴 | 大（可比小郡县国还强） | 中央难以干预、削藩几乎必逼反 | 野心涨、易离心 | 高 |

- **自治度来源**：分封时按 rank（亲王>郡王）、边疆（御边藩自治高）、皇帝恩宠定初值；此后随事件涨落（战功/中央暗弱→涨，削藩/推恩→降）。
- **联动 §7 削藩**：autonomy 越高，削藩越可能触发作乱——中央面临"养虎（高自治强藩守边）vs 削藩（逼反风险）"的长周期抉择。
- **联动 §C 集权度**（`落实方向.md §C.3`）：帝国集权度高 → 可强压藩国自治上限（`autonomy` clamp）；乱世相位 → 藩国自治事实上升（中央管不住）。

## 7. 削藩：中央 vs 藩

削藩是中央收权的手段，也是逼反的导火索——这对张力是本系统的核心玩法。

### 7.1 削藩手段（`FeudatoryService` + 决议/AI）

| 手段 | 效果 | 逼反风险 |
|---|---|---|
| **推恩（软削）** | 藩王死后，藩国**分给诸子**各成小藩（郡王），藩国越分越小、越分越弱（接 §10 继承） | **最低**——不夺现任的地，温水煮蛙。历史最优解（汉武帝） |
| **移封** | 把藩王迁到另一片（更小/更内地）城群，剥离其经营多年的根基 | 中 |
| **夺城** | 从藩国划走若干辖城归中央直辖（`FeudatoryCityTableItem` 置 active=0，城归郡县） | 中高 |
| **降爵** | 亲王→郡王，削自治/兵额（接 `noble_rank`） | 中高 |
| **废藩** | 直接除国、收回全部城、藩王贬为庶人（接 §5.4 除籍 `RefreshNobleStatus`） | **最高**——往往直接逼反 |

### 7.2 逼反判定
削藩动作触发 `FeudatoryService.CheckRevoltOnRevocation(feudatory, 削藩烈度)`：
```
反叛概率 ≈ f( 藩王野心(GeneralService AMBITION) − 藩王忠诚(loyalty)
             + 兵权(garrison 规模/帝国军力占比)
             + 削藩烈度(废藩>夺城>降爵>移封>推恩)
             + 中央暗弱(幼主/女主/权臣/低天命) )
```
——直接复用 `GeneralRebellionService.CalculateRisk`（`落实方向.md §C.4` 已确认它是现成的"权柄/反叛当量"，Clamp 0–120）。越阈值 → 走 §8 作乱裂变。**"削藩逼反"= 七国之乱/靖难的触发器**。

### 7.3 中央的抉择
- **不削**：强藩守边、宗室屏藩，但尾大不掉、传世越久越危。
- **温削（推恩）**：安全但慢，需要几代人。
- **急削（夺城/废藩）**：快速收权，但高自治藩几乎必反——赌中央军力能平叛。
AI 帝国按集权度/性格/藩国威胁自动选；玩家可手动。

## 8. 藩王作乱 → 靖难 / 七国之乱

**这是藩国系统的戏剧高潮，也是它区别于一切现有玩法的地方。**

### 8.1 触发
- **削藩逼反**（§7.2 越阈值）——最主要。
- **主动作乱**：高自治强藩 + 藩王高野心 + 中央暗弱（幼主/女主/权臣当道/低天命），藩王打"清君侧"旗号主动起兵。
- **中央天命崩**（§9）：天命崩解时，宗室藩王是**最有合法性的逐鹿者**，自动参与逐鹿。

### 8.2 裂变（复用现成链）
`FeudatoryService.Activate(feudatory, reason)`：
1. 藩都 `makeOwnKingdom(藩王, pRebellion:true, pFellApart:false)` → 真·叛军 Kingdom（藩王当王）。
2. 其余辖城 `joinAnotherKingdom(叛军, pCaptured:false, pRebellion:true)`（多城并入，仿 `MandateRebelService`）。
3. `FeudatoryTableItem.status = 作乱`；**辖城保留帝国法理核心标记**（不清 `MandateCoreCity`）——这是关键：法理仍在帝国。
4. 开战：`WarDecisionService.TryStartSystemWar(叛军, 帝国, WAR_JINGNAN, reason)`——**新战争类型"靖难/宗室内战"**（仿 `WAR_FIEF_INDEPENDENCE`）。

### 8.3 靖难战的特殊性（区别于义军 / 附庸独立）

| 维度 | 平民义军(`WAR_TIANMING_REBEL`) | 附庸独立(`WAR_FIEF_INDEPENDENCE`) | **藩王靖难(`WAR_JINGNAN`)** |
|---|---|---|---|
| 发起者 | 崩解后平民义军 | 附庸（主权藩属） | **宗室藩王（有正统血脉）** |
| 合法性 | 无（草莽） | 分离主义 | **有（宗室 + 帝国法理核心在手）** |
| 旗号 | 改朝换代 | 脱离 | **"清君侧"/继承本朝法理** |
| **藩王胜** | 建新朝 | 独立建国 | **入主中央：藩王取代皇帝当新帝，同朝更替（靖难后仍是本朝，如燕王→永乐）** |
| **中央胜** | 平定 | 收回附庸 | **平叛：除藩/废为庶人，收回城（城本就是帝国法理核心，故是"收复"不是"征服"）** |

### 8.4 胜负结算（`FeudatoryService.ResolveJingnan`）
- **藩王攻破帝国首都** → 藩王 `setKing` 帝国（或叛军 Kingdom 吸收中央）→ **同朝更替**：藩王成新帝，年号改元、可授"太宗/成祖"式庙号（接 `设计优化.md §B` 世祖/庙号——朱棣即"成祖"），天命**不崩解只易主**（接 `落实方向.md §C.4` 权臣篡位的"同国换主"精神）。原藩国裁撤（藩王已登基）。
- **中央平叛胜** → 叛军 Kingdom 被灭，城**收回中央**（法理核心本在帝国，`joinAnotherKingdom(帝国)` 或直接除叛军），藩王除籍/处决，`FeudatoryTableItem.status = 除国`。
- **僵持/第三方得利** → 天命大跌，可能推向乱世相位（§9）。

> **设计价值**：藩王作乱是"宗室内战"——它不像义军那样代表"天命崩解另起炉灶"，而是"本朝内部争夺正统"。胜则同朝换主（血脉延续），败则削平。这给天命系统补上了一条**外战灭国、平民义军之外的第三条更替路径：宗室夺嫡/藩王入主**。

## 9. 天命联动

藩国与天命深度耦合——它本质是**天命的"分布式备份"**。

### 9.1 平时：共天命、屏藩王室
- 藩国不单独算天命值，**共帝国天命**。
- 藩国城计入帝国**法理核心**（`MandateCoreCity`）与**实控率**（`CountControlledCoreCities` 已按"owner==帝国"计）——即藩王替天子守着法理疆土。
- 藩国镇军可听中央征调平叛/御外（`落实方向.md §D` 军事义务式），是帝国的边防冗余。

### 9.2 中央天命崩 → 藩王逐鹿（屏藩王室的正反两面）
天命崩解（`MandateRebelService.OnMandateCollapse`）时，宗室藩王因**有兵有地有血脉**，是**最有资格的逐鹿者**：
- 藩国自动 `Activate` 裂变（§8.2），藩王以宗室身份 `TryClaimMandate` 争天命。
- 若某藩王重夺天命 → **本朝延续/中兴**（藩王属同一宗室支）→ 可得"世祖"庙号（接 `设计优化.md §B.C` 世祖中兴状态机；`MandateService` 的 `restoration` origin 正好由"宗室藩王重建"写入）。
- 这就是分封的历史本意——**"屏藩王室"**：中央亡了，宗室藩王能续命本朝（如西晋琅琊王司马睿于江东建东晋）。反面则是藩王趁乱各自称帝、天下大乱。

### 9.3 藩国 = 治乱循环的催化剂（接 `落实方向.md §C.1`）
- 强藩坐大/削藩逼反 → 推向 **Decline/Chaos** 相位（催化剂 `catalyst_score +=`）。
- 藩王靖难成功入主 → 短期天命跌但同朝更替 → 可能回 **Renewal**。
- 藩王逐鹿决出新主 → **Renewal**（新朝休养）。
藩国是"治乱循环"里宗室维度的主要推手。

## 10. 世袭与继承

### 10.1 袭藩（默认嫡长）
藩王死 → 藩国传于其**宗室支嫡长子**（`HeirService.PickEldestLivingSon` 在藩支内选）。新藩王继任藩都太守 + 镇军队长。接 `设计优化.md §8` 继承法（藩国内部也可有留后/嫡长模式）。

### 10.2 推恩（软削藩的世袭形态）★
若帝国行**推恩令**（国策/法律，接 §7.1）：藩王死时，藩国**不整体传嫡长，而是分给诸子**——嫡长袭主藩（缩水）、余子各在辖城里分出**小藩（郡王）**。效果：
- 一代亲王 → 数个郡王小藩 → 再一代更碎 → 藩国**越分越小、离心力越弱**，几代后自然消融为郡县级。
- 复用 `LineageService.IsEnfeoffmentCandidate`（五服/诸子枚举）+ `设计优化.md §5` 分封机制。
- **这是中央最优的长期解**：不流血、不逼反，温水煮蛙。历史汉武帝解法。

### 10.3 绝嗣除国
藩王无合格宗室继承人 → **除国**，辖城收归中央郡县（`FeudatoryTableItem.status = 除国`，城清 `FEUDATORY_ID`、`MandateCoreCity` 保留）。藩王绝嗣是中央无痛收藩的良机。

## 13. 与现有系统的边界辨析

### vs FiefService（大将封地）——藩国是它的"宗室世袭升级版"
| | 大将封地 (FiefService) | 藩国 (本系统) |
|---|---|---|
| 受封者 | 功臣大将 | 宗室皇子 |
| 规模 | 单城 | 城群（藩都+辖城） |
| 世袭 | 否（人亡爵除/易主撤封） | **是**（宗室支世袭 + 推恩） |
| 作乱合法性 | 分离主义（`WAR_FIEF_INDEPENDENCE`） | **宗室正统（`WAR_JINGNAN`，胜=同朝更替）** |
| 天命 | 无特殊 | **法理核心 + 天命备份 + 崩解逐鹿** |
> 藩国**复用 FiefService 的骨架**（城留母国、关系表、钉太守/队长、税兵乘子、`makeOwnKingdom` 作乱链），但独立建 `FeudatoryService` 层，加"城群/世袭/推恩/宗室合法性/天命联动"。两者可共存：大将封地是功臣的、藩国是宗室的。

### vs VassalService（附庸）——行政 vs 主权，明确不同层
藩国**不是** VassalRelation：附庸是独立影子 Kingdom（有独立天命/色/外交），藩国的城**留在帝国 Kingdom**（无独立天命/色/外交）。**绝不复用 VassalService 建藩国**（否则又变回"附庸套壳"，正是用户要避免的）。二者唯一交集是**作乱裂变后**——叛军藩国短暂成为独立 Kingdom，此时才与附庸/独立国同层。

## 15. 分批 · 风险 · 开放问题

### 分批
1. **批一 · 静态藩国**：`FeudatoryService` + 两表 + 就藩（钉太守/镇军/法理核心）+ 藩国地图模式 + 就藩史料。玩法：皇子就藩、镇守可见，但不作乱。
2. **批二 · 世袭与削藩**：袭藩/推恩/绝嗣除国 + 削藩手段（推恩/夺城/降爵/废藩）+ 忠诚/自治演化。
3. **批三 · 作乱裂变**：削藩逼反 + 主动作乱 + `WAR_JINGNAN` 裂变 + 胜负结算（入主同朝更替/平叛除藩）。
4. **批四 · 天命联动**：崩解逐鹿 + 世祖中兴 + 治乱循环催化 + 官场藩国衙署/监察长史。

### 风险
- **R1 城归属漂移**：藩国城易主（被外敌夺/内部转）时须同步 `FeudatoryCityTableItem`（仿 `FiefService.OnCityTransferred` 自动撤销）。城丢了要从藩国辖城表移除，藩都丢了要迁藩都或除国。
- **R2 太守唯一性**：引擎一城一 leader，藩王只能当藩都太守；辖城各有自己太守（数据层从属藩王，非引擎从属）。别试图让藩王当多城 leader（引擎不支持）。
- **R3 裂变后法理**：作乱裂变后**务必保留** `MandateCoreCity`（不随 `city.kingdom` 改而清），否则丢掉"削藩正当性/藩王入主=继承法理"。
- **R4 与大将封地/义军的战争类型协调**：`WAR_JINGNAN` 的胜负结算（同朝更替）不同于 `WAR_FIEF_INDEPENDENCE`（独立）/`WAR_TIANMING_REBEL`（改朝），三者结算分支要分清，别共用。
- **R5 性能**：`FeudatoryService` 年度 tick 走缓存快照 + 错峰，勿每帧/每 actor 扫。藩国镇军锚定复用现成 `RepairSpecialArmiesAfterLoad`。

### 开放问题（动工前定案）
1. **藩都太守 = 藩王本人，还是藩王另派？** 建议藩王本人（`setLeader`），但藩王若出征/入京则藩都暂由长史代（需定代理逻辑）。
2. **辖城上限**：亲王/郡王各多少辖城？按 rank + 帝国爵位上限（接 `KingdomTitleService.getMaxCities`）。
3. **藩国间关系**：平时同属帝国永不交战（引擎天然）；但作乱时多藩连横（七国之乱）如何表达——各自裂变成独立叛军后用联盟(`Alliance`)绑，还是并入一个大叛军？建议联盟。
4. **推恩 vs 嫡长袭藩**：是帝国级国策开关（行不行推恩），还是每藩单独判？建议帝国级"推恩令"法律（接 §7.1 + `落实方向.md §C` 官制法）。
5. **藩王入主后原藩**：藩王当新帝后，其原藩国如何处置——裁撤归中央，还是转封其子？建议裁撤（他已君临天下）。
