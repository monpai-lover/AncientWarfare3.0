## 0. 设计总则：CK3 → WorldBox 的翻译规则

CK3 用 trait/law/event/customizable_localization 四件套，WorldBox 没有。以下是全文统一采用的**六条翻译规则**，每个系统都按此落地：

| CK3 机制 | WorldBox / AW3.0 落地方式 |
|---|---|
| **trait 官阶**（散官 29 阶等，纯状态标签 + 递增被动） | **int 品级字段** 存在官员记录里 + **分档 buff 表**（少量分段，不是 29 个 trait）。升降 = 改 int。 |
| **多选项 event**（谥法/庙号/考课，选项 trigger = 资格） | **Service 层评定函数**（自动，AI 与玩家同构）+ 少量**玩家决议**（改元/册封）。选项 trigger → C# 条件分支。 |
| **dynasty variable**（一朝一号唯一性锁 `set_variable`/`NOT exists`） | **per-朝代注册表**：`DynastyPeriod` 已按氏支切朝代，加一张"本朝已用名号"表或 `dynasty.data` 字典。 |
| **customizable_localization**（生死双名、结衔、告身） | **显示层拼接函数** + `Locales` 词条。按 `isAlive()`/品级/爵位选模板。 |
| **subject_contract**（8 地方建制档） | **附庸契约档 enum** 挂 `VassalRelation`；国内城市用"城市建制"字段（可选，见 §7）。 |
| **modifier**（tax_factor/development 等） | **`KingdomTrait` 注册** 或 **CourtService 缓存加权** 或直接数值结算。低频年度 tick。 |

**数值缩放**：CK3 数值（如散官月收入 0.19→3.1 金）不能直接用。AW3.0 城市税 = 人口/2、天命值 [-30,100]。本文给的 AW3.0 值都是**按 AW3.0 现有量纲重算的建议起始值**，标 `【可调】`。

**性能红线**（AW3.0 既定原则，务必遵守）：官员叙阶、考课、朝贡结算、祭祀全部挂**年度低频 tick**（`OnKingdomYear` 已有节奏），用缓存快照，**绝不每帧、绝不每 actor 全国扫描**。

**新增内容总览**（详见 §10）：约 **9 张新 SQLite 表** + 若干 `kingdom.data`/`actor.data` 字段 + 3~4 个新窗口 + 一批 `Locales` 文案词条。全部纯 Service 层 + Asset 注册，**不新增深度夺舍**。

## 1. 官僚制：个体官员生涯

> **这是两部 mod 里最深、AW3.0 缺口最大的系统。** 现状 C：`CourtService` 只有"国家级官场层"缓存快照（有哪些官职、主流学派、如何加权国策 AI），`CourtOfficerTableItem` 只是履历记录。缺**个体官员的官阶成长闭环**。本节把《礼制》的 官阶→契约产 merit→任期→考课→叙阶 整条链设计进 AW3.0。

### 1.1 品级阶梯（散官 / 勋官 / 爵位）

**CK3 原型**：文散官 `hanfan_sanguan_1..29`（九品三十阶），每阶挂 `monthly_income`（0.19→3.1，约 16 倍）+ `monthly_influence_mult`（0.01→0.17）；章服色分界：青(1)→**绿(9 宣义郎/从七品下)**→**绯(17 朝散大夫/从五品下，五品以上朝廷制授)**→**紫(25 银青光禄大夫/从三品)**；27 阶(光禄大夫/从二品)以上不可累叙。勋官 12 转（武骑尉→上柱国，prestige_gain 0.03→0.20）。爵位 9 级（开国县男 300 户→郡王 5000 户，dynasty_prestige 0.03→0.17）。

**AW3.0 设计**：**不照搬 29 个 trait**，压缩为 **9 品 × 上/下 = 18 阶** 的 int 字段 `rank`（1=从九品下 … 18=正一品/从一品），配一张 **6 段 buff 表**（不是 18 段，够用即可）。散官/勋官分文武两轨，共用 rank 数值。

**AW3.0 散官品级 buff 表【可调】**：

| rank 段 | 对应品级 | 章服 | 官员月产出（国库/城市加成） | 官员影响力权重 | 备注 |
|---|---|---|---|---|---|
| 1–4 | 九品 | **青** | +0.3 金/年 | 0.02 | 入仕起点 |
| 5–8 | 八~七品 | **绿**(rank5起) | +0.8 金/年 | 0.05 | |
| 9–12 | 六品 | 绿 | +1.5 金/年 | 0.08 | |
| 13–16 | 五品 | **绯**(rank13起) | +3.0 金/年 | 0.11 | 五品=朝廷制授，入"清要" |
| 17 | 四~三品 | **紫**(rank17起) | +5.0 金/年 | 0.14 | 三品软上限（见 §1.9） |
| 18 | 二~一品 | 紫 | +7.0 金/年 | 0.17 | 特恩制授，不可累叙 |

> "官员月产出"接到 CourtService 已有的"学派 7 维方向缓存影响国策 AI"同一层：高阶官员对国家科技/国策/决策的加权更大，且给驻在城市小幅产出/忠诚 buff。**影响力权重** = 该官在朝廷主流学派计算里的话语权（高阶官左右国策方向）。

**勋官（武轨）**：rank 同为 1–12，buff 改为 **军队维护减免 + 王朝威望**（对应 CK3 `martial_per_prestige_level`/`prestige_gain`）。**爵位**见 §5（个体虚封，走谱系家族威望）。

### 1.2 官员数据结构（扩 `CourtOfficerTableItem`）

在现有 `CourtOfficerTableItem` 上加字段（AW3.0 SQLite 自动补列）：

```
rank            : int      // 当前散官/勋官品阶 1..18
track           : byte     // 0=文(散官) 1=武(勋官)
office_id       : string   // 现任实职（丞相/太尉/刺史…，CourtService 已有官职层）
merit           : float    // 累积功勋
merit_cap       : int      // 功勋等级上限（由现任官职决定，见 §1.7）
term_end_year   : int      // 本任期满年（任期心跳，见 §1.4）
last_kaoke      : byte     // 上次考第 0..4（上/中上/中中/中下/下）
kaoke_mod_until : int      // 考绩事件修正到期年（4年）
seniority       : int      // 资历（累计考绩 xp，用于并列时排序）
```

### 1.3 入仕起阶（`f(领地/身份, 年龄)`）

**CK3 原型**：入仕阶 = f(领地 tier, 年龄, 权贵/宗室身份)。王国级+年长→高起点(.028)，伯国级+年轻→低起点(.022)。

**AW3.0 设计**：官员被 `CourtService` 纳入朝廷时定起阶：

```
起阶 base = { 城主/大将 → 5, 一般名士(诸子百家客卿) → 3, 平民入仕 → 1 }
+ 年龄修正: age>=50 +3, age 40-49 +2, age 30-39 +1
+ 身份修正: 宗室 +3, 权贵(高家族威望) +2
封顶 rank <= 13（五品，非特恩不得入紫）
```

诸子百家的名士出仕（AW3.0 已有客卿制度）即走此入仕，接上官阶轨——**两系统天然对接**。

### 1.4 任期心跳（3–6 年）

**CK3 原型**：`term_flag` 掷 3–6 年，考第好/年长→短任期→升得更勤。表：上考 100%→3yr；中上 50/50 → 3/4yr；age≥60 40/60 → 3/4yr；age30-40 10/40/40/10 → 3/4/5/6yr；age<30 → 4/5/6yr。

**AW3.0 设计**：官员入朝或叙阶后设 `term_end_year = 当前年 + roll`：

```
roll = 基础(按年龄): age>=60→3-4, 50-59→3-5, 40-49→4-5, 30-39→4-6, <30→5-6 (随机)
考第修正: 上考 → 强制 3；中上 → -1（下限3）
```

到 `term_end_year` 才触发考课+叙阶（§1.5–1.6）。任期未满不能叙阶——**这是全系统的心跳节拍器**，也天然限制了每年要处理的官员数（性能友好）。

### 1.5 考课引擎（校核 → 九等 → 事件修正）

**CK3 原型**：四善二十七最 → 考状自陈 + 校核（属性阈值）→ 九等压缩为 5 档 → 事件修正 mod_20..24（`monthly_merit_mult` +0.07/+0.05/+0.03/−0.05/−0.10，opinion，change_merit +150…−100，4 年）。校核阈值锚点 **10/13/17/20/28**。

**AW3.0 设计**：任期满时 `CourtService` 对该官算考第。**数据源复用 AW3.0 已有**：官员驻在城市的人口增长率、战功记录（`WarRecordWriter`）、是否廉洁（可由行为/特质近似）。

**校核评分（属性→上/中/下 概率）【可调】**：取官员主属性 = max(智力, 战力…AW3.0 actor 属性)：

| 条件（自上而下首中） | P(上) | P(中) | P(下) |
|---|---|---|---|
| 权贵（高家族威望/宗室） | 55% | 40% | 5% |
| 已入紫阶(rank≥17) 或 高影响力 | 40% | 50% | 10% |
| 主属性 ≥ 28，或驻城人口正增长 | 25% | 60% | 15% |
| 主属性 ≥ 17 | 15% | 50% | 35% |
| 主属性 < 17，或驻城人口负增长 | 0% | 30% | 70% |

> "户口增减→进降考"：AW3.0 城市人口表已有增长率数据，直接作为一档修正接入（CK3 此 build 反而没接，AW3.0 可做得更实）。

**初评 → 复考 → 九等最终 5 档**（简化为一次 random_list，权重同 CK3 fukao 表），产出 `last_kaoke` ∈ {0上, 1中上, 2中中, 3中下, 4下} + `kaoke_mod_until = 年+4`。

**考绩事件修正表【可调】**（4 年有效，接 merit + 叙阶 + opinion）：

| 档 | merit 速率乘子 | 一次性 merit | 忠诚/好感 | 驻城产出 |
|---|---|---|---|---|
| 上考 | +0.07 | +100 | 君臣好感 +10 | 城市产出 +小 |
| 中上 | +0.05 | +70 | +5 | +微 |
| 中中 | +0.03 | +30 | 0 | 0 |
| 中下 | −0.05 | −30 | −10，城市税 −0.05 | −微 |
| 下考 | −0.10 | −70 | −15 | −小 |

### 1.6 叙阶跳级表（考第 → 跳几阶）

**CK3 原型**：读当前阶 + 读考第 → random_list 决定 +1/+2/+3 阶。权贵 20/50/30；上考 35/45/20；中上 70/30/0；无考绩 100/0/0。

**AW3.0 设计**：任期满、考课出档后，按 `last_kaoke` 掷跳级：

| 当前考第 | +1 阶 | +2 阶 | +3 阶 |
|---|---|---|---|
| 权贵/宗室 | 20% | 50% | 30% |
| 上考 | 35% | 45% | 20% |
| 中上 | 70% | 30% | 0 |
| 中中 | 100% | 0 | 0 |
| 中下 | **降 1 阶** | | |
| 下考 | **降 2 阶** | | |

跳级后 `rank += n`，重设任期（§1.4）。**上考→短任期+高跳级 = 能吏滚雪球；下考→降阶 = 新陈代谢**。所有过程写一条官员履历史（`CourtOfficerTableItem` 已在，加叙阶记录）。

### 1.7 merit 闭环（功勋来源 + 上限）

**CK3 原型**：merit 靠**契约**产出——文官 `monthly_merit_per_liege_tax`（0.8/1.0/1.5 随建制）、武官 `monthly_merit_per_title_maa_value`（0.024/0.032）；merit 上限由**现任实职 trait** 定（宰执 +9、普通官 +1）；考课注入 merit 且乘速率。

**AW3.0 设计**：

- **产出**：官员年度 merit += f(实职类型)。文官按其**主政城市的税收/人口**（AW3.0 城市税已有）；武官按其**统领军队规模**（AW3.0 军队已有）。乘 `last_kaoke` 的速率修正。
- **上限**：`merit_cap` 由 `office_id`（现任实职）定——三省长官/宰执类高上限，地方小吏低上限。**失去实职则上限下降**（merit 溢出封顶）。
- **用途**：merit 不是硬门槛，是**平行资源**——高 merit 官员在 `CourtService` 主流学派计算里权重更高（左右国策），且是升实职（非升阶）的排序依据。叙阶靠考第，实职任命靠 merit——两条线。

### 1.8 文武分途

**CK3 原型**：地方建制契约打 `civilian_province`/`military_province` 旗，决定官走文班（散官）还是武班（勋官）。

**AW3.0 设计**：官员 `track` 字段（0 文/1 武）在入仕时按其来源定——名士/治政型→文，大将/军功型→武。文轨升散官（产出/影响力），武轨升勋官（军队减免/威望）。CourtService 主政学派可偏文偏武，影响两轨官员比例——接上已有的"学派影响国策"层。

### 1.9 三品软上限（清要出于特恩）

**CK3 原型**：三品（rank 25+）以上自动叙阶停止，只能靠君主特批决议（`hanfan_sanguan_27_decision`）。

**AW3.0 设计**：`rank >= 17`（紫阶）后，考课不再自动 +阶。升到一品需**君主决议"制授"**——花皇权/威望，且名额稀缺（全国紫阶官数量上限，如 ≤3）。**既合"宰执出于特恩"史实，又防数值失控**（否则全是一品）。

**实现挂点（§1 全节）**：`CourtService.cs`（个体官员生涯，扩 `CourtOfficerTableItem`）；年度 tick 用已有 `OnKingdomYear`；考绩数据源复用城市人口表 + `WarRecordWriter`；三品制授走 `KingdomPolicyDefs` 新决议；显示走 `CourtWindow.cs`（官员列表加阶名/考第/任期）+ `OfficialShiRules.cs`（官职氏）。**纯 Service 层，无新 Harmony patch。**

## 2. 名号系统

> 现状 C：AW3.0 谥号（五维打分）、天命庙号（祖/宗）、年号（帝国雅号/普通国拼接）**均已生产级实装**。本节是**在现有引擎上补深度**：把两部 mod 的谥法字库、覆免、文武分流、世祖状态机、生死双名、奉正朔、国号绑姓全部接进去。

### 2.1 谥法引擎强化（谥字全表 + 覆免 + 文武分流）

**CK3 原型（参考 A）**：每个谥字是一个选项，trigger = 该字资格；美谥 AND 高门槛、恶谥/夭折谥 OR 低门槛；两道**覆免**黑名单否决极美谥；主属性分流生成文某/武某双字。

**AW3.0 设计**：`PosthumousTitleService` 现有五维打分选字，**在选字层前置加"谥法资格表 + 覆免"**。以下是可直接编码的**谥字→条件表**（从 CK3 `hanfan_zengshi.001` 提取，属性名映射到 AW3.0 actor 属性/行为记录）：

**美谥（AND 多条件，高门槛）**：

| 谥字 | 类 | AW3.0 资格条件（AND） |
|---|---|---|
| 文 | 极美 | 未犯覆免文 且（学识高+文教背景 或 外交高+仁德 或 治政高+能吏） |
| 武 | 极美 | 未犯覆免武 且（战力高+统帅 或 勇武+武艺） |
| 成 | 美 | 威望高 + 勤勉 + 有能吏背景 + 无罪 |
| 昭 | 美 | 美貌 + （外交/仁德/亲和之一）+ 无罪 |
| 宣 | 美 | 外交 + 慷慨 + 威望高 + 诚信 + 无罪 |
| 桓/庄/襄 | 美(武) | 雄心/勤勉 + 统帅背景 + 勇武 |
| 景 | 美 | 公正 + 勇武 |
| 烈/元/宪/献 | 美 | 威望/能吏/学识向（见 CK3 .027/.028/.032/.033） |
| 孝/恭/懿/穆/贞/敬/简/定/惠 | 美/平上 | 仁德/谦逊/虔敬向（低战功也可得，重德行） |

**平谥（单条件）**：平（知足+温和）、僖（怯懦但安分）、和（外交+仁）、节（谦+节制）、敏（勤+谦+有才）等。

## 3. 礼制 · 正统 · 祭祀风险博弈

> 现状 C：AW3.0 有天命值 [-30,100]/皇权/王朝威望，但"礼制"只是国策节点（礼乐/宗庙祭祀/天命礼制），**升爵纯看领土，无祭祀这种主动仪式**。本节把《礼制》的三祭风险博弈接到天命值上，并让礼制门控称帝升爵。

### 3.1 三祭风险博弈（郊祀 / 禘享 / 祭社）

**CK3 原型（参考 A）**：三祭按月份门控（郊祀冬≥10 月 300–500 金 / 禘享夏 4–6 月 / 祭社春 1–3 月，各 150–300 金），须正确信仰+无战。**斋戒三级**（越深吉率越低但保底）+ **祭司资历**（能吏/神学/虔敬≥3/学识≥20 任一 = 达标，换概率表）。概率与结果：

| 斋戒 | 达标(大吉/平/凶) | 未达标(大吉/平/凶) |
|---|---|---|
| 一级(赌大) | **39/60/1** | 25/65/10 |
| 二级 | 15/75/10 | 5/70/25 |
| 三级(保守) | 50/50（无凶） | 40/60 |

三结果奖惩（5 年 buff）：**大吉** piety+300~500/prestige+200~400/legit+30~50 + `mod_51`（county_control+0.1/legit+0.1/clergy+20）；**平** 减半 `mod_52`；**凶** 全负 `mod_53`（county_control−0.07/legit−0.05/clergy−15）。中途凶兆(`.0122`)会恶化最终概率表——**赌博张力**。

**AW3.0 设计**：新常态决议 `aw_decision_grand_sacrifice`（郊祀，AW3.0 已有"祭天整顿"可作起点，改为博弈）：

- **门控**：帝国级/天命国、非战时、已研 `宗庙祭祀`+`天命礼制`、按季节（可选）、cooldown 5 年。花皇权 + 金【可调：50~100 金】。
- **祭司资历**：国王 智力≥某阈 或 学识型 或 已建太庙 = 达标 → 用好概率表。
- **斋戒选择**：决议给三档（赌大/中庸/保守），对应上表概率。
- **三结果接天命值**【AW3.0 缩放】：

| 结果 | 天命值 | 皇权 | 王朝威望 | 5 年 buff |
|---|---|---|---|---|
| 大吉 | +8~12 | +大 | +大 | 全国城市秩序/忠诚 +，天命增速 + |
| 平 | +3~5 | +中 | +中 | 小幅正 |
| 凶 | −8~12 | −中 | −中 | 城市秩序/忠诚 −，天命增速 −，可能触发灾异事件 |

**价值**：AW3.0 天命值现在是被动年度演化，此决议给玩家/AI 一个**有敬畏感的主动赌注**，与已有系统零冲突。

## 4. 政体与官制法律链

> 现状 C：AW3.0 有共和政体（`RepublicGovernmentService`）+ 爵位 5 级，但无"周汉唐宋官制改革"这条随时代演进的制度线。本节把《礼制》的官制法律链 + 三条辅助法移植为 AW3.0 的"官制国策"。

### 4.1 中华行政制（流官 vs 世封）

**CK3 原型**：`hanfan_guanzhi_law` 四档递进，各鲜明修正 + AI 按史实年代自切（唐制 <900、宋制 >1000）。周制重分封(+vassal_limit/可指定继承)、汉制重集权武备(+county_control/+levy)、唐制重开放(+异文化好感/+MAA)、宋制重文治(+development/+vassal税/−武力)。

**AW3.0 设计**：新增一条"官制"国策科技分支（4 档，`KingdomPolicyDefs`），每档给国家级 buff（`KingdomTrait`）：

| 官制 | AW3.0 buff【可调】 | 解锁 |
|---|---|---|
| 周制 | 附庸上限 +，可指定继承人（接 §8），分封路线加成 | 默认/早期 |
| 汉制 | 城市秩序 +，征兵 +，集权（削附庸自治） | 研"官场制度" |
| 唐制 | 异族好感 +，军队上限 +，开放扩张 | 研"三省六部" |
| 宋制 | 城市发展/科技 +，附庸税 +，但军队维护 −、武力 − | 后期文治 |

### 4.3 三条辅助法

- **任期法**（0/3/6/9 年）：接 §1.4 官员任期长度。终身任期(0)→官员好感+但流动慢；短任期(3)→流动快但好感−。国家级国策，默认六年。

- **用官文化法**（0/1/2）：是否偏用本族（Xia）官员——接 §1 入仕（异族官员好感修正）。

**实现挂点**：官制链入 `KingdomPolicyDefs`（4 科技节点）+ `KingdomTrait` 表达 buff；三辅助法作社会国策；改制史走官场已有史料。

> 现状 C：AW3.0 有大将实封城池（`FiefService`）+ 拥兵叛乱，爵位是王国级（伯侯公王帝）。缺**个体宗室/功臣爵位**与"虚封 vs 实土"抉择。本节移植《礼制》的荣誉虚封 + 开府建国 + 大封五服 + 削藩 + 赐姓。

### 5.1 荣誉虚封爵位（9 级，纯家族威望）

**CK3 原型**：`juewei_1..9`（开国县男 300 户→郡王 5000 户），纯荣誉 trait，只给 `monthly_dynasty_prestige_mult`（0.03→0.17）+ 生育 + dynasty_opinion。食邑户数是文案。

**AW3.0 设计**：个体虚封爵位 int 字段挂宗室/功臣（`LineageService` 家族威望已有）：

| 爵 | 名义食邑 | 家族威望/年【可调】 | 谱系地位 |
|---|---|---|---|
| 开国县男 | 300 户 | +0.03 | 入贵族 |
| 县子/县伯/县侯 | 500/700/1000 | +0.05/0.07/0.09 | |
| 县公/郡公 | 1500/2000 | +0.11/0.13 | |
| 国公 | 3000 | +0.15 | 高门 |
| 郡王 | 5000 | +0.17 | 异姓爵之极 |

**虚封无风险、无实权**——只是荣誉 + 家族威望 + 谱系上位。君主低成本笼络手段。嫡长子袭爵（AW3.0 谱系已有嫡长逻辑），袭爵给小额继承 buff。

### 5.2 开府建国（实土授权，不可逆抉择）

**CK3 原型**：唯"开府建国"实土化——`create_cadet_branch` 开小宗 + 授古国名王国头衔（k_hanfan_title_zhou/qin/jin…），分世袭 vs `destroy_on_succession`（身没爵除）两组。

**AW3.0 设计**：把 AW3.0 已有的 `FiefService`（大将实封城池）**明确定位为"实土"档**，与虚封（§5.1）二元对立：

- **虚封**（授爵）：安全，只给荣誉/威望，不给兵不给地。
- **实土**（开府建国 / 分封城池）：给封地（城池）+ 封地军（`FiefMilitaryService` 已有），**但埋叛乱种子**（`GeneralRebellionService` 拥兵自重已有）。可选世袭（传子）vs 身没收回。

**君主抉择**：授荣（无风险，笼络）vs 授土（有战力/守边，但可能拥兵自重、削藩要付代价）。**这几乎是把 AW3.0 已有的爵位 + 大将封地重新框定为一个抉择，代码增量小、张力大。**

### 5.3 大封宗室（五服亲疏批量授爵）

**CK3 原型**：新帝即位"大封宗室"决议（1000–1500 金），按五服亲疏批量定爵——直系男→亲王、子降郡公、女→公主等级。

**AW3.0 设计**：称帝/即位时可发"大封宗室"决议（花皇权/威望），遍历王族在世成员（`LineageService` 谱系已有亲疏），按代距授虚封：

```
皇帝之子/孙 → 亲王（最高虚封）
亲王之子 → 郡公
更远支 → 递降
女性宗室 → 公主/长公主/大长公主（按代距）
```

一次性仪式，写天命史高光（§9 册书文案）。

### 5.4 削藩 / 降爵 / 除籍（5 级惩罚）

**CK3 原型**：graduated——降 1/2/3 级（亲王→郡王→国公→郡公，摧毁其王国）；force_step_down（夺地）；除籍（set_to_lowborn 连坐子女）。merit/opinion 大幅负。

**AW3.0 设计**：君主对宗室/实封者的惩罚链：

| 级 | 效果 | 代价/风险 |
|---|---|---|
| 降爵 1–3 | 虚封降级 | 好感 −，实封者可能"抗命起兵"（接 `GeneralRebellionService`） |
| 夺地 | 收回实封城池（`FiefService.RevokeFief` 已有） | 强反弹，可能封地独立战 |
| 除籍 | 逐出王族氏（`LineageService` 改氏/贬平民）+ 连坐子女 | 最重，忠诚崩 |

**长周期耦合**：养大的实封亲王越难削（会起兵）——"分封时的慷慨"与"日后削藩的成本"形成跨时段策略。

### 5.5 赐姓 / 付籍（纳功臣为宗亲）

**CK3 原型**：赐姓 = `set_house` 把功臣及其在世子孙纳入天子家族（+prestige_level），是忠诚最高奖赏；与除籍构成一进一出。

**AW3.0 设计**：赐姓——把高忠功臣纳入王族氏（`LineageService` 已支持改氏，且同步族谱），子孙一并。给家族威望 + 谱系上位。忠诚极端奖励。**与除籍（§5.4）对称**。

**实现挂点（§5 全节）**：虚封爵位挂 `LineageService`（家族威望）；实土沿用 `FiefService`+`GeneralRebellionService`；大封/赐姓走 `ChronicleEvents` 一次性事件；削藩接 `FiefService.RevokeFief` + 叛乱服务。

## 6. 社会互动

> 现状 C：AW3.0 君主对臣、臣对君缺"制敕/干谒"这类社会动作。本节移植《礼制》的处置（君→臣）+ 干请（臣→君），作为官僚系统（§1）的操作面。

### 6.1 处置（君 → 臣，10 合 1 总控台）

**CK3 原型**：`hanfan_chuzhi_interaction` 一个互动含 10 个 send_option——升擢/罢黜/增减官资/谕夺/封疆/属籍/供辞/调整区划/留任转迁/赐名。auto_accept 但高爵者可能抗拒。

**AW3.0 设计**：君主对官员的操作集（在 `CourtWindow` 官员条目上的按钮）：

| 操作 | 效果 | 接 |
|---|---|---|
| 升擢/罢黜 | 改 rank / 免实职 | §1.6 叙阶 |
| 封疆（授实土） | 授封地 | §5.2 |
| 属籍/赐姓 | 纳王族氏 | §5.5 |
| 除籍 | 逐出 | §5.4 |
| 调整区划 | 改城市归属/建制 | §7 |
| 赐名/赐谥 | 授号 | §2 |

高爵/实封者可能抗命（好感低+野心高→拒绝甚至起兵），接 `GeneralRebellionService`。

### 6.2 干请（臣 → 君，AI 官员求进）

**CK3 原型**：`hanfan_jinxianganlu_interaction` AI 官员献口/进宝/干谒——花钱刷好感谋仕进。

**AW3.0 设计**：AI 官员年度低频尝试"干请"——高野心低阶官花资源刷君主好感，提升被升擢概率。作 `CourtService` 年度 tick 里的一个 AI 行为（低频、缓存）。**制举出身者更忠诚**（少干请）。

**实现挂点**：处置走 `CourtWindow` 按钮 + `CourtService` 执行；干请作 `CourtService.OnKingdomYear` 的 AI 行为。

## 7. 朝贡 · 附庸契约深化

> 现状 C：`VassalService` 的 `VassalRelation` 有 `autonomy`/`tribute_rate`/`military_obligation` 三字段但**无逻辑消费**（空壳）。这是**全项目最高性价比的缺口**。本节移植《礼制》8 建制契约 + 奉正朔。

### 7.1 附庸契约档（移植 8 建制）

**CK3 原型**：8 地方建制（州县/监榷/升府/防戍/军镇/都护/分封/羁縻），在"上供税/军事/自治"三轴取舍，文/武分途。羁縻（异族，税−1 兵−1 只给威望不可夺）；军镇（半自治藩镇，几乎不上供）；州县（基础，上供 0.25+levy）。

**AW3.0 设计**：把附庸从"是/否"升级为**契约档 enum**（挂 `VassalRelation`），映射 CK3 建制到 AW3.0 三字段：

| 契约档 | tribute_rate | military_obligation | autonomy | 可夺 | 对应 CK3 | AI 倾向 |
|---|---|---|---|---|---|---|
| **内藩（州县）** | 高(0.25) | 高 | 低 | 可吞并 | 州县 | 顺从 |
| **外藩（军镇）** | 中 | 中 | 中 | 难 | 军镇 | 半自治，可能独立 |
| **羁縻（异族）** | 0（不上供） | 0 | 高 | **不可强夺** | 羁縻 | 松散，只记威望 |
| **都护（域外驻军）** | 低 | 高（驻军） | — | — | 都护 | 边疆扩张 |

### 7.2 朝贡年度结算（激活三字段）⭐

**AW3.0 设计**：在 `VassalService` 加年度结算（`OnKingdomYear`）：

- **`tribute_rate`**：附庸按比例向宗主转移金/资源（复用 AW3.0 城市税收/缴税路径——附庸城市 `gold_change` 的一部分流向宗主）。
- **`military_obligation`**：附庸战争支援的兵力比例（现状是全有全无的"拉入同侧"，改为按义务比例出兵）。
- **`autonomy`**：高自治→少上供，但宗主对其内政干预（换将、强制改元、调整建制）受限；低自治→多上供，宗主可深度干预。

**三字段立刻从装饰变成经济/军事/政治杠杆。** 无需新字段，纯补结算逻辑。

### 7.3 奉正朔（附庸显宗主年号）

**CK3 原型**：附庸/朝贡国无自己年号→显示宗主的年号（`nianhao_date_top_liege` / `GetSuzerain.Custom('huangdi_nianhao')`）。

**AW3.0 设计**：附庸国（非帝国级）的年号显示，取 `VassalService.GetRootSuzerain` 的年号（`YearNameService` 已有取年号）。接 §2.4 称呼优先级第 1 档。**一眼可见"天下奉谁正朔"**，强化天命圈存在感。

**实现挂点**：契约档 + 朝贡结算走 `VassalService.cs`（`OnKingdomYear`）；档位 UI 走 `VassalRelationWindow.cs`；奉正朔走 `YearNameService`+`KingdomWindowAddition`（先查 GetRootSuzerain）。

## 8. 三继承法

> 现状 C：`HeirService` 只有嫡长子优先。本节移植《礼制》三继承法，并让**继承法反映国家性质**。

**CK3 原型**：流官叙迁（能力，meritocratic + 退休 + 任期，不世袭）/ 嫡长（血统，血缘+嫡庶+性别）/ 留后（武力，候选=军中将领/廷臣不含子嗣，按武艺+勇略，还原藩镇拥立）。政体自动匹配。

**AW3.0 设计**：给王国一个"继承法"状态（`kingdom.data`），按国家性质自动/可选切换：

| 继承法 | 触发条件 | 选继承逻辑 | 接 |
|---|---|---|---|
| **嫡长**（默认） | 常态 | 嫡长子优先，无子按最近共同父系（AW3.0 现状） | `HeirService` 现状 |
| **留后/军中拥立** | 边军/大将势力主导，或天命崩解义军期 | 按军功/军力/勇武拥立强者（含非直系将领） | 边军服务 + `MandateRebelService`（义军已有快速决出精神） |
| **流官/禅让** | 官场升至三省六部，或共和政体 | 按官阶/能力/威望选，非血统 | `CourtService` + `RepublicGovernmentService` |

**价值**：军阀国走武力拥立、文官国走能力禅让、常态走嫡长——**制度差异在继承上可见**。天命崩解时义军国走留后（乱世强者上位），完美贴合 AW3.0 已有的义军逐鹿。

**实现挂点**：`HeirService.cs`（加继承法分支，判据来自 CourtService/RepublicGovernmentService/MandateService/边军服务）。原版底座 `CultureTrait` succession 组可作原生承载。

## 9. 表现层

> **两部 mod 深度感的绝大部分来自表现层**——机制数值很轻，考据文书极重。AW3.0 数据已全（谥号五维/庙号/年号/爵位/官阶），只差把史料从"白描"升级为"诏敕/骈文"。**这是全文性价比最高的一批。**

### 9.1 骈体化关键史料文案

**CK3 原型**：谥法事件内嵌《逸周书·谥法解》原文；骈体确认句"先帝好和不争，在国遭忧，谥曰孝愍！"；授号句式"先帝功劭德崇且慈民爱物，曰仁，庙号仁宗！"。

**AW3.0 设计**：给关键节点（授谥/授庙号/改元/升爵/开府/赐姓/天命得失/官制改革）套**骈文诏书模板**，动态填入结衔/年号/干支。改 `HistoryWriter` 输出为诏敕口吻：

- 授谥：`先帝〔生平骈句〕，〔谥字古义〕，曰〔谥字〕，庙号〔X宗〕！`
- 改元：`〔君主〕践祚，改元〔年号〕，大赦天下。`
- 开府：`封〔宗室〕为〔古国〕王，开府建国，世守〔封地〕。`

配一批《谥法解》古义词条（每个谥字一句古义）作文案库——**纯 `Locales` 词条，零机制成本**。

### 9.2 干支纪年

**CK3 原型**：`年 mod 10 = 天干`、`年 mod 12 = 地支`。

**AW3.0 设计**：史料日期加干支——"远景二年"→"远景二年岁在丁未"。纯格式化，接 `HistoryWriter.BuildYearPrefix`（已有纪年前缀）。

### 9.3 告身 / 结衔（官员名片）

**CK3 原型**：29 散官各有专属任命骈文（告身）；结衔 = 多重荣衔织成的长串名片。

**AW3.0 设计**：官员（§1）升阶时写一条"告身"史料（按阶名生成任命辞）；官员 tooltip / `CourtWindow` 显示结衔（散官阶 + 实职 + 勋 + 爵拼接）。集邮式养成的表现层。

### 9.4 册书 / 九锡（叙事道具）

**CK3 原型**：即位册/九锡文/改制诏作神器；九锡（大辂/衮冕/朱户/纳陛/虎贲/斧钺/彤弓/秬鬯 + 剑履上殿）是禅代前奏顶级荣誉。

**AW3.0 设计**：称帝/受禅/权臣加九锡等重大节点，生成一段仪式文案作历史高光（挂天命史/人物史）。可选：加九锡作"权臣篡位"前兆事件（接 AW3.0 已有篡位）。

### 9.5 内阁风味化（官名随官制变）

**CK3 原型**：同一 council 席位在周/汉/唐/宋 + 建制不同下有历史准确的不同官名。

**AW3.0 设计**：AW3.0 官场三层级（原始朝会/三公九卿/三省六部）已有官名切换。**补充**：官名随 §4.2 官制改革（周/汉/唐/宋）进一步变体（如丞相↔中书令）。`OfficialShiRules` 已有官职氏，扩官名表即可。

**实现挂点**：`HistoryWriter.cs`/`ChronicleEvents.cs`（文案模板）；`Locales`（骈文/古义词条）；干支纯计算；告身/结衔走 `CourtWindow`+`OfficialShiRules`。

## 12. 风险与边界

1. **不要重做已实装系统**：谥号/庙号/年号/官场/天命/分封/诸子百家/共和政体都已生产级。本方案是"补深度 + 补个体层"，非推翻。动手前先读对应 Service（注意 `YearNameService`/`PosthumousTitleService`/`LineageService.cs:1667` 几处过时"待做"注释是误导）。

2. **官阶不要照搬 29 个 trait**：CK3 七部官阶数百 trait + 上千行 `has_trait` OR。AW3.0 用"品级 int + 6 段 buff 表"表达同样手感，避免维护地狱。谥字/庙号条件表可以详尽，但用 C# 条件分支，不是 event 选项。

3. **性能红线**：官员叙阶/考课/朝贡/祭祀/干请全部挂**年度低频 tick**（`OnKingdomYear`），缓存快照，绝不每帧/每 actor 全国扫描。官员任期心跳（§1.4）天然摊平每年处理量。

4. **少夺舍**：优先官方扩展点（`OpinionAsset`/`KingdomTrait`/`PlotAsset`/Asset 配置）。AW3.0 特殊军队靠反射调私有字段已有版本脆弱风险，新系统别再加。`[MethodReplace]` 慎用（只校验名不校验签名）。

5. **中文命名依赖编译符号 `一米_中文名`**：谥号/年号/称呼/骈文文案的呈现依赖中文词库；无 ChineseName mod 时退回内置古姓池，发布构建需确认符号状态，避免新表现层文案报错。

6. **表现层先行验证**：CK3 两部 mod 证明"轻机制 + 重考据文案"极低成本换极高沉浸。AW3.0 数据已齐，**骈体文案（§9.1）是最快见效、最值得先做的一条**。

## 13. 参考 E：Oriental Empires 可移植系统

> 《Oriental Empires (All Under Heaven)》是中华总转化 mod，体量远大于参考 A/B。剔除 AW3.0 已有系统后，它的增量价值**不在任何单一子系统，而在把天命做成了"乱世↔治世的动态阶段机"**。本章按"新增/显著不同"筛选，给出对 AW3.0 的移植方案。数值仍标 `【可调】`。
>
> **三处架构级升级思想**（最值得吸收）：① 天命从**静态数值**升级为**带阶段的状态机**（治乱循环）；② 中央集权用**分级法律 + 冷却**表达；③ 权臣用 **diarchy 权力天平**建模，而非单纯忠诚度。

### 13.1 ★ 治乱循环阶段机：把静态天命升级为状态机（最高价值）

**OE 原型**：用 CK3 的 **Struggle**（`tartaria_struggle`：4 阶段循环 `迁徙→敌对→鼎革→涵化`，催化剂推相变，参与方分 Involved/Interloper/Uninvolved 三档吃不同修正）+ **Situation**（`dynastic_cycle` 治乱循环：全局阶段 `治世→衰→乱世`，叠加四派运动 尊君/进取/扩张/保守）。关键耦合：**乱世相位无法维持最高集权法律**；`hostility` 阶段解锁"问鼎天下"CB + 给参与方巨大战力修正（`advantage=5`）；`conciliation` 阶段强制和平 + 开互市。

**AW3.0 设计**：把现有天命（-30~100 静态值 + 义军 + 称帝）**升级为一个全局阶段机**（存 `MandateService` 全局单例，AW3.0 已是单例）：

| 阶段 | 触发（由天命值 + catalysts 推进） | 阶段规则（改写全局行为） |
|---|---|---|
| **治世** | 天命值高、皇权稳 | 集权法律可达最高级（§13.2）；义军难起；天命国战力小幅 + |
| **衰世** | 天命值中低、灾异/暴政累积 | 义军开始出现；集权法律上限降一级；边镇/大将野心 + |
| **乱世（逐鹿）** | 天命值触底 / 天命国崩解 | **解锁"问鼎天下"称帝**；义军占领速度×8（AW3.0 已有）；群雄战力 +；禁止普通停战（逐鹿到底） |
| **新朝（涵化）** | 逐鹿决出新天命国 | 强制一段和平期休养；新朝进入治世，循环重启 |

**催化剂（catalysts）→ 用 AW3.0 已有事件当推进器**：暴君/屠城/大疫（§13.7）/篡位/天命国战败 → 推向衰/乱；祭天大吉（§3）/统一度提升 → 推向治世。**四派运动**可映射到 AW3.0 官场学派方向（进取派≈法家/兵家、保守派≈儒家…），朝中主流派影响国策 AI（`CourtService` 已有学派加权层，天然对接）。

- **移植性：概念 High / 逐字 Medium**（Struggle/Situation 是 CK3 专有框架，但"阶段机 + 催化剂 + 每阶段改写规则"的数据驱动范式可用 C# 状态机重写）。
- **挂接**：直接扩 `MandateService`——加一个 `MandatePhase` enum + 阶段规则表 + 催化剂累积器。AW3.0 义军/称帝/王朝威望正好当现成 catalysts。**这是 OE 对 AW3.0 最大的单点升级。**

### 13.2 分级皇权法律（中央集权度）

**OE 原型**：`celestial_bureaucracy_0→3` 四级累进法律 = 中央集权度，每级 `tax_contribution +0.05→0.10` + 封臣好感修正，逐级解锁：级1 指定官僚继任/设任期/换官、级2 **禁封臣内战 + 调换大将防区**、级3 **永久禁封臣一切战争**。升级耗威望 + 10/20/30 年冷却。**级3 在乱世相位维持不住**（接 §13.1）。

**AW3.0 设计**：给王国一个"集权度"整数轴（0–3，存 `kingdom.data`），每级挂 `KingdomTrait` buff + 解锁表：

| 集权度 | AW3.0 效果【可调】 | 解锁 |
|---|---|---|
| 0 松散 | — | — |
| 1 初集权 | 附庸上供 +，可指定官员继任 | 设官员任期（§1.4） |
| 2 集权 | 城市秩序 +，**可禁附庸内战、调换边军防区** | 边军调防（AW3.0 边军已有锚城，改为可手动调） |
| 3 高度集权 | 征税分成 +，**永久禁附庸对外战争** | 兵权归中央（接 §4.3 边防之制法） |

升级耗皇权/威望 + 冷却。**乱世阶段（§13.1）强制降级**——"乱世无法中央集权"。移植性 **High**（分级 + 解锁 + 冷却，逻辑简单）。挂接 `MandateService`（阶段）+ `KingdomPolicyDefs`（作国策）。

### 13.3 朝贡藩属（华夷中间态）★

**OE 原型**：独立于封臣的**宗主-藩属**关系（临时/永久/被征服三型），有 `tribute_exp` 经验、叩关 CB、脱离战争，**不转移头衔、只纳贡**；天子夺天命时境外藩自动转 `tributary_celestial`。

**AW3.0 设计**：这与参考 A 的"羁縻契约档"（§7.1）**是同一需求的两种来源**——OE 把它做成了**独立于附庸的更松散一层**。建议在 §7 附庸契约档之上，再补一个**最松层"朝贡国"**：

- **朝贡国 ≠ 附庸**：不改颜色、不并入战争体系，只每年纳一次贡（金/资源），换宗主"不征讨 + 册封名分"。
- **叩关 CB**：宗主可对不臣的邻国发"叩关"战，胜则收为朝贡国（AW3.0 宣战理由体系已有，加一种 `tributary_war`）。
- **称帝自动收贡**：天命国称帝时，周边弱国自动转朝贡国（呼应 §13.1 新朝）。

移植性 **High**（弱关系数据）。挂接 `VassalService`（加"朝贡"关系类型，比附庸更轻）+ `DiplomacyContent`（叩关 CB）。

### 13.4 权臣权力天平 → 弑君篡位 ★

**OE 原型**：`grand_secretariat`（丞相/首辅）与君主 **swing 0→90 共治天平**，swing 越高解锁越多侵权：0 侵吞国库 → 20 关押 → 40 撤职夺爵 → 60 自设职责 → 80 找替罪羊 → **90 可弑君 + 篡位 + 成为继承人**。三法变体（文丞相/武大将军/御史）。

**AW3.0 设计**：AW3.0 已有篡位（`first.tianmingP` 自动篡位）与官场，但**缺"权臣渐进坐大"的过程**。加一个**权柄计 0–100**（存于当朝首席官员，`CourtService`）：

- 首席官员（丞相/大将军）在职年限 + 高 merit（§1.7）+ 幼主/女主/暗弱之君 → 权柄逐年上涨。
- 权柄分档解锁对君行为：侵国库 → 专权（架空国策）→ **权柄满 + 低天命 → 触发篡位/禅代事件**（接 AW3.0 已有篡位 + §9.4 九锡前兆文案）。
- 君主可用"处置"（§6.1）罢黜压制，但高权柄者可能抗命起兵。

移植性 **Medium**（swing 机制需自建，概念清晰）。挂接 `CourtService`（权柄计）+ `MandateService`（低天命触发）+ 已有篡位逻辑。**"权臣坐大→改朝换代"是 AW3.0 缺的一条新王朝更替路径**（区别于外战灭国与义军）。

### 13.5 官资↔州格铨选 + 差遣 + 内廷宦官轨（深化官场）

三个可直接接到 §1 官僚制的官场增强：

- **官资↔州格铨选评分**（`succession_appointment\chinese_bureaucracy.txt`）：官职出缺时，按候选人**官资（人的品级）vs 州格（职的品级）**匹配度自动补官——官资 > 州格给 `差×20`，反之罚分；叠加科举（进士 +20/状元 +50）、门第（家族威望 ×20）、寒门法、流官法（一人一职否则 −1000）。→ **这是 AW3.0 官场未描述的新维度**（我在 §1.7 把 merit 作实职排序依据，OE 提供了更完整的"人品级配职品级"公式）。**移植性 High**，直接作 §1 实职任命的评分器。
- **差遣/使职**（`tax_slots`）：皇帝任命宫廷官为"税吏"管辖若干封臣，按差遣类型施加政策组合——太府（重税/封臣 −好感）、理藩院（异族羁縻）、兵部（府兵，兵役 +税 −）、市舶司（沿海，发展 +）。→ 给官员一个"差遣"字段，对辖区施加政策组合。**移植性 High**，接 §7 建制 + §1 官员。
- **内廷宦官轨**（`court_positions`）：平行于外朝六部的**宦官任命轨**，宦官有专属能力加成、给城市控制/阴谋，但被锁在外朝之外（内外朝对立）。→ §1 官场加一条宦官子轨。**移植性 Medium**（六部本身别照搬，取宦官平行轨 + 内外朝互斥）。

### 13.6 始祖传说逐城传播 ★

**OE 原型**：`legends` 系统——角色/王朝创造"传奇"（黄帝/夏禹等始祖神话），**逐省 province-by-province 传播**，三品质 famed/illustrious/mythical 传播上限 200/600/1000 省，完成后给对应级别的法理宣称 + 威望 + "加入往逝皇族"；有 owner/赞助者分成机制。

**AW3.0 设计**：**极契合 god-game 俯视扩散**。做"**始祖传说/开国神话**"：

- 天命国/大氏支可发起一个"始祖传说"（如"承黄帝之统"），从**起源城逐城扩散**（复用 AW3.0 文化/宗教已有的逐格转化传播机制，或天命地图层）。
- 覆盖率到阈值 → 给**称帝合法性 / 王朝威望 / 对覆盖区的宣称**。接 §3.2 礼制门控（传说覆盖率作称帝的一个软条件）+ `LineageService`（始祖挂到氏支谱系源头）。

移植性 **High**。挂接姓氏谱系 + 天命 + 文化传播层。低成本高叙事，且强化"天命 = 受命于天 + 神话正统"的主题。

## 14. 复国战争扩展：自主起兵复国 · 中兴之主 · 世祖

> 现状 C：AW3.0 复国系统（`RoyalClaimService` + `WarTerritoryService` 的 `GOAL_RESTORE_KINGDOM`）**只实装了一条路——"宗主扶持傀儡"**。本节补上缺失的另一条：**幸存宗室自己起兵、独立复国**，并规定**唯有自主复国者方为"中兴之主"**，接通 §2.2 那条长期悬空的世祖分支。史实锚点：**刘秀**（光武帝，庙号世祖）——新莽末群雄逐鹿，白手起兵，克复旧都、再受天命，非受人扶立。

### 14.0 现状三缺口（起手先读代码，勿重做）

落地前务必确认以下三点仍成立（现场代码为准）：

1. **复国 = 傀儡独一路**：`ChronicleEvents.OnKingdomDestroyed` → `RoyalClaimService.CreateClaimsFromFallenKingdom` 为幸存宗室（king/heir/宗族成员，男性、非 `madness`）建 `RoyalClaim`，宿主 = 该宗室现居国。**由宿主**（AI 或玩家，`WarTerritoryService.TryDeclareRestorationWar`）发起复国战争；胜后 `TryRestoreKingdomForClaim` 用旧国名 `makeOwnKingdom`，**但紧接着 `VassalService.SetVassal(restored, host, "restoration_war")`——复国即成宗主附庸**。宗室全程被动。
2. **义军/拥兵不"复"名号**：`MandateRebelService`（义军）、`GeneralRebellionService`（拥兵自重）能自募兵、自立国，但**建的是叛乱者自己名下的新国**，不复活某个具名的亡朝。
3. **世祖是死代码**：`MandateRulerTitleRules.SelectTempleName` 收 `refounder` 形参却**从不读取**；调用处 `refounder = context.OriginType == "restoration"`，而**全代码库没有任何地方把 `"restoration"` 写进 `MandatePeriod.ORIGIN_TYPE`**（实际只写 `native`/`rebel`/`pseudo_foreign`）。故 `refounder` 恒 `false`，"世祖"现被误发给"强势中段之君"（`reignIndex≥3 && reformScore≥90 && conquestScore≥30`）；无 `restored_pending`、无中兴标记。

> 结论：**"中兴之主"要落地，缺的不是庙号分支本身，而是一条能把 `ORIGIN_TYPE="restoration"` 真正写进去的"自主复国"路径**。本节即补此路径。

### 14.1 两条复国路线对照（本节核心）

| 维度 | 傀儡复国（现状，保留） | **自主复国（新增）** |
|---|---|---|
| 发起者 | **宿主国**（扶持者） | **幸存宗室本人** |
| 军队来源 | 宿主国军队 | **义军化自募**（复用 `MandateRebelService.MobilizeRebelForces` 动员人口成军） |
| 据点来源 | 宿主领土为后方 | 从宗室所居地/一座失序核心城 `makeOwnKingdom`，**立即打出旧国号** |
| 战后地位 | **宗主附庸**（`SetVassal`） | **独立**（不奉宗主，无 `SetVassal`） |
| 天命 | 不重受 | **重新受命**（前天命朝→`TryDeclareMandate`，`origin="self_restoration"`） |
| 庙号 | 普通 X宗（附庸、未受命，**永不得世祖**） | **世祖 / 中兴之主**（前天命朝）；普通亡朝→独立复国但普通谥 |
| 门控 | 有宿主 claim 即可发起 | **限乱世阶段**（§13.1）+ claim 资格 |
| 叙事 | "某国扶某公子复某国" | "**某公子白手起兵，克复旧都，再造某朝**"（§9 骈文高光） |

**一句话**：扶持复国换来附庸，自主复国换来世祖——**两条路，两种结局，玩家/AI 二选一**。

### 14.2 自主起兵复国状态机（义军化自立）

在 `RoyalClaim` 上加 `restore_mode`（0 傀儡 / 1 自主），自主分支走如下状态机（全程复用现有服务，**不新增深度夺舍**）：

```
资格（沿用现状 claim 资格 + 追加门控）：
  claim 存在且 claimant 有效（男性、非 madness、未死）
  且 世界处于「乱世（逐鹿）」阶段（§13.1 MandatePhase == 乱世）        【可调：亦可放宽到「衰世」末】
  且 claim 强度达阈（king=100 / heir=85 …；AI 仅高强度者自立）        【可调】

起兵（TryLaunchSelfRestoration，新方法，复用 MandateRebel 基建）：
  ① 取一座后方核心城（claimant 现居城 / 旧国失序核心城，按义军 PickCollapseCities 打分）
  ② city.makeOwnKingdom(claimant, pRebellion:true) → setName(claim.originalKingdomName)   ← 立即打旧国号（区别于普通义军的新国号）
  ③ MarkRestorationArmy：绑 claim_id + ORIGIN=self_restoration（区别于 MANDATE_ORIGIN_TYPE="rebel"）
  ④ MobilizeRebelForces（复用）：动员据点人口成军（复用义军 80% 动员 + 年度上限）

逐鹿（年度 tick，复用义军循环 + 通用攻城加速）：
  独立攻取旧都/旧天命核心城；CityOccupationAcceleration 照常生效（非义军专属加速）

胜利（控旧天命核心城 ≥ 65%，复用 RESTORE_CORE_THRESHOLD=0.65）：
  若原为天命朝 → MandateService.TryDeclareMandate(origin="self_restoration") 重新受命
  关键区别：绝不 SetVassal —— 独立复国
  置 kingdom.data: restored_pending 消耗 → 中兴标记；写复国史高光（§9.1）
```

> **复用清单**：动员 = `MandateRebelService.MobilizeRebelForces`；据点打分 = `PickCollapseCities`；建国 = `City.makeOwnKingdom`；旧国名 = `RoyalClaim.originalKingdomName`（已存）；受命 = `MandateService.TryDeclareMandate`；核心城阈值 = `RESTORE_CORE_THRESHOLD`（已存）。**新写的只有"绑 claim 的复国义军"这层皮 + 不 `SetVassal` 的独立收尾。**

### 14.3 中兴之主 → 世祖（接通死代码）

自主复国是**唯一**给 `ORIGIN_TYPE` 写 `"restoration"` 的入口——正是 §14.0 缺口 3 缺的那个写入端：

- **写入端**：`MandateService.TryDeclareMandate` 增参 `origin="self_restoration"`，落到新 `MandatePeriod.ORIGIN_TYPE`（新增合法值 `self_restoration`，与 `native/rebel/pseudo_foreign` 并列）。`OnMandateReignEnded` 组 context 时 `OriginType` 由此非空。
- **消费端**：`MandateRulerTitleRules.SelectTempleName` **真正读取 `refounder`**（现在是死参），置于 founder 判断之前：

```
if (founder && refounder)  return "世祖";     // ← 中兴之主：起兵复国、再受天命的开国之君
if (founder && lowOrigin)  return "高祖";
if (founder && conquestScore >= 70) return "太祖";
if (founder)               return "高祖";
... （其余不变）
```

- **中兴标记**：`kingdom.data` 置/清 `restored_pending`（§10 已列）+ `self_restored=true`；对齐 §2.2 世祖状态机的"消耗中兴标记"。

**傀儡复国永不得世祖**：附庸、未 `TryDeclareMandate`、`ORIGIN_TYPE` 非 `self_restoration` → `refounder` 恒 `false` → 只能拿普通 X宗。**"世祖"由此从数值失控风险变回稀缺荣誉**，且严格绑定"自己打下来的天下"。

### 14.4 世祖资格：仅限前天命朝【可调】

"中兴之主/世祖"是**天命朝的再造**，故资格分三档（默认取最史实的一档）：

| 亡国类型 | 自主复国成功后 | 庙号 |
|---|---|---|
| **前天命朝**（该亡国曾有 `MandatePeriod`） | 重新受命（`TryDeclareMandate`，继承旧核心城） | **世祖 / 中兴之主** |
| 普通亡朝（从未受命） | 独立复国，可后续另行称帝 | 普通谥/庙（除非日后自受天命）；叙事上仍是"复国之君"，但非世祖 |
| 傀儡复国（任意） | 成宗主附庸 | 普通 X宗，**永不得世祖** |

> 【可调】若想放宽：可允许"任意亡国自主复国者"都记一个较弱的"中兴之主"叙事标记（家族威望 + 复国史高光），但**世祖庙号仍只留给前天命朝**——避免遍地世祖。默认从严。

### 14.5 触发与 AI / 玩家入口

- **门控接 §13.1 治乱循环**：仅 `MandatePhase == 乱世（逐鹿）` 可自主起兵——**中兴必生于乱世**（新莽末群雄→光武）。治世/衰世前期，宗室只能走傀儡路或蛰伏。这让 §13.1 的阶段机**多一个下游后果**，二者互相强化。
- **AI**：乱世期，高强度 claim（king/heir）的幸存宗室 AI **优先尝试自立**（而非等宿主扶持）；低强度者仍走傀儡/蛰伏。逐鹿逻辑复用义军年度 tick。
- **玩家**：`WarDecisionTargetWindow`（现有"复国"选项来自 `report.can_restore`）**分裂为两个入口**——"扶持复国"（现状，产附庸）与"**自主起兵复国**"（新增，独立、乱世限定）。玩家操控该宗室或其义军直接逐鹿。

### 14.6 数据结构（最小增量）

| 载体 | 字段 | 用途 |
|---|---|---|
| `RoyalClaimTableItem`（扩） | `restore_mode`（0 傀儡/1 自主）、`self_faction_kingdom_id`（自立义军国 id） | 区分两路线、回指自立国 |
| `kingdom.data`（扩） | `restored_pending`（§10 已列）、`self_restored`、`restoration_origin_name`（复的哪个旧国） | 中兴标记 / 世祖判定 / 史料 |
| `MandatePeriod.ORIGIN_TYPE`（扩值） | 新增合法值 `self_restoration` | 喂 `refounder` → 世祖 |

**无新窗口、无新 SQLite 表**——纯扩字段 + 复用义军/复国/天命三套现成基建。

### 14.7 实现挂点

- `RoyalClaimService`：新增 `TryLaunchSelfRestoration(claim)`（§14.2 状态机）；`restore_mode` 分流；**自主分支收尾不调 `VassalService.SetVassal`**（与 `TryRestoreKingdomForClaim` 的傀儡收尾并列）。
- `MandateRebelService`：复用 `MobilizeRebelForces`/`PickCollapseCities`；加"复国义军"标记分支（绑 claim、打旧国号，区别于普通义军的新国号与 `MANDATE_ORIGIN_TYPE="rebel"`）。
- `MandateService.TryDeclareMandate`：增 `origin` 传参，写 `MandatePeriod.ORIGIN_TYPE="self_restoration"`；乱世门控查 `MandatePhase`（§13.1）。
- `MandateRulerTitleRules.SelectTempleName`：**真正消费 `refounder`** → 世祖分支（§14.3）。
- `WarDecisionTargetWindow` / `KingdomPolicyService`：玩家/AI"自主起兵复国"入口（与现有"扶持复国"并列，不产 `SetVassal`）。
- 史料：`HistoryWriter`/`ChronicleEvents` 出复国骈文高光（§9.1："某公子播越草莱，纠合义徒，克复旧京，再受天命，庙号世祖！"）。

### 14.8 移植性与边界

- **移植性 High（复用为主）**：三套基建（义军动员 / 复国 claim / 天命受命）全现成，新代码集中在"绑 claim 的复国义军皮"+"不 `SetVassal` 的独立收尾"+"接通 refounder"三处。
- **性能**：自主复国逐鹿复用义军**年度低频 tick**，无每帧/全国扫描（守 §12 红线）。
- **依赖 §13.1**：乱世门控依赖治乱循环阶段机；若 §13.1 未落地，可临时用"天命值触底/天命国已崩解"作等价门控（`MandateService.CrisisLevel <= collapse/lost`）。
- **不破坏现状**：傀儡复国路径原样保留，自主复国是**并列新增**，非替换。
