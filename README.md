# AncientWarfare 3.0 春秋

AncientWarfare 3.0 是基于新版 WorldBox 0.51.x、NeoModLoader、Harmony 和 .NET Framework 4.8 重写的 AncientWarfare 系列模组。当前主题是 Xia 文明、姓氏谱系、王国历史、国策科技、官场百家、奴隶制、多军队、附庸、宣战理由和天命王朝系统。

本 README 是当前 GitHub 首页说明和近期开发记录。更细的设计计划保留在 `docs/superpowers/plans/`。

## 最近更新：2026-07-09

本轮继续补齐国家层行为控制点和官场百家框架，并会推送到 `master`：

- 新增“玩家锁定国策节点”功能：玩家可以在国策窗口锁定任意科技、社会国策或常态决策节点，锁定后玩家和 AI 都不能选择该项。
- 锁定会同步清理当前研发、常态决策队列和独立核心制造槽；`aw_decision_fabricate_core` 被锁定时不会继续后台制造核心。
- 附庸战争支援补齐：宗主国进入战争后，直属和递归附庸会被维护逻辑拉入宗主同侧，避免附庸旁观宗主战争。
- 新增 `PolicyNodeLockRules` 和 `VassalWarSupportRules` 覆盖，继续把国家决策、附庸参战和核心制造等行为纳入规则测试。
- 新增低开销“官场与诸子百家”第一版：国家先使用原始朝会，研究官场制度后升级为百家官场，中央官、地方官署、军府和监察以缓存学派影响国家科技、国策、决策和战争倾向。
- 王国 UI 在四个国策按钮下方新增一条官场入口按钮；官场窗口复用原版滚动窗体，只读取低频缓存快照，不实时扫描全国 actor。

### 1. 天命、战争和地图模式

- 补强天命战争、夺取天命、义军天命战争、伪朝入夏等规则入口。
- 外族伪朝不再简单把 actor 种族强行改成 Xia，而是记录入夏状态、伪朝合法性、城市入夏进度、外族精英进度和民怨。
- 天命王朝地图和天命法理地图继续以王国层为主，减少 tile 级覆盖造成的卡顿。
- 天命法理、天命王朝、科技、发展度、核心、宣称等地图颜色规则继续统一到 AW3 mapmode 规则层。
- 宣战理由补齐核心、宣称、复国、夺取天命等入口，核心控制、战争目标和结算数据进一步统一。
- 外族自己建立的本族城市不再误记为“外族占领/同化进度”，只有占据 Xia 法理或 Xia 身份城市时才按伪朝/占领处理。
- 天命榜、天命历史和君主分段记录补强了事件归属，避免事件全部挂到一个皇帝底下。

### 2. 国策、科技、决策队列和 UI

- 新增独立的核心制造槽，不再占用普通国家决策槽。
- 新增国家决策队列编码和解码，后续国家层行为可以统一走常态决策。
- 制造核心拥有最高优先级，可用时会优先进入核心制造槽。
- 国策 UI 侧边栏加入核心队列入口和天朝决议窗口入口。
- 国策树节点右上角新增锁定按钮，玩家可以按国家禁用任意单个科技、社会国策或常态决策。
- 锁定节点会在 UI 中灰化并显示“玩家锁定” tooltip，AI 自动选择、玩家强制切换和队列启动都会被拦截。
- 天朝决议复用国家决议窗口逻辑，但使用独立内容，不再依赖战争目标按钮。
- 独立国家爵位升级按领地条件执行；附庸国爵位提升仍受宗主爵位上限约束。
- 科技/政策/常态决策相关本地化补齐一批中文键。

### 3. 谱系、继承、历史和 Xia 数据

- 增加旁系恢复宗统的追踪服务，避免把完全无关的同姓家族强行改氏并“夺舍”为王族。
- 继承逻辑继续优先直系儿子；找不到直系时再考虑合法旁支来源。
- 补充死亡亲属记录的规则，减少每死一人全世界扫描造成的性能压力。
- 家族树按钮布局规则加入测试，避免侧边按钮被挤到窗口边缘。
- 人物传记和历史记录继续补齐角色快照、年龄快照、谥号/庙号归属等元数据。
- Xia 城名词库新增中文地名来源，Xia 命名与原版 human 命名继续分离。
- 补充 Xia 物品效果规则，避免特殊物品效果直接散落在内容注册里。

### 4. 多军队、奴隶军、禁卫军和边军

- AW3 特殊军队现在分三类：
  - 禁卫军：仍然是 detached army，跟随 king，不绑定城市。
  - 奴隶军：保留真实城市 anchor，每个城市最多一支。
  - 边军：保留真实城市 anchor，每个天命国最多三支。
- 修复军队 UI 里 AW3 自定义军队城市显示为 `???` 的问题：奴隶军和边军运行时恢复 `Army._city`，但保存时不写原版 `id_city`，避免读档后抢走城市正规军。
- 修复“曾经的队长”重复堆同一个人的问题：特殊军队只有队长变化时才调用原版 `setCaptain()`，并清理连续重复的 past captains。
- 奴隶军规则：
  - 每个城市最多一支奴隶军。
  - 将领必须不是奴隶。
  - 非奴隶干部最多 5 人，包括将领。
  - 战争中奴隶军会优先作为前锋，向同岛最近敌军推进。
- 边军规则：
  - 每个天命国最多三支边军。
  - 边军绑定当前最重要的边境城市。
  - 边境变化后会迁驻新的边境城市，旧边军会清理或重锚。
  - 平时在边境驻防巡逻；有敌人靠近时出击，威胁消失后回到边境。
- 天命边防决议现在不仅修城墙，也会尝试建设 watch tower/箭塔。
- 边墙候选条件放宽，不再要求 tile 必须紧贴敌国城市，只要是城市边界并适合作为边防即可。
- 禁卫军候选、刷新、dismiss、巡逻和威胁扫描继续节流，减少 `guard_refresh`、`candidate scan` 和寻路开销。

## 当前系统状态

### Xia 文明

- Xia 种族、建筑、船、纹理、神力、语言、宗教、文化、亚种命名和中文命名已经接入。
- Xia 单位皮肤目录已经对齐原版 `male_*`、`female_*`、`warrior_*` 范式，避免 `Actor.calculateMainSprite()` 读取空贴图。
- Xia 城市名继续扩展中文地名词库。

### 姓氏谱系

- 已有姓、氏、分支、家族树、氏族大树、亡者画像重建、人物 tooltip、社会身份、父母兄弟姐妹关系和祖源分析。
- 支持氏族树侧边改氏，并同步族谱中能显示到的成员。
- 当前重点仍是性能：后期超大家族展开时要继续减少无关节点加载。

### 历史系统

- 王国史、城市史、人物传记、王朝统治期、君主在位期、谥号、战争记录和天命事件已经接入。
- 普通王国谥号和天命王朝专属庙号/双字谥号已经分层处理。
- 国家层历史只保留国家级事件；禁卫军、退伍、奴隶个人经历主要进入人物传记和城市史。

### 国策和科技

- 国家拥有政治点数、科技点数、科技树、社会国策树和常态决策。
- 新独立国家会继承地区或母国科技进度，避免白板国家。
- 城市科技传播已接入：国家完成科技后从首都向其他城市扩散，邻国也能受益。
- 核心制造已经独立出专门槽位。

### 官场与诸子百家

- 国家国策系统启用后会形成原始朝会；研究 `aw_tech_official_court` 后升级为百家官场。
- 官场任官、学派影响、官场效率和主流学派按低频缓存刷新，AI 选择科技、社会国策和常态决策时读取缓存加权。
- 中央官员任免写入 `CourtOfficer` 履历，地方官署按低频写入 `CityBureauState` 快照（官职槽位、主理学派、官署效率）。
- 王国 UI 官场入口位于四个国策按钮下方，窗口显示官场状态、主流学派、效率、学派构成、中央官员和地方官署，均来自低频缓存表。
- 普通官员任免不刷屏国家史；重要人物和贵族任官/罢免写入人物传记，官场建立、学派主导变化、官场变法强事件和地方官署改组写入国家史。

### 奴隶制

- 国家层奴隶制开关已经预留给未来废奴政策。
- 奴隶获取包括城破俘获、战斗俘获和奴隶军将领捕奴。
- 奴隶只能和奴隶通婚，奴隶子女继承奴隶身份。
- 奴隶军军功可以换取平民身份。
- 捕奴扫描被限制在战争中和敌方领土相关场景，避免和平期全图扫描。

### 禁卫军、奴隶军、边军

- 禁卫军是一国一支，保护 king，不作为普通进攻军。
- 奴隶军是城市级特殊军队，每城最多一支，作为战时前锋。
- 边军是天命体系特殊军队，每个天命国最多三支，驻扎边境并巡逻。
- 后续仍需游戏内实测：边军巡逻距离、箭塔实际建造位置、奴隶军冲锋节奏和军队列表 UI 展示。

### 附庸和战争

- 附庸关系、宗主、吞并、独立战争、附庸战争、战争联动和亡国收口已经接入。
- 附庸不能随意结盟，宣战权受到限制。
- 宗主国战争维护会把没有参战的附庸拉入宗主同侧；已在敌对侧的附庸不会被强制切换。
- 普通战争逐步收束到 AW3 宣战理由和国家决策系统。
- 核心、宣称、制造中项目、复国宣称和夺取天命都进入同一套战争目标框架。

### 天命王朝

- 天命值、法理核心、天命王朝、天命榜、天命战争、义军、伪朝入夏和地图模式已经接入。
- 历史人物可以无视爵位和礼制称帝要求，但不能无视国力领先要求。
- 天命国家如果不是最强国家，天命衰减更快。
- 天命法理会随天命国核心领土增加，并且旧王朝法理不会因为王朝灭亡而简单消失。

## 工程约定

- 以 AssetRipper 导出的新版 WorldBox 源码为 API 真相。
- 使用 Harmony 小范围 patch，尽量不完整接管原版方法。
- 新持久化数据优先通过 `[TableDef]` 表项接入 SQLite 自动建表/补列。
- UI 维持 WorldBox 原版风格：原版窗口、原版滚动结构、icon 按钮、tooltip。
- 性能问题优先加 benchmark 分量，再根据数据节流或改架构。
- 提交前至少运行规则测试和 `dotnet build AncientWarfare3.csproj`。
